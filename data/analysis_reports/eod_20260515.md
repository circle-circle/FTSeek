## 二、HKExitAggregator 双跑差异分析 ⚠️ P1发现

### 2.1 双跑状态: ❌ 未激活

**日志检查结果**:
```
grep 'HKAggregator·双跑|HKAggregator·差异' logs/ftseek.log → 0 results
grep 'HKAggregator' logs/ftseek.log → 0 results
grep 'get_hk_exit_aggregator' app/ --include="*.py" (排除定义) → 0 results
```

### 2.2 根因追溯

```
HKExitAggregator 类定义于: app/risk/hk_exit_aggregator.py:245
get_hk_exit_aggregator() 函数定义于: app/risk/hk_exit_aggregator.py:421

但调用链断裂:
  main.py → ExitRuleEngine 初始化 ✅ (日志确认 18 次)
  main.py → 从未调用 get_hk_exit_aggregator() ❌
  data_subscriber.py → 从未调用 get_hk_exit_aggregator() ❌
  任何文件 → 从未调用 HKExitAggregator.evaluate() ❌
```

**结论**: HKExitAggregator 双跑模式 **从未在运行时执行过一行评估代码**。ExitRuleEngine 的3个规则 (atr_hard_stop, structural_stop, trailing_stop) 已注册并启用，但 HKExitAggregator 的"新旧系统并行对比"功能完全未接入数据管线。

### 2.3 影响评估

- ExitRuleEngine 的 ATR/Structural/Trailing 规则通过 `_check_positions` 路径执行 (P1/P3 组合退出)
- HKExitAggregator 设计的"双跑对比"功能 (新旧系统差异记录、退出策略有效性统计) 从未产生数据
- **无法通过日志或数据验证新退出系统的有效性** — 没有对比基准

### 2.4 修复建议

在 `data_subscriber.py` 的 `_check_positions()` 或 `_process_tick()` 中接入 HKExitAggregator:
```python
# 在 _check_positions 中，exit rule evaluation 之后:
from app.risk.hk_exit_aggregator import get_hk_exit_aggregator
aggregator = get_hk_exit_aggregator()
aggregator.evaluate(positions, current_prices)  # 双跑对比
```

## 三、止损 Spam 循环问题 (今日重现)

### 3.1 事件时间线

```
13:13:50  HK.00700 日内止损触发 (P3, -2.0%) → 冷却拦截 (1.8s < 5s)
13:13:51  再次触发 → 冷却拦截 (2.4s < 5s)
13:13:52  再次触发 → 冷却拦截 (3.6s < 5s)
13:13:54  再次触发 → ✅ 冷却通过 (5.7s > 5s)，执行止损
13:13:55+ 冷却重置，继续拦截

13:50:00  HK.00700 ATR硬止损触发 (P1, -2.4%) → 开始 spam 循环
13:50:00  HK.01810 止损触发 → 冷却拦截
13:50:00-39  HK.00700 ATR硬止损触发 ≥14次，全部被冷却拦截
            每 0.2-1.2s 触发一次，全部 diff < 5s

13:51:10  ⚡ systemctl restart (服务重启)

13:53:04  重启后首次 scan: 冷却状态清零 (last_stop_time=0.000)
          → HK.00700 止损通过 → 平仓 (成交价 456.6)
          → HK.01810 止损通过 → 平仓 (成交价 30.54)
```

### 3.2 问题分析

**问题 A: 止损触发 Spam 循环**
- 每次 tick 都触发同一个退出规则，但被冷却拦截
- 每轮产生 5-6 条日志 (止损触发 → 入口 → 调试 → 冷却)，造成日志膨胀
- 05-15 13:50 时段: 40秒内 ≥14 次触发，≥70 条冗余日志
- **根因**: `_check_positions` 在每个 tick 循环中运行，退出条件持续满足但冷却阻止执行 → 无限重复检测

**问题 B: 止损执行依赖重启**
- HK.00700 在 13:13:54 首次通过冷却并执行止损，但 13:50 ATR 硬止损再次触发
- 说明 13:13 的止损执行 **并未真正关闭持仓** (或持仓被重建)
- 最终在 13:51 重启后，冷却清零，两个仓位才被真正关闭

**问题 C: exit_reason 标注错误**
- DB 中 exit_reason = `normal_close`，但实际触发路径是 ATR硬止损 (P1) + 日内止损 (P3)
- 日志明确显示 `[组合退出-P1] ATR硬止损(1.5x)` 和 `[组合退出-P3] 日内止损触发`
- 但写入 trade 表时 exit_reason 被覆盖为 `normal_close`

### 3.3 修复优先级

| 问题 | 严重度 | 修复建议 |
|------|--------|----------|
| 止损 Spam 循环 | P1 | 退出条件首次触发后，设置"已触发"标志，冷却期内不再重复检测 |
| exit_reason 标注错误 | P2 | 确保退出规则触发时的 reason 正确传递到 trade 写入路径 |
| 止损执行未生效 | P1 | 调查 13:13 止损执行后为何 13:50 仍触发 (持仓重建/未正确删除) |
