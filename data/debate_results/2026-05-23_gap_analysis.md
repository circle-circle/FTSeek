## Round 1: 独立分析

### 🔬 Agent A (数据科学家) — 模式与统计

#### 🔴 致命缺陷

1. **期权交易是最大出血点**: SHORT_PROXY_OPTION <5min 9笔, 0%胜率, -$23,635。占总亏损的41%。系统不应该交易期权。
2. **PRICE_FAIL 系列灾难**: 4笔 0%胜率 -$17,780。这是价格获取失败导致的错误平仓，不是真正的交易亏损——是系统bug。
3. **盈利极度集中**: ORCL一笔EXTERNAL_CLOSE +$17,883占总盈利44%。去掉这一笔,系统亏-$34,166。这不是策略能力,是运气。
4. **信号强度与盈利倒挂**: strength≥80的53笔亏-$247, strength 60-79的102笔赚+$3,221, strength<40的150笔巨亏-$18,797。高信号≠高收益,低信号=灾难。
5. **BREAKEVEN_STOP 反向巨亏**: 1笔 -$6,015。保本止损逻辑有严重bug,应该是微亏/微盈,不可能是-$6,015。

#### 🟡 结构性弱点

1. **market_regime 93% UNKNOWN**: 市场状态检测完全失效,所有交易在"未知"状态下进行。VIX过滤形同虚设。
2. **LONG 30m-2h 区间异常亏损**: 17笔仅17.6%WR,-$2,616。而同区间SHORT是+$17,761。LONG在中持仓区间完全失效。
3. **SHORT >8h 持仓**: 86笔(最多!)仅27.9%WR,-$6,041。系统让大量SHORT持仓过夜,变成慢性亏损。
4. **scalping vs main**: scalping 147笔18.4%WR仅亏-$1,638(每笔-$11)。main 162笔36.4%WR反而亏-$14,645(每笔-$90)。main策略的单笔亏损远大于scalping。
5. **QCOM/TME/NVDA 持续亏损**: QCOM 44笔22.7%WR -$3,768, TME 20笔0%WR -$913, NVDA 3笔0%WR -$2,905。这些股票应该进黑名单。

#### 🟢 被忽视的优势

1. **SHORT + TRAILING_STOP**: 22笔, 平均+$268, 平均持仓107min。这是系统唯一的"稳定盈利模式"。
2. **LONG + TRAILING_STOP**: 18笔, 平均+$348, 平均持仓214min。比SHORT更好,但交易数太少。
3. **PRE_CLOSE_EXIT**: 22笔, 27.3%WR, +$2,578。盘前退出策略有效,应该在更多场景使用。
4. **SHORT 5-30min**: 17笔, 41.2%WR, +$89。短持SHORT有微弱正期望。
5. **signal_strength 60-79区间**: 102笔, +$3,221。中等强度信号反而最赚钱,说明信号评分体系需要重新校准。

### 🏗️ Agent B (系统架构师) — 架构完备性

#### 🔴 架构致命缺口 (回测通过但实盘会失败)

1. **回测标的池vs实盘标的池完全不匹配**: 回测用9只(AAPL/MSFT/NVDA等),实盘交易了40+只股票(含期权)。GDIAN/MFFF因子只在大盘蓝筹上验证,在QCOM/TME/LCID等中小盘上可能完全失效。
2. **日线回测vs分钟级执行的时间框架鸿沟**: 回测用日线收盘信号,实盘每3-10分钟扫描一次。日线级别的GDIAN<5信号在盘中可能频繁翻转,导致过度交易。
3. **无滑点模型验证**: CostModel使用IBKR费率,但实际是Futu broker。Futu的佣金结构、滑点、最小手数限制与IBKR完全不同。回测中的成本假设可能过于乐观。
4. **因子计算依赖历史K线缓存,实盘需要实时数据**: validate_factors.py读取backtest_cache/*.csv,但ShadowBridge需要从Futu实时获取数据。数据格式/延迟/缺失值的处理逻辑未对接。
5. **期权交易无过滤**: 系统交易了大量期权(SHORT_PROXY_OPTION),新框架完全没有期权相关的因子或风控。回测中也排除了期权,但实盘仍在执行。

#### 🟡 风控盲区

1. **旧系统的Emergency Interceptor (闪崩检测)未接入新框架**: RiskGateway.check_exit中有闪崩逻辑,但只是简单的price_drop>3×ATR,缺少旧系统的LV3实时推送、连续下跌检测、放量暴跌检测。
2. **旧系统的Battle Plan快车道未整合**: 作战计划匹配的信号可以跳过投票直接执行,但新框架的因子评估没有与Battle Plan交互的接口。
3. **Capital Safety的5级水位未验证**: MarketContextProvider调用了CapitalSafetySystem,但这个系统从未在实盘中被测试过。peak_equity计算、回撤触发逻辑可能与实际净值数据不匹配。
4. **PDT Guard (Day Trade限制)不在新框架中**: 美股账户需要遵守Pattern Day Trader规则(5个交易日内不超过3次day trade)。新框架的DynamicRiskExit没有PDT检查。
5. **连续亏损23笔的根因未分析**: streak_distribution显示{23:1, 21:1, 15:1}。这不是随机分布,是系统性问题(可能是某段时间市场状态完全不适合当前策略)。

#### 🟡 数据质量风险

1. **93% UNKNOWN market_regime**: 说明market_state.py的VIX获取长期失败。如果MarketContext也依赖同一数据源,它也会返回UNKNOWN。
2. **holding_hours可能有NULL值**: DB中部分交易的holding_hours为NULL,回测脚本如果直接计算会导致错误。
3. **pnl_pct vs pnl计算不一致**: 部分交易的pnl_pct为NULL但realized_pnl有值(或反之)。

### 🛡️ Agent C (风控经理) — 资金管理

#### 🔴 破产风险

1. **PF=0.72意味着每赚$1就亏$1.39**: 系统处于持续失血状态,如果不干预,最终必然破产。
2. **最大连续亏损23笔**: 假设每笔风险2%,23连亏后账户回撤约37%。接近资本水位的CIRCUIT_BREAKER(-35%)。
3. **5/21单日亏$16,166**: 单日亏损可能超过账户净值的10%,触发所有风控红线——但系统仍在继续交易。
4. **ORCL依赖症**: 如果ORCL不再产生信号(或信号质量下降),系统月均亏损约-$3,000~-$5,000。

#### 🎯 最小可行修复路径

| 1 | 禁止期权交易 | 止血 ~$2,700/周 | 1天 |

## Round 3: 共识报告

### ✅ 全员一致同意 (无需进一步讨论)

1. **立即禁止期权交易** — 0%胜率,$23,635亏损,无争议
2. **修复PRICE_FAIL错误平仓** — 这是bug不是策略问题

5. **修复market_regime检测** — 93%UNKNOWN使所有风控失效
6. **TRAILING_STOP是唯一有效的退出方式** — 应作为默认退出策略
7. **新框架必须先shadow验证,不能直接替代旧链路**
