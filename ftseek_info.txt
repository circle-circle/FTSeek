Gemini的方案如下
这是一个专为 FTSeek 量化框架设计的**多模态场景识别器 (Market Regime Recognizer)** 设计方案。该方案旨在将“市场状态”从单一的技术指标提升为“具备上下文感知”的智能判别系统。

---

### 一、 架构设计：RegimeRecognizer v1.0

该模块位于 `app/data_subscriber.py` 与 `StrategyManager` 之间，负责为每一时刻的行情打上“场景标签”。

#### 1. 核心模块组成
*   **FeatureProvider**：特征采集器（负责计算 ATR, ADX, VMA, RSI 等原始指标）。
*   **StateEngine**：状态决策引擎（执行分类逻辑）。
*   **ConsistencyFilter**：一致性平滑器（使用窗口投票解决状态抖动）。
*   **RegimeLogger**：场景性能追踪器（记录不同场景下的策略表现）。

---

### 二、 场景识别逻辑设计

我们将市场态势定义为 7 种明确的“环境向量”，每种环境对应不同的策略集：

| ID | 场景类型 | 特征表现 (触发条件) | 建议策略组 |
| :--- | :--- | :--- | :--- |
| **0** | **强上涨趋势** | ADX > 25, 价格 > MA20, Volume 增加 | `supertrend`, `confluence_v2` |
| **1** | **强下跌趋势** | ADX > 25, 价格 < MA20, Volume 增加 | `supertrend`, `confluence_v2` |
| **2** | **箱体震荡** | ADX < 20, 布林带收窄, RSI 在 40-60 | `rsi`, `bollinger` |
| **3** | **高波动变盘** | ATR 突然飙升(> 2σ), 价格快速穿破布林带 | `event_driven`, `sentiment_ai` |
| **4** | **缩量盘整** | 成交量 < MA50, 无明显方向 | `open_close_effect` |
| **5** | **美港股联动** | 港股开盘与隔夜美股涨跌高度正相关 | `cross_market_arbitrage` |
| **6** | **异常突发** | 情绪因子(LLM)触发新闻警报 | `event_driven` |

---

### 三、 详细实现逻辑 (Python 伪代码)

```python
class MarketRegimeDetector:
    def __init__(self):
        self.window_size = 10  # 状态平滑窗口
        self.regime_history = []
        
    def get_market_state(self, kline_data, news_sentiment):
        # 1. 提取基础特征
        adx = calc_adx(kline_data)
        atr_ratio = calc_atr_volatility(kline_data)
        volume_trend = calc_volume_slope(kline_data)
        
        # 2. 逻辑决策树 (规则层)
        if news_sentiment['score'] > 0.8: return "ABNORMAL_EVENT"
        
        if adx > 25:
            return "BULL_TREND" if price_slope > 0 else "BEAR_TREND"
        
        if atr_ratio < 0.5:
            return "SIDEWAYS_LOW_VOL"
            
        return "UNKNOWN"

    def apply_smoothing(self, current_regime):
        # 解决状态抖动：只有连续 N 次判定为某状态才切换
        self.regime_history.append(current_regime)
        if len(self.regime_history) > self.window_size:
            self.regime_history.pop(0)
        
        # 返回出现频率最高的场景（众数）
        return max(set(self.regime_history), key=self.regime_history.count)
```

### 四、 关键增强：场景性能评价矩阵 (Regime-Performance Matrix)

为了让场景识别变得“智能”，必须引入**自我迭代机制**：

1.  **记录**：当 `TradeExecutor` 执行订单时，将当前的 `current_regime` 写入交易日志。
2.  **评价**：每周末运行 `eval_regime_performance.py`，计算：
    *   `Profit/Loss` per `Regime`。
    *   如果发现 `SIDEWAYS` 场景下亏损严重，自动在 `config.yaml` 中调低 `rsi` 策略在 `SIDEWAYS` 状态下的基准权重。
3.  **结果**：形成一个动态的**策略-场景映射表**，系统不再是“写死”的，而是“根据胜率自动微调的”。

---

### 五、 设计实施路径建议

1.  **第一步（定义阶段）**：在 `app/` 目录下创建 `regime_detector.py`，先实现上述 7 种场景的判定规则。
2.  **第二步（挂钩阶段）**：将该模块集成至 `StrategyManager` 的 `__init__` 中，作为 `get_active_strategies()` 的前置条件。
3.  **第三步（监控阶段）**：在 `FastAPI` 的 `/api/risk` 接口中，增加 `current_regime` 字段，方便你在钉钉/前端复盘时，实时看到系统判定当前处于什么环境。

# FTSeek 场景识别器设计方案

## 一、设计目标

FTSeek 场景识别器（Scenario Classifier）的目标，是将连续的市场行情、量能、波动率、结构和事件信息，转换为**可执行的离散市场场景标签**，为后续策略路由、仓位控制、信号过滤和风控决策提供依据。

其核心任务不是预测涨跌，而是判断：

> **当前市场最适合哪种交易行为，以及应该启用哪类策略。**

---

## 二、设计原则

### 1）场景优先于指标
指标只是特征，场景才是交易语义。  
例如 ADX 高不一定就是趋势，必须结合结构、量能和多周期确认。

### 2）规则优先于模型
第一版建议采用规则引擎 + 评分机制，保证：
- 可解释
- 易调试
- 易回测
- 易上线

### 3）多周期共振
短周期负责入场时机，中周期负责结构确认，长周期负责方向过滤。  
避免单周期噪音导致误判。

### 4）场景稳定性优先
场景不能频繁切换，必须有持续确认和冷却机制，防止“来回抖动”。

### 5）支持反馈学习
场景识别结果必须记录并回测，用真实绩效反哺识别权重。

---

## 三、总体架构

```text
行情数据 / 新闻数据 / 波动率数据 / 成交量数据
            ↓
      Feature Extractor
            ↓
       Rule Engine
            ↓
      Scenario Scorer
            ↓
      Scenario Arbiter
            ↓
      Scenario Memory
            ↓
   输出场景标签 + 置信度
```

---

## 四、模块说明

---

### 1. Feature Extractor（特征提取器）

职责：  
从行情和外部数据中提取用于场景识别的关键特征。

#### 输入数据
- K线数据：1M / 3M / 5M / 15M / 30M / 60M / Day
- Tick/Quote 数据
- 成交量数据
- 波动率数据
- 新闻/公告/事件数据

#### 输出特征类别

##### 1）趋势特征
- ADX
- 均线斜率
- 均线排列
- 高低点结构
- 价格偏离均值程度

##### 2）波动特征
- ATR
- 布林带宽度
- 实现波动率
- 波动变化率

##### 3）量能特征
- 当前成交量 / 均量比
- 放量突破识别
- 缩量整理识别

##### 4）结构特征
- HH/HL（更高高点/更高低点）
- LH/LL（更低高点/更低低点）
- 箱体边界
- 结构破坏

##### 5）事件特征
- 跳空比例
- 新闻情绪
- 财报/公告标签
- 突发新闻强度

##### 6）位置特征
- 价格相对 VWAP
- 价格相对均线
- 超买/超卖程度
- 区间位置百分比

---

### 2. Rule Engine（规则引擎）

职责：  
对明显场景做快速识别，作为场景判断的第一道门槛。

#### 推荐规则类型
- 跳空事件规则
- 强趋势规则
- 震荡区间规则
- 波动扩张规则
- 反转预备规则

#### 示例规则

##### GAP_EVENT
满足以下条件之一：
- 开盘跳空幅度 > 2%
- 且成交量放大 > 1.5 倍均量
- 且存在新闻/公告事件

##### TREND_STRONG
满足以下条件：
- ADX > 25
- 均线多头/空头排列
- HH/HL 或 LH/LL 结构成立
- 回撤较浅，延续性强

##### RANGE_BOUND
满足以下条件：
- ADX < 20
- 价格在区间中反复
- 布林带宽度较低
- 均线走平

##### VOL_EXPANSION
满足以下条件：
- ATR 明显上升
- 布林带开始扩张
- 成交量同步放大

##### REVERSAL_SETUP
满足以下条件：
- 长时间单边后动能衰减
- TD计数接近耗尽
- RSI 超买/超卖
- 结构破坏或失败突破迹象

---

### 3. Scenario Scorer（场景评分器）

职责：  
对多个候选场景进行打分，输出概率或置信度。

#### 场景评分思路
每个场景都由多个特征加权组成，例如：

```text
TREND_STRONG_SCORE =
  0.25 × ADX_score
+ 0.20 × MA_alignment_score
+ 0.20 × structure_score
+ 0.15 × volume_score
+ 0.20 × pullback_quality_score
```

#### 输出
- 每个场景一个 score
- 归一化后得到概率分布
- 选出 Top1 主场景 + Top2 辅场景

---

### 4. Scenario Arbiter（场景裁决器）

职责：  
在多个场景同时高分时，决定最终哪个场景生效。

#### 裁决原则
1. 事件类优先于技术类
2. 高波动优先于普通趋势
3. 趋势启动优先于震荡
4. 强场景优先于弱场景
5. 多周期共振优先于单周期信号

#### 示例
- `GAP_EVENT` 与 `TREND_STRONG` 同时成立时，优先 `GAP_EVENT`
- `RANGE_BOUND` 与 `TREND_START` 同时成立时，若突破未放量，则保留 `RANGE_BOUND`
- `REVERSAL_SETUP` 与 `TREND_STRONG` 冲突时，若长周期仍强，则反转信号降权

---

### 5. Scenario Memory（场景记忆器）

职责：  
防止场景频繁抖动，并记录当前场景持续状态。

#### 功能
- 场景持续计数
- 场景切换冷却
- 场景失效判定
- 最近场景历史缓存

#### 示例
- 一个场景必须连续满足 3 根 K 线才正式切换
- 切换后在冷却期内不允许立即回切
- 若当前场景失效，则优先触发新场景

## 七、与 FTSeek 现有模块的关系

### 1）与 MarketRegimeDetector 的关系
MarketRegimeDetector 负责宏观市场状态。  
Scenario Classifier 负责更细粒度的交易场景。

例如：
- MarketRegimeDetector：趋势市 / 震荡市 / 高波动市
- Scenario Classifier：TREND_START / GAP_EVENT / RANGE_BOUND

### 2）与 ConsensusEngine 的关系
场景识别结果决定哪些策略参与共识，以及各自权重。

### 3）与 RiskManager 的关系
不同场景对应不同止损止盈和仓位模板。

### 4）与 StrategyManager 的关系
场景标签是策略启停的入口。

## 八、策略路由接口建议

场景识别器输出后，建议直接交给路由器：

```python
route = ScenarioRouter.route(
    scenario=primary_scenario,
    confidence=primary_confidence,
    secondary=secondary_scenarios
)
```

路由结果包含：
- 启用策略列表
- 主策略
- 辅助策略
- 风控模板
- 自动/人工确认模式
- 持仓周期建议

## 九、准确率提升手段

### 1）多周期共振确认
至少结合短、中、长三个周期判断。

### 2）加入量能和波动过滤
避免只看价格造成误判。

### 3）加入事件信息
港股对新闻、公告、财报反应明显，必须纳入场景识别。

### 4）引入场景持续确认
场景切换必须连续满足条件，避免抖动。

### 5）结合历史绩效回调权重
如果某个场景下识别后交易表现差，降低相关规则权重。

## 十一、关键参数建议
