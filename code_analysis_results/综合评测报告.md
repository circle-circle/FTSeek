## 四、共同发现的高置信度问题

以下问题被 **≥2个模型** 同时识别，可信度高：

### 1. broker_adapter.py: get_positions 断连返回空列表
**发现者**: deepseek ✓, qwen ✓, GLM-FlashX ✓  
**严重性**: Critical/High  
**问题**: `get_positions()` 在 broker 断连时返回空列表而非抛出异常，导致下游误判为"无持仓"  
**影响**: 可能触发错误的平仓/开仓操作

### 2. capital_allocator.py: 单例初始化竞态条件
**发现者**: deepseek ✓, GLM-Flash ✓, GLM-FlashX ✓  
**严重性**: High/Medium  
**问题**: `get_capital_allocator()` 使用 check-then-act 模式创建单例，无线程同步  
**影响**: 多线程环境下可能创建多个实例，状态不一致

### 3. capital_allocator.py: 资金管控未接入订单路径
**发现者**: deepseek ✓, GLM-Flash ✓, GLM-FlashX ✓  
**严重性**: Critical  
**问题**: `try_reserve()` 文档明确说明 `_submit_order` 下单前尚未调用资金检查  
**影响**: 资金管控形同虚设，可能超额交易

### 4. position_sync.py: 外部平仓去重逻辑缺陷
**发现者**: deepseek ✓, GLM-FlashX ✓  
**严重性**: High  
**问题**: 去重条件仅匹配 `(symbol, direction, exit_price>0)`，忽略时间窗口  
**影响**: 可能遗漏或重复记录外部平仓事件

### 5. 多个风险门控 fail-open
**发现者**: deepseek ✓, qwen ✓, GLM-Flash ✓  
**严重性**: High  
**问题**: VWAP 偏差检查、execution_rules 等多处失败时返回"通过"  
**影响**: 异常情况下风控失效，可能执行高风险交易

## 五、各模型独特发现

### deepseek-v4.1-flash 独特发现
1. **PositionStore 键设计缺陷**: 仅用 symbol 作键，与 symbol_lock_manager、position_sync 的 (symbol, direction) 不一致
2. **scheduler_core.py 的 PositionStore 初始化**: 未考虑并发访问

### qwen3.8-flash 独特发现
1. **observe_only 模式的静默失败**: 被阻止的 reserve 返回 True 但不更新 allocation ledger
2. **force_set 的并发写入风险**: 多策略同时调用可能导致状态不一致

### ZHIPU/GLM-5.3-Flash 独特发现
1. **engine.py shutdown 竞态**: `enabled=False` 与 `pending_orders.clear()` 之间无同步
2. **Reservation 无 TTL**: 预留无过期机制，依赖手动释放

### ZHIPU/GLM-5.3-FlashX 独特发现
1. **God module 问题**: order_executor.py 5685 行，违反单一职责
2. **Scheduler god-object**: 作为参数传递到所有 pipeline 函数，耦合度过高

## 六、架构理解能力对比

### 共同识别的架构弱点
1. **双 SSOT 问题**: PositionStore 内存字典 vs broker 实际持仓，仅 30s 周期同步
2. **混合并发模型**: asyncio + threading + 同步 SQLite，隐藏并发边界
3. **服务定位器反模式**: 模块级单例绕过 DI 容器
4. **Fail-open 设计**: 多处异常时选择继续执行而非中断

### 各模型架构分析深度

| 模型 | 识别的架构弱点数 | 独特见解 |

| qwen | 8 | observe_only 模式的会计漏洞 |
| GLM-Flash | 9 | Reservation 生命周期管理缺失 |
| GLM-FlashX | 8 | God module、Scheduler god-object |
