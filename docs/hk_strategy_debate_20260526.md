# 港股策略因子 & 止损止盈逻辑深度辩论报告

**审计日期**: 2026-05-26  
**审计范围**: consensus_engine → dynamic_exit_manager → kline_exit_checker  
**数据来源**: 80 笔真实交易 (修正后)  
**目标**: 确保无冲突、逻辑清晰、合理、能达到高胜率和盈利目标

---

## 一、核心发现：R:R 严重倒挂

### 配置 vs 实际

| 指标 | 配置值 | 实际值 | 差距 |
|------|--------|--------|------|
| 平均盈利 % | +8% (固定止盈) | **+0.39%** | 🔴 20倍差距 |
| 平均亏损 % | -3.5% (结构止损) | **-1.11%** | 🟡 3倍差距 |
| R:R 比率 | ≥ 1.25:1 (min_rr) | **0.35:1** | 🔴 倒挂 |
| 分批止盈触发 | 3 层 (1.5%/3%/5%) | **0 笔** | 🔴 从未触发 |
| 固定止盈触发 | +8% | **0 笔** | 🔴 从未触发 |

**根因**: 信号质量不足以支撑止盈目标，价格在达到 +1.5% 第一目标前就已反转触发止损。

---

## 二、6 大逻辑冲突

### 冲突 1: 分批止盈过早 vs 止损过宽 (R:R 倒挂根因)

**配置**:
- 第一目标: +1.5% (平 40%)
- 第二目标: +3.0% (平 30%)
- 第三目标: +5.0% (平 30%)
- 结构止损: -3.5% (全平)

**问题**:
```
假设 100 笔交易，胜率 50%:
  50 笔盈利: 平均 +0.39% (远低于第一目标 1.5%)
  50 笔亏损: 平均 -1.11%

即使完美执行分批止盈:
  50 笔 × 40% 仓位 × +1.5% = +30%
  50 笔 × 60% 仓位 × 假设继续涨到 +3% = +90%
  总盈利 = +120%

  50 笔 × 100% 仓位 × -3.5% = -175%

净收益 = +120% - 175% = -55% ← 仍然亏损！
```

**辩论**:
- **PRO 当前设计**: 分批止盈锁定早期利润，防止回撤
- **ANTI 当前设计**: 第一目标 1.5% 太容易达到，但止损 -3.5% 太宽，导致盈亏比倒挂
- **SYNTHESIS**: 提高第一目标到 +2.5%，收紧止损到 -2.5%，使 R:R ≥ 1.0

---

### 冲突 2: 日内止损过紧 vs 信号质量差

**配置**:
- 日内止损: 1.5% (default) / 2% (TimeGate override)
- 结构止损: -3.5%
- T+0 当日使用日内止损，T+1 后跳到结构止损

**实际数据**:
- 29/79 交易 (37%) 在 <1h 内关闭
- 其中 4 笔真实亏损，全部是 HK.00981，亏损 -2.0% 到 -2.01%
- 这 4 笔恰好触发了日内止损 (2%)

**问题**:
```
信号生成 → 开仓 → 价格立即反向 2% → 日内止损触发
持仓时间: 40-55 分钟
亏损: -$775/笔 × 4 = -$3,100
```

**辩论**:
- **PRO 当前设计**: 日内止损保护 T+0 快速止损
- **ANTI 当前设计**: 信号质量太差，开仓后立即被止损，说明信号本身就是噪音
- **SYNTHESIS**: 
  1. 提高信号质量门槛 (min_confidence 0.45 → 0.60)
  2. 放宽日内止损到 2.5%，给信号更多时间验证
  3. 添加"信号验证期"：开仓后 30 分钟内不触发止损

---

### 冲突 3: confluence_v2 权重 2.0 vs 0% 胜率

**配置**:
```yaml
strategy_weights:
  confluence_v2: 2.0  # 最高权重
  event_driven: 1.2
  st_factor: 0.6
  bb_factor: 0.5
  rsi_factor: 0.5
  vol_factor: 0.3
```

**实际数据**:
- confluence_v2: 5 笔，0% 胜率，-$125
- bb_factor + rsi_factor 组合: 14 笔，7.1% 胜率，+$100

**问题**:
- confluence_v2 权重是 bb_factor 的 4 倍，但胜率为 0
- 高权重因子应该有更严格的历史表现要求

**辩论**:
- **PRO 当前设计**: confluence_v2 是多因子融合，理论上更稳健
- **ANTI 当前设计**: 历史数据证明 confluence_v2 完全失效，高权重放大了亏损
- **SYNTHESIS**: 
  1. 立即禁用 confluence_v2 (已在 ADR-042 建议)
  2. 引入"因子权重自适应"：根据滚动 30 天胜率动态调整权重
  3. 设置权重上限：任何因子权重不超过 1.5

### 冲突 4: 时间衰减止损与时间止损重叠

**配置**:
```python
# dynamic_exit_manager.py:559-576
if holding_hours > 72:  # >3天
    struct_stop = struct_stop * 0.30  # -3.5% → -1.05%
elif holding_hours > 48:  # >2天
    struct_stop = struct_stop * 0.50  # -3.5% → -1.75%

# time_stop: max_holding_hours = 48 (default)
```

**问题**:
```
持仓 48 小时:
  - 时间止损触发 (priority 4)
  - 结构止损收紧到 -1.75% (如果浮亏 >1.75% 也触发)
  - 两者同时触发，优先级冲突
```

**辩论**:
- **PRO 当前设计**: 双重保护，持仓越久止损越紧
- **ANTI 当前设计**: 48h 时间止损和 -1.75% 结构止损同时生效，逻辑冗余
- **SYNTHESIS**: 
  1. 时间止损仅在浮亏时触发 (已在代码中实现: `if pnl_pct > 0.005: skip`)
  2. 时间衰减止损改为线性：每 24h 收紧 20%，而非阶梯式

### 冲突 5: 盘末退出与移动止损竞争

**配置**:
```
Priority 4.5: 盘末退出 (15:45 前 15 分钟)
  - 亏损 → 全平
  - 微利 (0~0.5 ATR) → 减半
  - ≥0.5 ATR → 保留

Priority 7: 移动止损 (盈利 >2.5% 后回撤)
```

**场景**:
```
14:30 开仓，盈利 +3% (超过移动止损 trigger 2.5%)
15:50 盘末退出检查:
  - 盈利 +3% > 0.5 ATR (假设 ATR=2%)
  - 盘末退出: 保留过夜 ✓
16:00 收盘前价格回落到 +1%
  - 移动止损: 从峰值 +3% 回撤 2% → 触发！
  - 但已收盘，无法执行
```

**辩论**:
- **PRO 当前设计**: 盘末退出保护隔夜风险
- **ANTI 当前设计**: 盘末退出判断时点 (15:45) 和移动止损判断时点 (每分钟) 不同步
- **SYNTHESIS**: 
  1. 盘末退出后禁用移动止损 (已部分实现: 盘末退出后不再检查)
  2. 或者：盘末退出时如果盈利 >2.5%，直接执行移动止损而非保留

### 冲突 6: 分批止盈从未触发 (数据证明)

**实际数据**:
- 0 笔 partial TP 记录
- 0 笔达到 +5% 的交易
- 平均盈利仅 +0.39%

**根因**:
```
信号生成 → 开仓 → 价格在 +0.39% 附近震荡 → 触发止损或时间止损
从未达到 +1.5% 第一目标
```

**辩论**:
- **PRO 当前设计**: 分批止盈是理论上的最优策略
- **ANTI 当前设计**: 当前信号质量无法支撑分批止盈，配置是"空中楼阁"
- **SYNTHESIS**: 
  1. 短期：禁用分批止盈，改用固定止盈 +3% (更现实的目标)
  2. 长期：提高信号质量后再启用分批止盈
  3. 或者：将第一目标降低到 +0.8% (接近实际平均盈利)

## 三、策略因子权重辩论

### 当前权重 vs 历史表现

| 因子 | 权重 | 历史胜率 | 历史PnL | 建议权重 |
|------|------|----------|---------|----------|
| confluence_v2 | 2.0 | 0% (5笔) | -$125 | **0 (禁用)** |
| st_factor | 0.6 | 0% (10笔) | -$1,550 | **0 (禁用)** |
| vol_factor (末尾) | 0.3 | 0% (5笔) | -$2,260 | **0 (禁用组合)** |
| bb_factor + rsi_factor | 0.5+0.5 | 7.1% (14笔) | +$100 | 0.5+0.5 (保留) |
| 分批止盈 | - | 83.3% (6笔) | +$9,429 | **扩大使用** |

**辩论**:
- **PRO 当前权重**: 多因子分散风险
- **ANTI 当前权重**: 0% 胜率的因子仍有权重，污染信号
- **SYNTHESIS**: 
  1. 立即禁用 confluence_v2 / st_factor / vol_factor 组合
  2. 引入"因子权重 = f(滚动胜率, 滚动盈亏比)"
  3. 设置因子权重下限：胜率 <20% 自动降权到 0

## 四、止损止盈参数优化建议

### 当前 vs 建议

| 参数 | 当前值 | 建议值 | 理由 |
|------|--------|--------|------|
| **结构止损** | -3.5% | **-2.5%** | 实际平均亏损 -1.11%，-3.5% 太宽 |
| **日内止损** | 1.5-2% | **2.5%** | 4 笔 HK.00981 在 -2.0% 被止损，给信号更多时间 |
| **第一目标** | +1.5% | **+2.5%** | 实际平均盈利 +0.39%，1.5% 太近 |
| **第二目标** | +3.0% | **+5.0%** | 提高盈亏比 |
| **第三目标** | +5.0% | **+8.0%** | 保留趋势利润 |
| **移动止损 trigger** | +2.5% | **+3.5%** | 与新第一目标对齐 |
| **时间止损** | 48h | **24h** | 实际 >12h 持仓胜率 47.6%，>48h 仅 20% |
| **min_confidence** | 0.45 | **0.60** | 提高信号质量门槛 |
| **min_rr** | 1.25 | **1.5** | 强制更高的盈亏比 |

### 预期效果

```
当前:
  80 笔，21.3% WR，+3,850 HKD，R:R 0.35:1

优化后 (假设):
  信号数量减少 40% (min_confidence 0.45→0.60)
  胜率提升到 35% (更高质量信号)
  R:R 提升到 1.2:1 (止损收紧 + 止盈放宽)
  
  48 笔 × 35% = 17 笔盈利
  48 笔 × 65% = 31 笔亏损
  
  17 × +2.5% × 20,000 HKD = +8,500 HKD
  31 × -2.5% × 20,000 HKD = -15,500 HKD
  
  净收益 = -7,000 HKD ← 仍然亏损！

结论: 仅调整参数不够，必须同时提高信号质量
```

## 五、根本问题：信号质量不足

### 数据证据

1. **29/79 交易 (37%) 在 <1h 内关闭** → 信号生成后立即反转
2. **平均盈利仅 +0.39%** → 价格从未达到 +1.5% 第一目标
3. **0 笔触发分批止盈** → 配置是"空中楼阁"
4. **24/29 <1h 交易是 position_sync 伪交易** → 数据质量问题

### 根因分析

```
信号生成链:
  consensus_engine._evaluate()
    → 加权评分 (score)
    → 与阈值比较 (adaptive_threshold: 0.8~2.5)
    → score >= threshold → 推送信号

问题:
  - threshold 自适应窗口 200 笔，太慢
  - min_confidence 0.45 太低，弱信号也能通过
  - 因子权重静态，0% 胜率的因子仍有权重
  - 没有"信号验证期"：开仓后立即被止损
```

### 建议修复 (按优先级)

**P0: 立即执行 (🟢级)**
1. 禁用 confluence_v2 / st_factor / vol_factor 组合
2. 提高 min_confidence 到 0.60
3. 收紧结构止损到 -2.5%

**P1: 短期优化 (🟡级)**
4. 引入"信号验证期"：开仓后 30 分钟内不触发日内止损
5. 放宽日内止损到 2.5%
6. 提高第一目标到 +2.5%

**P2: 长期优化 (🔴级)**
7. 引入"因子权重自适应"：根据滚动 30 天胜率动态调整
8. 引入"信号质量评分"：结合 ADX、成交量、市场regime
9. 引入"影子测试"：新因子先在影子盘验证 30 天再启用

## 六、结论

### 当前系统设计评分

| 维度 | 评分 | 说明 |
|------|------|------|
| **逻辑清晰性** | 7/10 | 10 级优先级清晰，但有 6 处冲突 |
| **合理性** | 4/10 | R:R 倒挂 0.35:1，分批止盈从未触发 |
| **可达标性** | 3/10 | 信号质量不足，无法支撑止盈目标 |
| **无冲突性** | 5/10 | 6 处逻辑冲突，需修复 |

### 核心问题

**不是止损止盈逻辑的问题，而是信号质量的问题。**

当前止损止盈逻辑在理论上是合理的 (10 级优先级、 regime-aware、time-decay)，但信号质量太差，导致：
- 价格在达到 +1.5% 第一目标前就已反转
- 37% 的交易在 <1h 内关闭
- R:R 实际 0.35:1 (配置要求 ≥1.25:1)

### 建议行动

1. **立即**: 禁用 0% 胜率因子 (ADR-042 已建议)
2. **短期**: 提高 min_confidence 到 0.60，收紧止损到 -2.5%
3. **中期**: 引入因子权重自适应 + 信号验证期
4. **长期**: 引入影子测试，新因子先验证再启用
