### E2. 因子 IC 语义反转 — 生产打分把"校准度"当"因子 alpha"用, 74% 推错方向

**代码路径 (在产, 无 FeatureFlag)**:
`app/playbook/screener.py:189-232` `_load_factor_ic_adjustments()` 读 `data/factor_ic_latest.json`:
```python
if n < 30: continue
if ic > 0.05:    adjustments[factor] = 1    # 判为正 alpha → 加分
elif ic < -0.05: adjustments[factor] = -1   # 判为负 alpha → 扣分
```
消费点 `screener.py:254` (`_calculate_score` 内), 入口 `screener.py:128`。
**在产链**: `pipeline.py:2072` `screener = PlaybookScreener(collector)` → `:2074-2078` `screener.screen(...)` ← `:1962 run_playbook_generate` ← `app/core/scheduler_core.py:2055 / :2186` (实盘调度器)。**无开关可关。**

> **⚠️ 第 3 轮病灶位置更正 (本条原始定位错误, 结论需改挂)**:
> 上述 screener 路径经实证**几乎无行为效力**, 不构成"当期在亏钱"的通道 —
> ① `screener.py:63` 职责自述 = 质量门槛(流动性/财报/新鲜度) + 因子打分**标注**; `:74` 返回"全部通过质量门槛"者按分降序 → 因子分**不参与 pass/fail**;
> ② `pipeline.py:2079` 日志明写"筛选出 N 只候选 (**无截断**)";
> ③ 指令生成循环 `pipeline.py:1237-1440` 内**零处读取 `sr.score`** (全文件无 `sr.score`/`result.score` 引用, 仅取 `sr.symbol`/`sr.data`/`sr.factors`)。
> ⇒ 因子分只影响排序; 无截断 + bridge 决定成员资格 (E3) ⇒ 该路径的错误**被罩住不兑现**。第 2 轮"打分错误大部分被罩住"成立, 第 1 轮"A 级当期在亏钱"**不成立**。
>
> **真正的行为消费点 (第 1、2 轮均漏)**: 同一文件的**第二次独立读取** —
> `pipeline.py:1188-1199` 循环外再读 `factor_ic_latest.json` → `:1456-1463 _direction_conditioned_ic_net(direction, _bearish_hits, _bullish_hits, _factor_ic)` → `:1466 if _net_score < -0.05` → **直接 `Instruction(direction="SKIP", skip_reason="IC方向冲突...")` 硬杀指令**。这是真正改变产出的闸, 不经 screener。
> **但实测该闸近乎休眠**: `playbook_instructions` 中 `skip_reason LIKE '%IC方向冲突%'` **累计仅 15 条**, 全部落在 **8/17-8/20**, **近 10 日归零**。⇒ E2 紧迫度应**双方共同下调**, 而非重新辩论。
>
> **E2 残留的最锋利版本是设计问题, 不是数字**: `pipeline.py:1442-1443` 注释自承 "BEARISH/BULLISH 列表方向和真实 IC 相反 (`above_ma20` 被当 bullish 但 IC=−0.553)", 其解法是**选择信 IC 而不信分类表**。若 `ic` 确系校准度而非方向 alpha (语义已第 1、2 轮双方实锤), 则这个抉择建立在错的量上 —— 该辩论的对象应是"信 IC 还是信分类表", 而非"改 screener 读哪个字段"。
>
> **排除一项疑似**: `factor_ic_latest.json` **未僵死** — crontab `40 5 * * 2-6 factor_ic_backfill.py` 在跑, `_meta.generated_at = 2026-08-28T21:40:13Z` (末个交易日), mtime 8/29 05:40。

**语义错配**: `scripts/factor_ic_backfill.py` `calc_ic` (~:148) 的 `ic` = **Spearman(signal_strength, fwd_ret_t1)** — 这是**信号强度的校准度** (强信号是否真更强), **不是因子的方向性 alpha**。把校准度当 alpha 加减分, 是量纲之外的语义错用。

**复算证据**:
- 31 条实际生效的调整中 **23 条 (74%)** 与该因子的实测 `avg_ret` 符号冲突。
- pearson(`ic`, `avg_ret`) = **−0.361** → 该字段与真实收益**负相关**, 越信越反。
- 最典型: `insider_net_sell` wr **0.685** / `avg_ret` **+1.065%** (全表最优之一) 被 **扣 −1 分**。
- 输入卫生: `factor_ic_latest.json` 124 个键中 **91 个是解析垃圾**, 非因子 (`strategy_type:`、`signal_scores:{}`、`gate_decision:BLOCK`、`theme_wind:+0.40`), 但只要 `n≥30` 且 `|ic|>0.05` 就照样进权重。
- 该文件 entry 结构为 `{ic, n, wr, avg_ret, avg_alpha, ic_long, n_long, ic_short, n_short, ic_intraday_entry, ...}` — **无 `avg_pnl_pct` 字段** (审计中曾误查该字段得 0/0, 已校正)。

**同族先例**: 属"字段存在≠字段有效"+"扣分存在≠扣分有效"病灶族。修复成本极低 (改读 `avg_ret`/`wr` + 非因子键白名单), 但**方向性影响全部指令打分**。
