## 四、关键分歧 (待用户/B 裁决)

1. **"不要被人为限制"的边界原则**: 哪些门属"安全兜底"不可下放 (资金/仓位/合规/账户状态 — 模型不可能知道), 哪些属"判断替代"可由数据裁决去留 (confidence 门/方向冲突门/supply 门)。需要一条明文原则, 否则每个门都要单独重辩。

`_compute_confidence` 的 docstring 把设计意图写得毫无歧义 (adapter.py:191-205 原文): 「第一性原理: confidence = P(trade profitable | signal)」/「数据验证: LLM自评confidence无预测力(r=-0.211), 数据质量分无预测力(r=-0.073)」/「唯一弱正相关信号: 模型一致度(r=+0.102)」, 映射表 = **基准 0.50 (无辩论数据) / 2 模型一致+AGREE +0.20 → 0.70 / 2 模型方向分歧 −0.15 → 0.35 (注释自称"不通过 gate, 正确行为")**。三档点质量与我实测的 0.5 (n=146) / 0.7 (n=139) / 0.35 完全对应。据此:
1. **门的语义更正**: conf≥55 门既不是"置信度门"也不是我先前写的"日期开关", 而是 **challenger 一致性门** — 只有挑战者同向且 AGREE 的信号过门, 方向分歧的被拦。我先前观察到的"35 时代 5% 过门 / 70 时代 100% 过门"是**辩论结果分布随时代迁移**的表现 (7/20-8/13 近乎全分歧 → 8/14 起近乎全一致), 其成因应追 challenger 侧改动而非 prompt 版本。此为**新的待查项**, 不在本轮结论内。
2. **第 3 轮 P3② 已被实现**: "双模型分歧度是天然的行为置信度"不是新提案 — 生产链**已经**在用它, 且它是 adapter 自称唯一有预测力的信号。所以 D-4 项的正确表述不是"新建行为置信度测量", 而是"**重测 adapter 赖以立门的 r=+0.102**"。
3. **我上一条推断的自我更正 + 实测分组表**: 我先前把 0.50 读作"无辩论数据", **实测是错的** — 0.50 的绝大多数是「➖ 一方弃权 (BUY vs SKIP), 保持有观点方向, confidence 不罚」(n=128), 即**挑战者主张 SKIP 而分析师坚持 BUY**; 另有 17 行是「⚠️ 方向一致但挑战者有质疑」。按 `debate_outcome` 实测重分组 (全 DA 史, 剔 reentry):

   | 辩论结果 | n | BUY 的 T+1 方向性 | 触发率 | 执行子集 meanPnl | 执行胜率 |
   |---|---|---|---|---|---|
   | ✅ 2 模型一致 (conf→0.70) | 156 | **−0.794%** (n=130) | **77%** | **−$2.0** (n=113) | **61.1%** |
   | ➖ 一方弃权 (conf→0.50) | 198 | **+0.008%** (n=197) | 52% | **−$7.5** (n=103) | 38.8% |
   | ⚠️ 有质疑 (conf→0.50) | 25 | +0.214% (n=23) | 56% | −$2.1 (n=14) | 21.4% |

4. **结论: 门的符号"未定"而非"装反" (下调我先前的主张)** — 两把仪器给出**相反**的排序: 方向性口径 (fwd_return_t1_open) 说"挑战者同意的更差", 执行口径 (realized P&L / 胜率) 说"挑战者同意的更好" (−$2.0/61.1% vs −$7.5/38.8%)。故**不能**据此主张 55 门方向装反 — 我先前那句是过度主张, 已收回。可以确立的是三点: ①adapter 立门依据 `模型一致度 r=+0.102` 在两把仪器上**都未被本窗口复现为稳定正号**; ②两仪器的分歧被**触发率差异 (77% vs 52%)** 精确定位在执行层 — 与第 2 轮副产"方向对与赚钱被触发/未触发解耦"同源, 说明"一致"组更容易触发 (可能因其入场设定更靠近现价/更保守), 赚钱差异部分来自触发选择而非判断质量; ③因此**该门的存废必须先解决"用哪把尺"这个前置问题** — 这是比"门放在 55 还是 40"更上游、且尚未被本档任何一轮处理过的问题。
5. **第一原则读数 (为什么"一致"反而方向性更差)**: 两个模型吃**同一份材料**时, 一致不是独立确认, 而是**共享先验的确认**; 它系统性地选出最"共识/显然"的交易, 而共识交易的 edge 通常已被定价。弃权组恰是分析师持有**差异化观点**的样本。若 ①②在样本外稳住, 则真正该被奖励的是**差异化**而非一致 — 这与"挑战者应当是证伪官"的 r14 设计意图 (4117899) 方向一致, 但与"一致→加分"的 adapter 映射相反。**这是全档目前最值得跑的单条只读测量**, 且不需要任何新基建。
6. **连带**: L2 的最终表述应为 —「门在过滤**模型间一致性**, 而该一致性的预测力在两把仪器上排序相反、未获稳定支持」。比"过滤 adapter 派生量"更具体, 也比我先前写的"实测为负"更诚实。

**C. 第一原则增补 (P7-P10)**

**P7 变量溯源原则 (本轮最重要的新增)**: **给任何变量装门、或以它为主语下结论之前, 先追它的写入算子。** 本档三轮里出现了同一类错误三次, 每次都把**基建缺陷读成了模型行为**: ①"模型的置信度是常量" → 实为 adapter.py:207 的算术; ②"最低信心桶最赚钱" → 实为**缺失哨兵装桶** (写入端 `order_executor.py:1029` 的 `or 0.0` 把缺失折叠成 0.0, 读取端再装进最低桶; 我第一次只追到读取端 `_safe_float(None)→0.0`, 实测 NULL 仅 2 行而显式 0.0 有 23 行 — **P7 自身也被我执行得不彻底, 追写入算子要追到最上游那个赋值**); ③"模型不填 triggers" → 实为落库未接线。可操作纪律: **任何以"模型如何如何"为主语的结论, 必须附该变量的写入点证据 (文件:行号), 否则不得进入"不复议的事实"**。这一条能预防本轮发现的 3/5 处归因错误, 成本是每条结论多一次 grep。

**P8 契约优先于选型**: 本系统内"模型能力差异"已三次被证明是引出契约差异 (score 自由数值 67% 塌到 7.0 → score_band 锚定后恢复; DA triggers 0→100% 靠接线+白名单; UE 0% 未做对照)。推论: **模型选型实验必须先把契约固定为已知最强版本, 再比模型** — 否则测的是 prompt 不是模型, 且会把可用一次 prompt 改动解决的问题误判为需要换模型/加成本。这直接改写 L4 与方案 D 的设计顺序 (E3 先于 D)。附注: 第 3 轮 P3 建议"改引出结构 (强制分布/成对排序)"方向正确, 但应引用系统内**已验证的先例** (score→score_band, r14/4117899) 而非当作新提议; 真正的增量是**横截面配额** — 全仓 grep "只能有N个/最多/至多/相对排序/横向比较" 零命中, 每只股票仍是孤立打分, 无跨候选区分压力。

**P9 反馈的符号必须先被检验**: 喂给模型的历史, 必须先证明其符号 (正/负) 与未来结果**同号**, 再决定措辞。本系统两侧独立实测均为**反持续** (skill 侧 pearson=−0.40; 本轮同标的配对 6/6 逆向)。因此 A2/A3 的喂料**不能采用"本股历史亏损→应更谨慎"这类隐含正持续性的框架**, 否则是在教模型学一个反向规律 — 这比不喂更坏。正确形态 = 喂**可检验的失败模式分类** (第 3 轮 P4 的 MFE 三分类方向正确: 论点错/入场晚/失效未触发) 且显式标注"非方向先验" (生产 prompt 已如此措辞: L1319「近期交易经验（背景事实, 非方向先验）」)。**推论**: L3 "喂料不全"仍然成立且值得做, 但它的价值命题要从"让模型知道自己亏过"改为"让模型能区分**为什么**亏"。

**P10 修仪器 ≠ 修读数 (8/31 实施日新增, P7 的运维侧同构)**: 观测代码的缺陷一旦落盘, 就成了**独立于代码存在的坏事实**; 改完代码不重算产物, 被污染的读数会继续被下游消费, 修复在账面上"已落地"而在链路上未生效。本轮实证: 一.3 装桶修正当日完成, 但 `latest.json` 停在 8/29 04:51 (周末 phase 休眠), 若不手动重算, 9/1 盘前 DA 仍会拿到「最低桶期望+0.83%」这条假事实, 只有 9/2 起才干净 — 修复与生效之间有一整个交易日的缺口。可操作纪律: **修改任何生成缓存/报告/快照的代码, 提交时必须同时回答"已落盘的旧产物何时被覆盖"**, 三个合法答案 = 立即幂等重算 (需先备份) / 明确写出自然重算时点并接受缺口 / 证明产物无下游消费者; 不回答不算修完。验证也要落在**消费端表面** (本轮: 不传路径调 `_build_signal_quality_context()` 读生产文件), 而非只看函数返回值。
