### 勘误 1：「做大股数（不是大金额）」是错的，方向相反

用真实费用公式（`app/execution/fee_model.py`）复核：

```
commission = max( min($0.01×qty, 0.3%×amt), $1.99 )   每腿
settlement = $0.003/股
```

固定 $3,400 名义额下实测：

| 股数 | 股价 | 往返费用 | fee_bps |
|---|---|---|---|
| 10 | $340 | $4.12 | 12.1 |
| 100 | $34 | $4.67 | 13.7 |
| 400 | $8.5 | $10.55 | **31.0** |
| 1000 | $3.4 | $26.27 | **77.3** |

**股数越多越贵**（$0.01/股越过 $1.99 地板后线性加价；低价股还会撞 0.3%×amt 上限=单腿30bps）。
真正决定 fee_bps 的是**名义额**：qty≤199 时 `fee_bps ≈ 2×1.99/notional`（$3.4k→12bps，$9k→5bps，$18k→2.8bps）。

60 日数据印证：股数≥200 桶净额 **−$1,223**（最差）；fee_bps<5 桶（即最大仓位）净额 **−$2,648**（全场最差）。

→ 正确表述：**股数≤199 前提下抬高名义额，回避 <$30 低价股**。
→ 但**仍不产生利润**：毛边际≈0 时抬名义额是等比放大亏损。已记入项目经验库（`decdd0aa`）。

## 一、核心事实（代码锚点，不依赖统计）

### 1.1 confidence 的两个来源都不是"确信度"

| 路径 | 来源 | 实质 |
|---|---|---|
| 非 bridge | `instruction_generator.compute_confidence()` (L506-538) | **数据可用性分**：6 个数据源 ok 数×12 + 条件命中×28，封顶 90 |
| DA bridge | `vote_result.final_confidence` | **LLM 辩论票数**：0.50 基准，同意 +0.20 / 异议 −0.15，clamp[0.10,0.95] → 只有 {25,35,50,70,72,...} 几个离散值 |

`pipeline.py:1191-1193` 源码注释自述：
> "compute_confidence() 是纯数据质量分…数据完整时永远=90，与分析确信度无关 → confidence=90 但胜率31%"

### 1.2 confidence 门只作用于一条路径，84% 流量无门

- 门位置：`pipeline.py:1264`（BUY 70 / SHORT 65，默认值来自 `strategy_registry._DEFAULTS`；
  注册表中**无** `deep_analysis` / `universe_expansion` / `technical_fallback` 条目）
- 门仅存在于 `_build_instructions_from_votes`
- `pipeline.py:1523-1532` 明确记载：**"bridge候选已由 deep_analysis skill 直写DB，不需要 VotingCoordinator"**

## 二、改动 1（已落地｜白名单"修尺子"）：VWAP 门评估器修复

**文件**：`scripts/eval_vwap_gate.py`（只读脚本，零交易逻辑）

### 2.1 原实现的三个度量缺陷

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | **不可测量样本被静默计为 +0.00% 并算进均值** | `aligned` 组 144/144 事件 forward 轨迹长度=1（门放行后标的转持仓，entry 影子停止轮询 → 事件永远是当日最后采样点）→ pnl 恒为 0。输出"正0/负144 均值+0.00%"，被误读为"放行组零边际"（作者本人即误读为"评估器全坏"） |
| 2 | **出场标签 `CLOSE` 名不副实** | 轨迹终点是"最后一次轮询"（中位仅 6 个采样点、跨度中位 **26.1 分钟**），不是当日收盘 |
| 3 | **对照组取错数据源** | 放行组真实结果在 `trade_records`（它们真成交了），不该从影子轨迹找 |

### 2.2 修法

1. forward 采样点 `< min_forward`（默认 2）→ 标 `UNMEASURABLE` 并**排除出统计**，单独报数
2. 标签改 `LAST_POLL`，并输出实际测量跨度（分钟）
3. 对照组改从 `trade_records` 取**已实现 pnl**（`pnl_pct` 实测为小数，已 ×100 对齐百分数口径）
4. 强制输出 BUY/SHORT 分列 + beta 混淆自动告警

### 2.3 修复后结论（16 日，2026-07-15..08-05）

```
[处理组] 被VWAP门拦掉 (wrong_side): 56 事件, 排除不可测量 1
  测量跨度中位 26.1 分钟
  放行假想盈亏: n=55 正35/负20 均值 +0.254% 中位 +0.173%
    ├─ BUY  : n=46 均值 +0.176%
    └─ SHORT: n=9  均值 +0.649%
[对照组] VWAP门放行 (aligned): 144 事件 → join 真实成交 141
  已实现盈亏: n=141 正80/负61 均值 −0.166% 中位 +0.091%
```

**VWAP 方向一致性硬门当前实盘拦掉 45.2% 的入场尝试**
（`entry_timing_shadow` 3103 样本：wrong_side 1402 / aligned 1644 / vwap_missing 57，vwap 填充率 98.2%）。

**方向性读数**：在本 16 天样本里，wrong_side 事件在约 26 分钟窗口内的短期漂移均值为 **+0.25%**，
而 aligned 真实成交均值为 **−0.17%**。

> ⚠️ **措辞收窄（复核方攻击点 1，作者采纳）**：初稿写作「门倾向扼杀而非救命」——
> 在两组测量基不同 + beta 混淆 + 55 笔全为 `LAST_POLL`（无一触 SL/TP，说明采样过稀）的限制下，
> 这只是一个**倾向性证据**，**不足以证明 VWAP 门在整体上「扼杀」或「救命」**。
> 尺子修好了（从「全 0 不可用」到「能给出方向读数」），但**尺子不等于结论**。

**beta 混淆检验通过**：若为大盘上行漂移，SHORT 应为负；实测 SHORT **+0.649%**（比 BUY 更正）→ 无法用市场漂移解释。
（但 SHORT n=9 < 30，按宪章口径七律第 5 条不得下结论。）

### 2.4 口径警示（写入脚本输出，不可省略）

1. 两组**测量基不同**（26 分钟反事实 vs 全持仓期已实现）→ **不可直接相减**做因果推断
2. 离散采样非连续行情 → 日内极值低估、SL/TP 触发滞后（55 笔全部 `LAST_POLL`，无一触 SL/TP，说明采样过稀）
3. SHORT 切片 n=9 < 30 → 按宪章口径七律第 5 条不下结论
4. 处理组 26 分钟窗口衡量的是**短期漂移**，不等于交易结果

## 四、准入门定档回放：**没有一档在双窗口站得住**（重要负面结论）

`scripts/admission_replay.py`，双窗口强制对照。
关键指标是**留存/笔**（存活交易的单位经济），而非「Δ vs base」—— 从亏损账本删交易，总额必然"改善"，那是算术假象。

| 门 | Δ 35d | Δ 60d | 留存/笔 35d | 留存/笔 60d | 判定 |
|---|---|---|---|---|---|
| *基线* | — | — | *−5.21* | *−12.29* | |
| notional≥3000 | +588 | +610 | −3.93 | **−14.63** | 不一致 |
| notional≥5000 | +928 | +1114 | **−6.38** | **−29.79** | 更差 |
| price≥30 | +49 | +74 | −5.33 | −12.74 | ≈无效 |
| shares≤199 | −1 | +1223 | −5.29 | −7.82 | 35d 无效 |
| pf_ratio≥10 | +10 | +10 | −5.23 | −12.39 | 只拦到 3 笔 |
| conf≥70 | +996 | +996 | −2.37 | **−26.19** | 不一致 |

**另一个负面发现**：费用效率门几近空门 —— 215 笔中 **191 笔 pf_ratio > 20**
（TP 距离已是费用的 20 倍以上）→ 费用并未挤占 TP 空间，问题是**走不到 TP**。

→ **决议：全部阈值维持 0（不拦）。** 任何启用需先有双窗口一致的证据。

> ⚠️ **幸存者偏差警示（复核方攻击点 3，作者采纳）**：本回放的反事实 = **直接剔除被拦交易**
> （假设不开仓），**未计资金复用与机会成本** —— 被拦的资本可能在别处赚钱。
> 故「留存/笔」只能回答「该门在当前账本上是否止漏」，
> **不能被解读为收益预测或整体资本配置改善**。若未来要讨论机会成本，
> 需在 `admission_replay.py` 内增加资金复用模型，而那是一个**新假设、需预注册**，
> 不得混入当前反事实。

### 6.2 `dead_signal_60m_mfe0.3` 与 `MFE_STALL_EXIT` 的关系（**非等价** — 已按复核意见修正）

> ⚠️ **作者初稿错误（复核方攻击点 6，已采纳）**：初稿写「`dead_signal` = 现有 `MFE_STALL_EXIT`
> 的参数变体，机制已存在无需新规则」—— **这个等价声明不成立**。两者语义不同：
> - `dead_signal_60m_mfe0.3`（shadow）= **信号失效标签**，仅在 60min 记录 `triggered = MFE<0.3%`，**无任何退出行为**
> - `MFE_STALL_EXIT`（live）= **退出动作**，且带**水下硬条件** `profit_pct < 0`

| | 现行 live 参数 | 已毕业 shadow 变体 |
|---|---|---|
| 时间 | 150 min | **60 min** |
| MFE 阈值 | 0.5% | **0.3%** |
| 水下要求 | **是**（`profit_pct < 0`） | **无** |
| 浅亏豁免 | 是（>−1% 转持有） | — |

**关键风险（复核方指出）**：若直接把 `MFE_STALL_EXIT` 调成 60min/0.3% 并**去掉水下要求**，
会**误杀正浮盈仓** —— 某些仓位 60min 时 MFE<0.3% 但当前已微转正（如 +0.1%），
强平它们违背 first-night gate 的「零质量损失约束」。

**修正后的结论**：
1. `dead_signal` 的分离度（+1.51pp）**不能**直接用作「在正浮盈状态下强制退出」的依据；
2. 若未来要将其实单化，**应保留 `profit_pct<0` 水下条件**，或新增独立开关
   `mfe_stall_exit_require_underwater` 明确是否允许在盈亏附近触发；
3. 去掉水下要求的版本属于**未经验证的新变体**，需先回 shadow 重新判分。

→ **待裁**：验证期内改 live 退出参数 = 新机制插队，需**知情破例 + 归因影响评估**（宪章 §四）。
