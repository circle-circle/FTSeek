### 核心新发现 ②：W_WEEK 水下豁免把"从没对过"的仓放行隔夜

**主会话日志证据**（`logs/ftseek_us.log-2026*.gz`，轮转语义：文件按 CST 日期收，ET 盘跨两个文件）：

⇒ **改阈值 `dead_signal_exit_mfe_pct` 0.2→0.3 对这三笔完全无效**（0.03% 本来就 <0.2%，分支照样进入、照样豁免）。⇒ 杠杆 P1 降格。

### D2 · ① MFE 口径拆分（零交易行为变更）

**加列**（`trade_records`，只加不改）：
- `mfe_tick_pct REAL` —— tick 通道**全程**峰值（复现在线闸门口径；bar 峰值已可从 `metadata_json.peak_price_bar` 复算，不另加列）
- `mfe_gate_pct REAL` —— **闸门评估时刻**读到的 peak（复现死信号/豁免判定口径）

`mfe_pct` **语义保持不变**（全程峰值，含隔夜尖峰），但必须补单位声明注释 + 契约测试断言（军规：新增落库字段必带单位/量纲声明 + 契约例）。

**消费方处置（关键纪律）**：
- **本批只做"加列 + 报表并列披露三个口径"，不改任何门禁的读列** ⇒ 零行为变更；
- `symbol_streak_ban`（`intraday_indicators.py:264`）当前读落库 `mfe_pct`，**保持不动**（改读列 = 行为变更，须影子先行；且它前进窗 0 次触发，改动无可观测差异，但不能因此跳过纪律）；
- `e60_ok`（`close_flow.py:851`）、DEB 探针墓地分档、`bundle_builder`、`factor_ic_backfill` 一律**保持不动**，仅在报表侧并列披露替代口径；
- 后续若要迁移任一消费方，**每个独立立项、影子先行**。

### D3 · ③ KR2 死单率口径钉死（纯裁决，零改动）

**裁决：KR2 死单率 = 落库 `mfe_pct` < 0.3%（A9/A10 口径）。**
理由：① **与既有基线同轴** —— C12 的"入场即错"基率 **26.0%（mfe<0.3%）** 就是这个口径，换口径会切断与历史基线的可比性；② KR2 的对象是"入场即错"这一**交易属性**（全程从未朝有利方向走），全程峰值是最贴近该语义的量；③ 换口径 = 改判据（判据字典 §使用规则 4：改判据 = 重新裁决），本次不为此改口径。

**替代口径降级为披露项**（不参与达标判定）：tick 口径 / 闸门口径 / 决策时刻口径，由 ① 的加列提供可算性，报表并列输出。
**并记一条**：tick 口径下 DA 死单率 **22.56%**（贴 23.0% 线）⇒ 若将来改口径，达标判定会翻转 ⇒ 改口径必须重新裁决。

### D4 · ② W_WEEK 豁免分档 —— **降级为纯观测影子**（原提案降格）

**原提案**：给 W_WEEK 豁免加"当日 peak 下限"（peak<0.1% 的仓不享多夜豁免），预注册毕业判据。

**降级理由（三条，均为红线/终裁约束）**：
1. **C11** 明写："跳空发生在夜里，开盘时仓已 −4.6%~−6.7% 且 SL 已被打穿 ⇒ **开盘无决策空间，唯一真实决策点是前夜 EOD**"；而 peak 下限只能在**入场后 60 分钟**判定 ⇒ 这是**比前夜 EOD 更早的时点**，机制上可行，但：
2. **B19 `eod_depth_gate` 已终裁 GATE_NOT_WORTH**（2026-10-14：n=9、ΣΔ=−293.98、误杀 5/9）⇒ 同一出血口换判据轴（depth → peak）**不产生新信息**（C11/C14/C16 家族条款明文禁止"同族换动作"）；
3. **B15** 已存在隔夜臂判罪线（修复率<40% ⇒ 提请裁排除 `loser_overnight_enabled`）⇒ 本议题应挂在 B15 下作子集细化，不另开平行判据。

**降级后的形态**：
- **纯观测（record-only）**：只按 peak 分档**记账**，不改任何豁免行为、不设毕业门、不进任何 live 路径；
- **必须预注册的"本议题关闭条件"**：若 peak 分档命中集与 B19 命中集**完全重合** ⇒ 本议题关闭（不产生新信息，不得再以同族理由重开）；
- **允许的后续路径**（不在本批）：若观测窗显示 peak 分档命中集与 B19 **不重合**（即 peak 轴触及 B19 触及不到的笔——机制上可能：B19 的 depth 轴在**前夜 EOD** 才看，peak 轴在**入场后 60 分钟**就看，是**过程变量 vs 结果变量、时点早 vs 时点晚**的差异），则**另立 RFC + 用户裁**申请带毕业判据的影子；
- **红线遵守**：本议题**不得**以"隔夜跳空亏损仓放宽 SL / 补仓摊平"（C11）、"EOD 减半隔夜仓"（C14）、"取消隔夜"（C17）、"偏斜 guardrail"（C15）、"入场形态轴"（C16）任何形态复活——那五项均已被历史数据终局证伪。

- **本次踩到的 3 个工程缺陷**（须进 ops 知识）：

## N4 专节 · `entry_confirm` 门（入场前 2 分钟观察价格是否反转）

**是什么**：`app/playbook/entry_confirm_gate.py`，`DEFAULT_DELAY_SEC=120`（影子只裁过 2min/5min 两条腿；判定必须落在 10s 快循环，否则等于静默落地未预注册变体）。语义：**入场前**"让子弹飞"2 分钟 —— 价格仍站触发方向才进场，反转就放弃。锚 = arm 时刻的 reprice 执行锚（两锚分歧中位 2.10%、38% 的行分歧 >2% ⇒ 选错锚会翻转超三分之一判定）。

**它瞄准的正是"死单"的第一族**：门存在的理由原文写着 "SL_INITIAL 出血族 (进场即反向, MFE=0, ~17 分钟被杀) 是 playbook 最大单一亏损族: 近窗 6 笔 −$898, 全史 −$2,963"。

**实测证据（很强）**：影子回放（DEB-20260909 §5.2 / `scripts/entry_delay_confirm_shadow.py`）——"触发后延迟 2min 复核, 价格仍站触发方向才进场"对**该族避免率 65.5%、误杀 0、日聚类 t=4.92**。
**但该读数用的是事后 `exit_reason` 标签人群** ⇒ T19 红线：`exit_reason` 不得进门前置 ⇒ live 门无法据此识别 ⇒ 2026-10-10 用户裁「直接走 sim 交易链路」⇒ `holdout_pct=0` 全量走门、无同期对照臂（代价=受市况混淆，RFC-141 §5.4 已披露）。

**它是怎么被关掉的**：2026-10-31 按 RFC-141 v2 预注册后果执行 `entry_confirm_enabled=false` + 重启。当时读数：**verdict = INSUFFICIENT**（族样本仅 5 笔）、判据 1 FAIL（SL_INITIAL 族净均 −$120.4，未达严线 −$40；基线 −$162.3 ⇒ **实际改善了 26%**）、判据 2 ❌、判据 3 ❌、仅判据 4（剔费净均 +$23.08）✅。

**⚠️ 治理疑点（本 DEB 登记，不自行裁决）**：RFC-141 §5.5「判据 1 是限速环节」明文写 —— *"会出现「总量样本够但病灶族样本不够」的相位。此时**不得**用「样本不够」当通过理由，也不得改用其它判据替代；结算器会如实输出 INSUFFICIENT/OBSERVE，**裁决须等族样本到位**。"*
而实际执行是 **verdict=INSUFFICIENT（族样本 5 笔）→ 直接关门**。
⇒ **该门是在"族样本不足"状态下被关的，而预注册明文要求此时应"等族样本到位"而非关门。**
⇒ 且关门时的读数方向**正向**（族净均 −$162.3 → −$120.4，改善 26%），并非机制证伪。
⇒ **重开与否属用户裁决事项**（用户已裁过关门），本 DEB 只登记疑点与证据，**不自行重开**。

**它的已知缺陷已修过两轮（重开时应直接用 v2 形态）**：v1 前瞻 54 行暴露 ①**混尺**（锚=ask/bid 成交侧、复核=last trade，价差跳动被当反转：INTC +1.6bp 即弃单）②**一次性**（单点采样定生死）⇒ v2 改 mid-vs-mid 判尺 + grace 2-of-3 持续性（到点首见逆向进 grace，≤3 次 sweep 内 ≥2 次逆向才弃，任一同侧即确认，取价失败不消耗次数，耗尽不足票 ⇒ 确认放行 = fail toward trade）。

**它与本 DEB 的死单早退提案的关系**：同一族（进场即反向），**不同作用时点**：
- `entry_confirm` = **入场前 2 分钟放弃** ⇒ 不进这个单 ⇒ **不付往返费（$5.13）、不占风险预算** ⇒ 严格优于入场后认赔；
- 15min/60min 峰值捕获 = **入场后认赔** ⇒ 已付往返费、已占风险。
⇒ **若 15/60min 影子证实死单可识别，第一顺位应是"入场前放弃"而非"入场后认赔"**（省下 $5.13/笔 + 释放风险预算）。
⇒ **但入场前的"死单预测"需要可事前观察的信号**，而 C12 已证六类静态字段（confidence / decision_conf / risk_reward / ok_dimensions / model_used / vol_bucket）**对成交质量零区分度**（eta² 0.07~2.29% < 5% 门）⇒ **静态字段这条路是死的；`entry_confirm` 的信号是"触发后 2 分钟的动态价格行为"，不在那六类字段里** —— 这正是它比 C12 那批字段更值得注意的原因：**死单的可识别性存在于动态价格路径，不存在于静态分析字段**。
