## 一、背景与问题陈述

系统现状 (2026-08-05 核实):
- **执行链路**: 入场市价单追突破; 保本/trailing/停滞退出全部由 pipeline 20s 轮询循环自实现 (pipeline.py `_check_playbook_exit_rules`); OpenD 近期重连抖动 11-15 次/日 (均 60s 内自愈, 但轮询退出在断连窗口裸奔)。
- **行情侧**: QUOTE/K_1M/TICKER/ORDER_BOOK 已订阅推送 (futu_lv3_provider.py:397-529 四个 push handler), ORDER_BOOK 十档盘口**已订阅但几乎未入决策** (仅 `_gather_intraday_evidence` 有订单流雏形); 盘后快照今日刚接通 (after_hours_shadow); **盘前行情未采集**。
- **门A 教训**: 40% 回撤规则 1-min 重放增量仅 +$0.32/笔 (p=0.67) — "靠规则改善捕获"天花板低; 而**执行延迟/粒度**是规则无法触及的另一维度 (重放中触发 bar 收盘粒度滑损 $37.8)。

## 二、五项主张 (待辩)

### 主张1: 服务端条件单 — 把 SL/TRAIL 落到富途侧
- 现状: 保本 ratchet、SL_TRAIL_LOCK、MFE_STALL 全部靠 20s 轮询判断后市价单; 断连/重启窗口无保护; 退出价=轮询到的 last quote。
- 提议: 开仓成功后即向富途挂**服务端止损/移动止损条件单** (TrailingStop/StopLimit, 富途 OpenAPI 支持关联单), 轮询逻辑降级为对账/兜底。
- 预期: 退出延迟 20s级 → 毫秒级; 断连保护; 捕获率改善 (门A 重放显示粒度滑损 $37.8/17笔)。
- 风险: 状态机复杂度 (本地退出决策 vs 服务端单的同步/撤单); SIM 账户是否支持条件单需实测; 双通道竞争 (本地先触发 vs 服务端先成交)。

### 主张2: 盘口深度特征入入场影子
- 现状: ORDER_BOOK 十档已订阅推送, 未产出可回测特征。
- 提议: 每次入场触发检查时记录 bid/ask 深度不平衡 (前5档量差/额差)、spread、队列斜率 → 并入 `data/entry_timing_shadow.jsonl` (现有攒样框架), 见数前不作判据。
- 预期: 零新增订阅成本; 为入场择时 logistic 过滤提供订单流维度。
- 风险: 特征噪声; 与 vwap_dev/slope 共线; 攒样周期。

### 主张3: 盘前行情采集
- 现状: 盘后快照已通 (`get_snapshot_after_hours` 走 `_connect_for_historical`); 盘前 (04:00-09:30 ET) 无采集。
- 提议: 同法接通盘前快照; 开盘篮子入场前先取盘前价/量, 缺口 (premarket gap) 作为入场条件特征 + 指令 anchor 新鲜度校验 (PLTR 型 +23% 跳空占位事故的直接解法)。
- 预期: anchor_dev_pct 从"指令生成时锚"升级为"盘前实测锚"; 开盘方向先验。
- 风险: 盘前流动性差, 价格噪声大; 采集时段与现有服务生命周期错配 (服务是否 04:00 ET 在跑?)。

### 主张4: RT_DATA 逐笔数据
- 现状: 未订阅。
- 提议: 入场决策用逐笔方向/大单过滤。
- 反方预判: 噪声大、配额贵、本系统 20s 决策粒度吃不下逐笔; 除非限价入场落地才需要。

### 主张5: 期权链 / IV 信号
- 现状: 未用 (期权代码快照已有路径)。
- 提议: 远期 — IV 异常/期权异动作事件确认。
- 反方预判: 当前日内动量框架用不上, 纯增加复杂度, 建议显式否决。

## 三、裁决要求

1. 每主张给出: 维持/修改/否决 + 依据 (代码证据, 不得凭空)。

3. 明确实施顺序与依赖 (如: 主张1 需先实测 SIM 条件单支持)。
4. 富途 API 能力以 futu-api SDK 文档为准, 不确定处显式标"待实测", 不得编造接口名。

### 4.1 反方攻击要点 (★=主控已复核)

1. **主张1 (服务端条件单) — 最该否决**: ★SIM 不支持 STOP 已实证 (E2); LIVE 侧开仓挂 STOP 已存在 (`post_trade_hook.py:166-209`) 且 `broker_stop_order_id` 只写不读、**无撤单路径** (孤儿单存量债务); 收益锚 $37.8 系不显著规则 (p=0.67) 的中间量, 且 17 笔中 9 笔多峰/7 笔触发后更高 → "更快退出"方向性更差; TIME_EXIT/MFE_STALL/PRE_CLOSE 等非价格规则无法服务端化。
2. **主张2**: ★前提失实 (E1/E3); 与在跑 S2 窄校准实验 (08-04→08-18) 直接冲突 — 该实验预注册"IC≈0 则合法关门"且明令实验期不动订阅 (`orderbook_s2_capture.py:7-16` ★); 顶层 OFI 特征 73 笔历史检验胜率 50%/44%/44% 无区分度 (DEB-20260724 先例)。
3. **主张3**: PLTR 案上周已裁"现有守卫已拦截、gap-and-go 无正期望证据"; anchor_dev_pct 是 record-only 归因字段**无行为消费方**; force_reconnect 盘前拒绝重连 → 采集可靠性差; 开盘前快照配额最紧张 (历史 P0 打爆前科)。
4. **主张4/5**: TICKER 实现已存在被砍未复活、20s 粒度吃不下; 期权链决策层零消费者。

### 4.2 方法论审计 (验证设计)

- **主张1 影子路径不闭合**: 未挂出的服务端单无成交价、无亚 20s 历史价 → record-only 不可识别; 须改型: SIM 双臂随机对照 + 主判据**过程量** (时延/成交偏差/断连覆盖率, n=30 ~2周), pnl 仅作**单侧非劣守卫** (Δ=+$2); pnl 优越门按实测 σ≈$18.5 需 MDE≥$10 才可达 (~4-5周), 先验效应 $1.5-3 → **冻结**。效应锚勘误: 服务端单 vs 20s 轮询的剩余收益先验 ≈$1.5-3/笔, 非 $2.22 (那是 1-min 对连续时间的差)。
- **主张2**: 先过**数据质量门** (ob_* 非空率 ≥95%) 再攒样; 毕业检验=增量 rank-IC (在 vwap_dev+slope 基线上), ρ_MDE=0.15 → n≈350 ~8周; 禁裸边际 IC; "门内 vs 门外 pnl"毕业设计=门A 式选样恒等式, 禁用。
- **主张3 拆两 estimand**: 3a anchor 测量升级 (配对一致性, n=50 ~1周, 不设 pnl 门) + 3b gap-IC (n≈346 ~5周); PLTR 型尾部 (|gap|>8%) 被守卫截断, 前瞻不可辨识, 只记过程量。
- **主张4/5**: 无 estimand 违反规范§2 → 显式冻结/否决。
- **交互 (D12)**: 主张1 与门A/B 共用退出链、非独立可部署 → FWER 豁免前提不成立, **门A/B 毕业前主张1 只做过程量影子**。
- 规格缺陷清单 D1-D15 详见辩论代理原报告 (核心: 五主张原稿均未按规范§1/§2 预注册)。
