### 提案 E1: 0.5ATR 可达性门 — 限价回退市价 (附离线预验证 ★)

**机制**:
- 在 `app/playbook/entry_routing.py` 的 `resolve_route()` 中, 当 archetype=PULLBACK_LIMIT 且 `reach_dist_atr > 0.5` 时, 返回 `action=None` (回退市价), 而非挂限价等待 expired。
- `reach_dist_atr` 在指令生成时由 `instruction_generator.py` 计算 (确认位 vs 触发时快照距离 ÷ ATR), 存入 `playbook_instructions.conditions_json`。
- `reach_dist_atr ≤ 0.5` 时维持现状 (限价 + TTL)。
- 判据不可挪: 0.5ATR 是 ADR-035 C3 预注册桶界, **非本次新选阈值**。

**防自欺机制**:
- 0.5ATR 是预注册边界, 本提案不涉及阈值选择。灵敏度扫描 (0.25/0.35/0.50/0.75/1.0) 仅展示范围, **不用于选阈值** (避免阈值购物)。
- 前视偏差检查: `reach_dist_atr` 在指令生成时计算 (决策时点已知), `act_replay_net` 是同一重放器的市价臂结果 (非未来信息)。配对差的两臂共模偏差在差里抵消。
- 致命限制: 重放器对 OVERNIGHT_GAP_STOP 复刻为 0 (fidelity match_rate=0%), 对 SL_TRAIL_LOCK match_rate=40% — 市价臂 `act_replay_net` 可能高估或低估真实市价结果。**配对差可信, 绝对值不可信**。

**接线**:
- `entry_routing.py::resolve_route()` — 增加 reachability 分支, 返回 None 时 pipeline 维持市价 (零行为变更, 等于关闭限价路由)。
- `instruction_generator.py` — 确认位距离 ÷ ATR 写入 conditions_json (已有 `anchor_dev_pct` 字段可复用)。
- 消费者: `pipeline.py` re-price 段 (~L4222) 已处理 `action=None` → 市价执行路径。
- 开关: `playbook.entry_archetype_routing_enabled` (ADR-035 已冻结, 默认 false)。

- 目标: 过滤开盘首2分钟的"假突破/瞬态尖刺"死亡族 (MFE=0, MAE 1-4%)。

### 提案 E3: DA 锚价刷新门 — 过时锚抑制

**机制**:
- 在 `instruction_generator.py` 生成指令时, 若 `anchor_dev_pct |dev| > 0.5%`, 标记 `anchor_stale=True`。
- 在 `pipeline.py` re-price 段 (~L4222), 对 `anchor_stale=True` 的指令, **强制用触发时实时报价重算确认位** (而非用 DA 生成时的 `entry_price`), 然后再判定是否路由限价。
- 不改变执行方式 (仍市价或限价), 只改变限价位的锚定基准。

**防自欺机制**:
- 61.8% 的指令 `|anchor_dev|>0.5%` — DA 锚普遍过时是观测事实。
- 但: 执行滑点 median 仅 -0.026% (市价执行本身没问题) — **病不在执行滑点, 在以什么价为锚**。刷新锚后, 确认位会移动, 可能改变 `reach_dist_atr` 的分布。
- 前视偏差: 触发时实时报价在决策时点已知, 非未来信息。
- 风险: 刷新锚后确认位变动, 可能将原本可达的单变成不可达 (或反之) — 需影子验证。

**接线**:
- `instruction_generator.py` — 生成时计算 `anchor_dev_pct`, 写入 conditions_json
- `pipeline.py` re-price 段 — 读取 `anchor_stale` 标记, 重算确认位
- `entry_routing.py::resolve_route()` — 用刷新后的确认位计算 `reach_dist_atr`
- 消费者: 与 E1 同路径

**可验证性**:
- 影子方案: 在 `cf_pullback_limit_replay.py` 中增加 "anchor_refresh=True" 分支, 用触发时 bar_open 作为新锚重算 `reach_dist_atr`, 比较刷新前后的 fill_rate / 配对差。
- 预注册判据: 刷新后 fill_rate 不降 + 配对差不变差 (n≥40)。
- **无离线预验证结果** — 需新增影子脚本, 本提案为方向性提案。

### 提案 E4: 死亡族开盘抑制门 — MFE=0 前置过滤

**机制**:
- 目标: 在入场前识别"入场即错"族 (MFE=0, 从未翻绿), 而非改善入场价。
- 观测: MFE=0 死亡族 19笔 (10.6%), 净 -$2035, avg MAE 1.87%, 12/19 在9点档。Oracle 上界: 跳过全部 MFE=0 可省 $2035 (净从 -$672 → +$1363); 跳过全部死亡族可省 $3529 (净 → +$2857)。
- 代理特征 (决策时点已知): `entry_session=regular` + `entry_hour=09` + `anchor_dev_pct |dev|>0.5%` + `signal_confidence < threshold`。
- 在 pre-entry gate 增加死亡族评分, 超阈值则抑制入场 (放弃, 不市价追)。

**防自欺机制**:
- **反事实验证 (离线预验证)**: 对死亡族 SL_INITIAL/tighten 的14笔 (有 SL 距离数据), 模拟入场价改善 10/15/20bp 后是否存活:

| 改善bp | 存活数 / 分析数 | 结论 |
|--------|---------------|------|
| 10bp | 0/14 | 入场价改善无法救死亡族 |
| 15bp | 0/14 | 同上 |
| 20bp | 0/14 | 同上 |

> **原因**: 死亡族 MAE 中位 2.14%, 而 15bp=0.15% — 改善量比 MAE 小14倍。SL 距离 ~5%, 改善15bp 仅把 SL 距离从5%扩到5.15%, MAE 2% 远未触及。**入场价精度不是死亡族的病因, 方向/时点才是**。
> n=14 < 30, **仅方向性参考, 不可作证据**。

- 前视偏差风险: MFE=0 是事后才能知道的。代理特征 (开盘时段+锚过时+低置信) 必须在入场前可计算。
- 否决特征先查基率 (C8 前科): 9点档 death_rate=17.9% (24/134), 非死亡率82% — **单纯9点档不可作否决门** (会错杀82%)。需多特征组合。

**接线**:
- `app/playbook/candidate_eligibility.py` — 增加死亡族评分函数
- `app/pipeline/stages/risk_stage.py` — pre-entry gate 消费评分
- 消费者: pipeline pre-entry gate hook
- 无新表新文件 (评分写入现有 conditions_json)

**可验证性**:
- 影子方案: 对历史9月交易, 用代理特征回放死亡族识别率 + 误杀率 (非死亡族被抑制的比例)。
- 预注册判据: 死亡族召回率 ≥50%, 误杀率 ≤20%, n≥40。
- **无离线预验证结果** — 需新增脚本。Oracle 上界 ($2035-$3529) 是激励, 不是证据。

### 提案 E5: 混合门 — 可达性门 + 开盘延迟确认 (E1+E2 组合)

**机制**:
- E1 门把 dist>0.5 的单回退市价, 但市价入场在开盘首2分钟是死亡族高发区 (E4 观测)。
- 组合: dist>0.5 → 市价 + E2 延迟确认 (开盘时段); dist≤0.5 → 限价 + TTL (现状)。
- 目标: 同时获得 E1 的 $209.91 回收 + E2 的 SL_INITIAL 避免价值 $2781。

**防自欺机制**:
- E1 和 E2 的影子数据来自不同管线 (pullback_limit_replay vs entry_delay_confirm), 人群不同, **不可直接相加** ($209.91 + $2781 = $2991 是错误的)。
- 需要联合影子: 同一笔同时走"可达性门判定 + 延迟确认"的双门路径。
- 前视偏差: 两门的输入 (reach_dist_atr, 2min后价格) 均在决策时点可知。

**接线**:
- `entry_routing.py::resolve_route()` — 返回三元路由: `limit` / `market_delayed` / `market_immediate`
- `pipeline.py` — 消费三元路由, market_delayed 走延迟确认路径
- 消费者: 同 E1+E2

**可验证性**:
- 影子方案: 联合 `cf_pullback_limit_replay` + `entry_delay_confirm_shadow` 的决策 ID 交集, 对同一笔同时施双门。
- 预注册判据: 联合后 C3 fill ≥50% + 误杀 ≤40% + n≥40 (ADR-035 四门, 不挪)。
- **无离线预验证结果** — 需联合脚本, 本提案为架构组合提案。

## 2. 观测事实 vs 推断 分行书写

### 观测事实 (数据直接读出, 无推断)

- [F1] 9月180笔: 毛利$755, 费用$1427, 净-$672。费/笔$7.93 vs 毛/笔$4.19。

### 推断 (基于观测的逻辑延伸, 非直接读出)

- [I1] 入场价精度 (15bp量级) 无法救死亡族 — 因为MAE 1-4% >> 15bp。死亡族病因是方向/时点, 非价格。 (基于 F3, F9; n=14<30, 方向性)
- [I2] "挂太远饿死好单" — dist>0.5 的23笔 expired 但市场臂盈利 ($426.93), 限价臂全部$0。回退市价可回收。 (基于 F5, F8; 配对差可信但绝对值受重放器保保守偏差影响)

- [I4] 延迟确认对限价单人群有害 (D_candidate 净-$197, 误杀82.1%) — 不可对限价单施延迟。 (基于 F12; n=116但效果方向明确)
- [I5] 0.5ATR 门虽改善净PnL (+$209.91), 但 C3 fill 46% < 50% 门槛 + 误杀 59% > 40% 门槛 — **不满足 ADR-035 四门, 不可单独转正**。需与 E2 延迟确认叠加才有可能过门。 (基于 F7, F10)
