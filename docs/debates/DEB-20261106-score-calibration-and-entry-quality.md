## 背景：为什么是这三件事

复盘结论不是"缺一个风控门"，而是三处**结构性空白**：

1. `score` 没有语义（6 与 8 无历史期望映射）⇒ 任何按分数分档的调参都是盲调；
2. 入场形态路由关闭（"低吸"指令仍市价追）+ `entry_confirm` 拦了最大量却无反事实结算 ⇒ 入场侧**不知道自己在改什么**；
3. DA 只能逐票答方向，**没有组合级前提可表达** ⇒ 崩盘日"提交 11 个 BUY"在机制上是必然，不是模型失误。

三件事的关系：**P1 是所有阈值讨论的前置**（不校准不许谈门槛）；**P2 直接压亏损尾部**（入场质量 MFE<0.2% 占 19.5%）；**P3 是唯一能让 DA 表达"今天别做多"且不重开价格门轴的路**。

## P1 · score 校准表（离线，零行为变更）

**假设**：`score` 在历史同口径样本上与实现净额单调相关；若成立，则 score 可作为分档依据；若不成立，则一切"按 score 调参"永久禁止，直至出现新特征。

**做法**（只读）
- 数据源：`playbook_instructions`（`row_kind='instruction'`，取 `raw_instruction_json.score`）+ `trade_records`（按 `decision_id` 关联净额）。
- 分桶：score ≤4 / (4,5] / (5,6] / (6,7] / (7,8] / >8（先看实际分布再定，但**分桶边界在跑之前写死**）。
- 产出：每桶 n / 胜率 / 均值 / 中位 / 期望；Spearman(score, pnl_net)；日聚类 bootstrap CI（seed 固定 20261106，2000 次）。

**预注册判据（三条全过才算"score 可用"）**
1. 每桶 **n ≥ 30**（不足的桶合并后仍不足 ⇒ 该区段不下结论）；
2. Spearman ρ 的方向与显著性：**ρ > 0 且日聚类 CI95 不含 0**；
3. 最高桶与最低桶的期望差 **CI95 不含 0**，且差值 ≥ 单笔往返费用（≈11.5bps × 名义）。

**停止 / 否决条件**
- 任一桶 n < 30 且全样本 < 150 ⇒ 结论记 `UNPOWERED`，不扩样本、不调阈值（前向攒样不作为主要路径，与 9/24 先例一致）。
- 单调性不成立 ⇒ **score 永久降级为"叙述性字段"**，禁止再出现在任何 gate/sizing 里（并清理现存按 score 分档的代码）。

**成本 / 回滚**：0 次 LLM 调用、0 配置改动；新增 1 个只读脚本。回滚 = 删脚本。

## P2 · 入场形态路由 + `entry_confirm` 结算

### P2a `entry_archetype_routing_enabled`（**唯一涉及生产行为的项，待裁**）

**现状**：`false` ⇒ `PULLBACK_LIMIT` / `FADE_SHORT` 指令以市价成交。已知机制根因（配置文件注释原文）：
"路由开启后以确认位限价单 + TTL 撤单入场，不成交=放弃，零市价追单，消除'低吸变追高'"。
**已有依据**：ADR-035 预注册判据；`entry_archetype_ttl_seconds=300`（5min TTL 影子 Δ+416.8/108 对，30min TTL −224.4）；`entry_archetype_reanchor_enabled=true`（依赖本开关才有执行意义）。

**启用判据（三条全过）**
1. 影子样本 `pullback_limit_shadow.jsonl` 中 would-fill 率 ≥ 60%（低于此则限价单大多不成交，"零追高"等于"零成交"）；
2. 影子 CF-PnL 相对同期市价臂：**净额差 CI95 不含 0 且方向为正**；
3. 覆盖度：带 archetype 的指令占比 ≥ 30%（否则影响面太小，不值得动执行链）。

**停止条件**：启用后 10 个交易日若 ①成交率下降 > 40% 且 ②CF-PnL 未改善 ⇒ 当日回退 `false` + restart。

### P2b `entry_confirm` 反事实结算（离线，补观测）

**现状**：30 天拦 **80 条**（最大拦截量），但 `data/shadow/entry_confirm_forward.jsonl` 仅 8 行、无 settlement ⇒ 净效果不可判。
**做法**：把 `entry_confirm_post`（弃单后 +5m/+10m 补记）接入结算器，产出"被拦指令的反事实净额"分布，按方向/时段/score 分层。

**判据（决定该门去留，不改阈值）**
- 结算样本 **n ≥ 100** 才出结论；
- 若"被拦组反事实净额"均值显著为负（CI 上界 < 0）⇒ 门有效，**加强**（考虑扩大适用范围）；
- 若显著为正（CI 下界 > 0）⇒ 门在误杀，**下调或豁免**（走新预注册，不在本次）；
- 若不显著 ⇒ 维持现状，记 `NO-EVIDENCE`，不再反复评估。

**成本 / 回滚**：纯离线；回滚 = 移除结算脚本。

## P3 · `market_premise` 字段（离线 A/B，不作为 gate）

**假设**：给 DA 一个**组合级前提字段**（不是价格门），可以让它在冲击日表达"限制/禁止做多"，从而避免"崩盘日提交 11 个 BUY"这种机制性错误，同时不重开 DEB-20260924 已关闭的价格门轴。

**字段定义（写死，先离线）**
```
market_premise: {
  verdict: ALLOW | RESTRICT | BLOCK,          # 只描述"新增多头"，不做空头限制
  evidence: [指数相对昨收(QQQ/SMH/IWM), breadth, 板块分位, 当日事件簇摘要],
  confidence: 0-1,
  as_of: ISO8601
}
```
- 输入全部来自**已有数据**（`data/cache/daily_kline_v1.json`、`event_stream.canonical_events`、`playbook_regime_log`），不新增外部依赖。
- 该字段**只进 prompt 与事后归因**，不驱动 auto_execute、不改任何 gate、不改仓位。

**离线判据（三条全过才讨论"是否让它影响下单"）**
1. **冲击日召回**：在 11-05 / 10-30 / 7-29 等 5 个已知冲击日，`verdict ∈ {RESTRICT, BLOCK}` 命中 **≥ 4/5**；
2. **常态误伤**：在同期 20 个常态日中，`BLOCK` 误报 **≤ 1/20**；
3. **可复现**：同输入 N≥10 复跑，`verdict` 一致率 **≥ 80%**（这一条直接引用重复性实测：方向翻转率 8.3%，故 80% 是可要求的下限）。

**否决条件**：任一条不过 ⇒ 字段只保留为"事后归因标签"，**不得进入 prompt**（避免污染推理链），并记入 §7 禁令表。

**成本**：离线复用现有 LLM 预算，单批 ≈ 2 次调用；不改 config。
