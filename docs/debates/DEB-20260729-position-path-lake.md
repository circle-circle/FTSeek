# DEB-20260729-position-path-lake: 持仓路径湖 + 统一决策视图 — 把"两周一问"提速到"当天一问"

> **状态**: 🔶 新起案 (作者 Qoder) · 待辩论方证伪 → 待用户裁决
> **分类自评**: 修尺子 + 攒样本 (验证期白名单内); 零 live 信号/退出行为变更
> **预注册判据**: §五 · **辩论方任务**: §八

## 一、问题定义 (三个具体痛, 全部有锚点)

1. **反事实分析被"无路径"卡脖子**: `dd_param_scan.py` 被迫用单峰一阶近似
   (自述"忽略多峰路径与规则竞争"), 因为 trade_records 只存 `peak_price`/MFE 两个标量;
   be_shadow 顺风日零样本 (07-28 复盘), 埋点攒样本需 2 周/问题 — 两者根因相同:
   **没有 per-position 分钟级路径沉淀**。
2. **决策数据散落四面, join 靠人肉**: playbook_instructions (DB) / trade_records (DB) /
   trigger_miss_telemetry.jsonl / *_shadow.jsonl / exit_telemetry — 每次分析重新写 join,
   且已出过一次口径事故 (§14.2 跨窗口拼接叙事)。
3. **好现象被埋没**: `trade_records` 已有 `signal_id`/`decision_id`/`trace_id`/`config_version`
   且近 7 日 78/78 全填充 (2026-07-29 实测) — 串联的地基已存在, 缺的是"官方串联层"。

**本质主张**: 系统独有的资产 = 决策×状态×路径×反事实 (行情数据是商品)。
当前缺"路径", 且四要素缺统一索引 → 每次假设检验的边际成本 = 埋点+等待,
而非查询。本 DEB 把边际成本降为零。

## 二、存储架构决策: 各自存储 + 统一串联层 (handoff 模式的物化)

**不建单体数据仓**。类比 handoff 机制: handoff 不把 DEB/spec/OKR 合并成一个巨文件,
它是"单一进度队列 + 指针"。数据侧同构:

| 层 | 决策 | 理由 |
|---|---|---|
| 写侧 | **各自存储原样不动** (trade_records/telemetry/shadows/JSONL 全部保持) | 验证期纪律 + 零回归风险; 每个存储样式服务其写入方的局部效率 |
| 串联 | **`decision_id` 为官方主键**, 全链路穿线 (instruction→trade→telemetry→shadow→path) | 地基已实测 78/78 填充; 缺的只是"宣布它是官方键"并在缺口处补线 |
| 索引 | **数据地图文档** (`docs/data-map.md`, 比照 `docs/circuit-breaker-map.md`) | 每张表/文件一行: 主键/粒度/写入方/消费方/口径坑 — 防"平行层"与口径拼接事故 |
| 读侧 | **统一视图是查询层, 不是管道重写** (SQL VIEW/查询脚本) | 读侧合一, 写侧零风险 |

一句话: **存储保持联邦, 身份归于单一 (decision_id), 索引成文 (data-map), 读取成视图**。
这正是 handoff "单一队列+指针" 而非 "巨文件" 的同构决策。

## 三、P0: 持仓路径湖 (本 DEB 核心交付)

**设计**: 平仓事件后 (monitor_playbook_sim_exits 的 _close_position 完成处),
异步触发路径采集 — **复用 `scripts/exit_replay_backtest.py` 的 `fetch_bars` (L157)**
与 `data/replay_bars/US_{SYM}_{DATE}.json` 已有约定 (313 文件在跑),
落 `data/position_paths/{decision_id}.json`:
- 窗口: entry-30min → exit+30min 的 1min bar (含盘前/盘后若可得)
- 标注: entry/exit/peak 时刻与价格、config_version、exit_reason、vol_bucket
- 失败语义: 采集失败只 WARNING, **绝不影响退出链路** (try/except 全包 + 后台线程)

**为什么够**: 300 笔/季 × ~460 bar × 6 浮点 ≈ 数十 KB/笔, 存储可忽略;
一次建成后, dd 扫描类问题从"近似"变"精确", 新退出假设从"埋点等 2 周"变"当天查湖",
shadow 退位为最终确认手段。

## 四、P1: 统一决策视图 (读侧, 跟随 P0)

- `scripts/decision_view.py` (只读): 按 decision_id 一行一决策 —
  状态 (instruction 字段+entry_vix/entry_session) × 动作 × 结果 × 路径文件指针 × 各 shadow 反事实;
- 缺口补线 (辩论方先验证): playbook_instructions ↔ trade_records 的 signal_id 对应率 —
  作者实测 trade_records 侧 78/78, **instructions 侧是否可反查未验证 (§八 T1)**;
- `docs/data-map.md` 初版 (随 P0 一起交)。

**明确不做** (预注册, 防范围蔓延): 不改任何写侧 schema; 不建 ETL 管道;
不按标的/行业学参数 (n<5/股 = 占星术, 层级学习纪律另文); 不引入 ML 退出模型
(bandit 反馈 + n 太小, shadow+replay 的 OPE 在此规模严格更优)。

## 六、诚实边界 (作者自陈)

1. **不解决 n 饥饿与非平稳**: 湖让"问问题"变便宜, 不让"结论"变多 —
   七律#5 (n<30) 与 config_version 断代纪律原样适用, 湖上结论照样受约束。
2. **选择偏差原样存在**: 湖只含已成交笔的完整结局; 未触发/被拦笔仍只有 fwd_return 代理
   (trigger_miss 方向不在本 DEB, 属后续)。
3. **OPE 方差**: 离线政策评估在 ~300 样本上方差大, 湖上排序结论仍需 shadow 终裁 —
   "湖取代 shadow" 是误读, 正确关系是"湖出题, shadow 终裁"。
4. **前视风险**: 路径含 exit+30min 数据, 任何用湖设计的规则必须证明训练窗与评估窗分离
   (比照 L2 replay 的无前视断言)。

## 七、已否决的替代方案 (想过, 放过, 给理由)

- **单体数据仓/ETL 重写**: 验证期写侧大改 = 回归风险换存储洁癖, 且串联问题 90% 靠
  decision_id+视图即可解决, 重写只解决剩下 10%。
- **feature store + ML 退出模型**: n≈300/季 + bandit 反馈 (只见已选动作结局) →
  监督学习系统性有偏; 非平稳下模型过期快于训练。
- **先加更多 shadow**: 无路径湖的 shadow 仍答不了"为什么", 且每个占 2 周窗口。
- **按标的/行业维度沉淀学习**: 每股 n<5, 统计幻想; 两维只做描述性切片。

### 核心设计修正 (T2 处方): "平仓后异步钩子" → "盘后批量 cron"

路径湖是**离线分析资产, 实时性零价值** — 无须在 _close_position 挂任何钩子:
- 收盘后 (16:30 ET) cron 一次性采当日全部平仓笔 (查 trade_records 当日 exit_time 非空 → 逐笔 fetch_bars)
- 收益: **G2 判据自动满足** (盘中零代码侵入=零风险); 复用 exit_replay 成熟批量模式+限流; 顺带补 T3 的当日缓存缺口 (采集写 replay_bars 同款缓存, L1 回放直接受益)
- 代价: 路径滞后至当日盘后 — 对"当天一问"目标无损 (问问题的人在盘后)

### 3 个补丁 (并入 P0 设计)

1. **autype=NONE 显式声明**: 路径与原始成交价对比, 必须继承 exit_replay 的 AuType.NONE 口径 (bar-ruler F2 教训, fetch_bars 已修但 DEB 须写明防复用时退化);
2. **隔夜仓窗口声明**: entry-30min 跨日时取前一交易日尾盘 30min (当前全日内平仓, 但 cohort B 设计在);
3. **G1 判据微调**: 覆盖率分母排除"fetch 返回空的休市/退市标的" (合法空), 与 exit_replay 同款区分。

**辩论方裁决建议**: 按 T2 修正后批准 P0+P1 — 修正后的方案比原案更简单 (无钩子、无后台线程、无退出链路交集), 交付物不变。
