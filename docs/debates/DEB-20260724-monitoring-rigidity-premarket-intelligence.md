## 一、感知 ①"盘中监控死板"的核验：**方向对一半，药方开反了**

### 1.1 成立的部分：盘中监控确实是"价格阈值状态机"，零语义感知

现状（`monitor_playbook_sim_exits`，20s 快循环）全部检查项：

| 检查项 | 输入 | 语义 |
|---|---|---|
| SL_INITIAL / BREAKEVEN / TRAIL_LOCK | 当前价 vs 动态SL线 | 价格阈值 |
| TAKE_PROFIT | 当前价 vs TP（RR≥1.5 门） | 价格阈值 |
| PRE_CLOSE / TIME_EXIT / MAX_HOLD | 时钟 | 时间阈值 |
| MFE_STALL_EXIT（07-24 新上） | 峰值浮盈 + 时钟 + 现价 | 价格×时间阈值 |

**确实死板在**：系统明知"为什么进场"（`da_thesis`、`invalidation` 失效条件已随指令落库，Stage 1 上链），却在持仓期间**从不回头检查论点是否还成立**——invalidation 只有 shadow 在跑（`invalidation_shadow.py`，纯观测不实平，`pipeline.py:5246`）。同样，持仓期间对**大盘/板块相对表现零感知**：07-23 崩盘日，一笔逆着 SPY -1.2% 的多头和一笔顺风多头，退出规则完全同权。**死板的本质不是指标少，是"已存储的语义数据没有被消费"。**

### 1.2 被证伪的部分："加更多指标"这条路已经实测走过，负结果

- **微结构指标已测**：`entry_timing_shadow.jsonl` 73 笔 live join 实测，OFI（订单流失衡）三分组胜率 50%/44%/44%——**无区分度**；slope_5m 仅弱反向。结论已归档（rootcause DEB §四-b.2）：不在无效特征上建模型。
- **波动率指标已测且有效** → 已转化为昨日上线的低ATR门（live ③）。
- **样本量纪律**：本系统每周仅 ~54 笔平仓。一次性加 5 个指标 = 多重检验下必然出现假阳性"完美指标"（第 5 轮 "<0.3% 完美分离" 过拟合教训的重演）。**指标不是不能加，是必须一个一个 shadow 预注册阈值再加。**

### 1.3 感知①的本质重述

> 盘中监控的短板不是"指标数量"，是**语义闭环断裂**：进场论点（thesis/invalidation）、市场环境（SPY/板块实时）、信号质量（conf）三类已有信息，退出侧一个都不读。加十个新指标，不如把已有三类信息接进退出决策——且前两类已有 shadow 数据积累，切换成本低。

同时要诚实说清**天花板**：4h 内日内持仓 + $3K 仓位 + 入场≈掷硬币的前提下，盘中监控优化的理论上限约 $150~250/周（TIME_EXIT 磨血段的残余 + 逆风加速离场），**不是**把系统从亏转盈的主杠杆。主杠杆见 §三。

## 二、感知 ②"盘前不智能，未用宏观/事件/板块/榜单"的核验：**信息源大多已接入，失灵在另外三层**

### 2.1 被证伪的部分：源已经在了

UE scan 的 clue brief（`llm_universe_scan.py:_build_clue_brief`）当前**已接入且全部开启**（config 实查）：

| 源 | 开关 | 状态 |
|---|---|---|
| 新闻硬事件分类 | `clue_hard_events: true` | ✅ |
| 财报日历 | `clue_earnings_events: true` | ✅ |
| 内部人集群（SEC Form 4） | `clue_insider_clusters: true` | ✅ |
| 事件驱动标的清单 | `clue_event_symbols: true` | ✅ |
| 盘前板块峰群 | `clue_peer_surge: true` | ✅ |
| 板块轮动/异动佐证 | 市场佐证段（无独立开关） | ✅ |
| 人工线索 | manual_clue | ✅ |

DA 侧另有独立分析 + 质量闸（`da_gate_decisions.jsonl`）。**"没有充分利用事件+板块轮动"在源接入层面不成立**——问题在下面三层。

### 2.2 失灵层 A：区分度坍缩 — 源再多，出口是糊的

07-23 实证：15 候选 score = 13×7.0 + 2×6.0，conf 全 0.35（score-discrimination DEB）。**输入端 7 类信息源，输出端两档分数** → 信息在 LLM 排序层被压扁。给这样的漏斗再加"各种榜单"，等于给糊掉的镜头换更贵的灯。

### 2.3 失灵层 B：源级无淘汰 — 负 alpha 论据持续在用

`factor_ic_latest.json`（论据级 IC 台账，已存在！）实测：

| 论据因子 | n | IC | avg_alpha |
|---|---|---|---|
| valuation_expensive | 194 | 0.20 | **-0.57%** |
| insider_bearish | 212 | 0.15 | **-0.41%** |
| earnings_beat | 222 | 0.12 | **-0.22%** |
| sentiment_crowded | 191 | 0.11 | **-0.54%** |
| news_positive | 309 | 0.03 | **-0.38%** |

主流叙事论据的超额收益**全线为负**（DA gate 的 reasons 里天天在提示"使用了历史超额为负的论据"），但生成端没有淘汰机制，这些论据继续每天进 prompt。**"更智能"的正确形态不是加源，是给每个源上 IC 记分牌 + 淘汰赛**：负 alpha 论据从 prompt 降权/剔除，正 alpha 源加权。基建已有（ic_tracker + evidence_ref），缺的只是"回灌到 prompt"这半环。

### 2.4 失灵层 C：信息用错了层 — 选票用了，定仓/择向/择时没用

三个"已有数据无人消费"的断点：

1. **conf → 仓位**：`confidence_sizing_enabled: false`（config 实查）。而 conf 分桶数据显示右尾差异显著（高 conf top1 +$247 vs 低 conf +$102，rootcause DEB §二.5）。
2. **conf → 胜率校准**：`confidence_winrate_map_*.json` 每日在产出，但全仓库只有生成器自己引用，无消费方。且映射显示 conf 与胜率**非单调**（0.5-0.7 桶 WR 24.8% < 0-0.3 桶 47.1%，全策略口径需 PLAYBOOK 复核）——校准断裂本身就是"不智能"的量化证据。
3. **regime → 方向敞口**：盘前 07:37 快照定全天调性（crash-day DEB 缺陷 A）；regime 落库昨日已补全（三门第④项），但**积累 2~4 周前无法条件化**。

### 2.5 感知②的本质重述

> 盘前的短板不是"源不够"，是**漏斗的三个下游层失灵**：排序层区分度坍缩（A）、源层无 IC 淘汰（B）、消费层信息只用于选票不用于定仓/择向（C）。先修 A/B/C 再谈加源；顺序反了会放大噪声——负 alpha 论据台账就是"加源不淘汰"的前车之鉴。

## 三、多角度补漏：用户两点感知之外，被遗漏的更深层问题（按严重度排序）

### 3.1 【最被低估】执行成本层从未量化 — 滑点直接吃掉边缘

- 触发即 `OrderType.MARKET` 市价全仓（`playbook_service.py:979`）。
- 系统的生死线是 MFE 0.5%——**市价单滑点估 0.1~0.3%，等于边缘的 20~60% 在下单瞬间蒸发**。
- 现有数据无法分离"信号无边缘"与"执行滑点"各占多少（rootcause DEB 诚实弱点 4）。
- **对策（廉价可测）**：触发后限价单（entry±0.05% limit，30s 未成交撤单转弃）shadow 对照——可能是全系统性价比最高的单项改动。若滑点占了无边缘的一半，那么"入场无边缘"的诊断本身要部分改写。

### 3.2 【结构性】44% WR × RR≈1:1 = 数学上的负期望

`rr_ratio: 1.0`、SL 2%、TP 大多被 RR<1.5 门吞掉、日内 4h 窗限制利润伸展。这个结构下**入场胜率不到 55% 就必亏**，退出工程只能止血不能造血。两条根本出路（互斥于"继续磨日内"）：
- **X1 降频高信念**（rootcause DEB 已提）：只做 conf≥0.85，每周 2~3 笔，右尾厚、频率低；
- **cohort B 隔夜重评估**：`overnight_hold_enabled: false` 是一刀切关的。让 RR 伸展需要时间维度；隔夜风险可用 gap-stop（已有 OVERNIGHT_GAP_STOP 规则闲置）+ 小仓位控制。
两者都是"改变收益分布形态"而非"提高预测力"——**在无边缘被反复证实的前提下，改分布形态比改预测更可行**。

### 3.3 【行为性】入场 100% 聚集在开盘 09:35~09:52 — 最坏的 17 分钟

07-23 全部 19 笔在开盘 22 分钟内入场。开盘窗是价差最宽、假突破最密、逆向选择最强的时段；量能门还专门给了开盘 15min 豁免（`intraday_vol_gate_grace_min: 15`）——**等于在数据最不可靠的窗口放行了最多的单**。时区债（entry_time 双轨）修复前无法做完整时段分析，但"开盘聚集"本身已可见。对策：入场延迟窗（09:50 前只观察不触发）shadow 一档。

### 3.4 【地基】数据双轨与观测债清单

- 遥测 `date` 用 CST、trade_records 用 ET → 跨表 join 系统性错位（本文核验 07-24 遥测时再次踩到）；
- `entry_time` 时区混杂（P2 未修）→ 时段分析全盲；
- fwd_return 回填 T+1 滞后 → 选股质量评价永远迟一天；
- 7 月 atr_pct 覆盖 55/109（新指令已 100%）。
这些债不修，任何"更智能"的策略都在脏数据上标定。

### 3.5 【纪律】多重检验风险

54 笔/周的样本量下，"找到看起来有效的新指标"的成本≈0，"确认它真有效"的成本≈2~4 周。所有新信号必须：预注册阈值 → shadow → 按精确率/召回率裁决。本项目已两次栽在小样本完美分离上（第 5 轮教训 ×2）。

## 五、诚实弱点

1. **昨夜三门（stall/连败/低ATR）还没经过一个真实交易日**——今晚（07-24 ET）才是首夜。本文所有"退出侧已修"的表述在明早验证前都是预期而非事实。
2. **150min/0.5% 阈值是 in-sample**：若今晚是强趋势修复日，stall-exit 可能砍掉个别晚发动的单。测量方案已埋（shadow 并行），但首夜风险真实存在。
3. **滑点主张（S1）目前是估算**：0.1~0.3% 来自经验值而非本系统 tick 实测；限价单 shadow 的第一目的就是把这个数测出来。
4. **conf 非单调证据是全策略口径**：confidence_winrate_map 未按 source_type 过滤，PLAYBOOK 子集可能不同（跨策略污染教训），S4 执行前必须重算。
5. **"无边缘"结论依赖 07-23 的 fwd 回填**：T+3（07-28）后需复核，若崩盘日 fwd 大面积转正，L1 诊断部分改写、S1 的权重进一步上升。
6. **用户指标缩写未能识别**（cmq/sss/gdian/cnm/mfff）：若实有所指，§1.2 的"指标已证伪"覆盖面需重核。

### 7.3 受邀攻击点 1 — S1 滑点：**方向对，但期望值不确定 5~10 倍，且"改写无边缘诊断"主张前置过度**

- **关键**：若实测滑点仅 0.03~0.05%，则 S1 节省有限（$15~30/周），**且不能改写"无边缘"诊断**——作者把 S1 排在行动序列第 1 并称"改动最小杠杆最大"，这一排序的成立**高度依赖滑点上限为真**。

### 7.4 受邀攻击点 2 — S3 源级 IC 淘汰：**最重要攻击 — 淘汰判据被切换，会误杀全台账最强排序信号**

- **判据不一致**：`factor_ic_backfill.py:166` 生成器的 verdict 列**用 IC 判定**（ic>0.05=✅正）；而本文 §2.3 表格与 S3 却**用 avg_alpha 作淘汰证据**。同一台账、两套判据。
- **按生成器自己的 IC 判据，5 个拟淘汰论据有 4 个 PASS**：valuation_expensive IC=0.20（**全台账最高**）、insider_bearish 0.15、earnings_beat 0.12、sentiment_crowded 0.11 全部 >0.05=✅；仅 news_positive 0.03 落入⚪。**按 alpha 全负要删、按 IC 多数达标要留——结论完全取决于选哪把尺。**
- **IC 与 alpha 度量的是两样东西**（`factor_ic_backfill.py` 实读）：IC=Spearman（信号强度， 方向调整后前瞻收益）＝**排序力**；avg_alpha=方向调整后剥 beta 超额＝**均值方向盈亏**。台账自带反例 **insider_net_sell：IC=-0.15（负）但 alpha=+1.36%、WR=71.7%、trade_n=7**——若按 IC 淘汰会误杀最佳绩效者，若按 alpha 淘汰会保留。**判据选择直接翻转决策。**
- **负 alpha 更可能是"看空论据被做多方向错用"而非"信号无价值"**：valuation_expensive（估值贵，天然看空）在全 LONG 系统里被做多 → 方向调整后 -0.57% 恰说明"贵"的股票随后下跌、信号本身是对的、错在方向。IC=0.20 佐证其排序力是真的。**正确修法是反向使用（当 avoid/short 过滤器，把 -0.57% 翻成 +0.57%），不是从 prompt 删除**——删除等于扔掉全台账最好的排序信号。
- **约束建议（S3 重写为三判据）**：① 区分 IC（排序力）与 alpha（方向盈亏），两者并列上记分牌；② 设**最低 trade_n 门槛**（如 ≥20 笔）才允许下淘汰结论（insider_net_sell 仅 7 笔不可判）；③ 先诊断"方向错用"再决定动作——方向错用→反转/设为 avoid 过滤；真无 IC 又无 alpha→才剔除。**S3 原案（单一 alpha 降权/剔除）应否决，改为方向感知的三分类处置。**

### 7.5 受邀攻击点 3 — X2 隔夜：**gap-stop 不构成风险边界，隔夜需独立更小的风险预算**

- 作者称"隔夜风险可用 gap-stop + 小仓位控制"。**辩论方纠正：OVERNIGHT_GAP_STOP（pipeline.py:4676，阈值 3%）是"跳空已发生后离场"，不是"跳空防护"**——隔夜跳空（个股财报/新闻可达 5~20%）无法在缺口内止损，只能在缺口价成交，损失在跳空瞬间已锁定。**3% 的 gap-stop 挡不住 -10% 的跳空，它只是在 -10% 时帮你认赔，风险预算是 -10% 不是 -3%。**
- 日内 SL=2% 与隔夜潜在缺口 5~20% 相差一个量级，**隔夜仓位的真实单笔风险是日内的数倍**。用小仓位对冲是对的，但把 gap-stop 当风险控制是误导。
- **约束建议（X2 前置）**：① 隔夜仓**独立、更小的风险预算**——按"可容忍 $ 亏损 ÷ 假设 -15% 缺口"反推仓位上限，而非沿用日内 sizing；② **财报日历硬排除**（不在财报夜持仓，利用已有 `clue_earnings_events` 数据）；③ gap-stop 仅作兜底记录，**不得计入风险边界**。满足这三条前，X2 不应进 live。
