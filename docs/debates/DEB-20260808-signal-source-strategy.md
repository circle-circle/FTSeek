## 一、核心主张（第一性原理）

**胜负不由"选股能力"决定，由 4 个已验证维度决定：时间、方向、退出、波动。**

7-8 月数据反复证明：LLM 选股 score 无区分度（7.0 分 WR 29% vs 6.0 分 WR 60%），
但时间（9点档 vs 10点后）、方向（SHORT追涨日 vs LONG回调日）、退出（MFE_STALL
0% WR 29笔死扛）、波动（ATR 2.5-6% 赢家区 vs >8% 失血区）4 个维度有清晰预测力。

**方案本质**: 把已验证的 4 个维度做成不可绕过的量化制度，LLM 从"决定者"降级为
"假设提出者"（定性方向+故事），量化规则做验证筛选。所有组件都有 7-8 月数据背书。

```
标的池(什么进) → 信号(什么方向) → 入场(何时进) → 退出(何时走) → 闭环(怎么进化)
  波动适配       方向×动量一致      时间过滤        纪律离场         OOS校准
```

## 二、主张拆解（可检验化）

1. **score 无区分度**（7.0 WR29% vs 6.0 WR60%）→ score 重构后必须与胜率正相关
2. **方向×动量一致性是唯一有效方向维度**（SHORT禁追涨 +$172/月 价值, LONG回调日 +$103）
3. **时段过滤是最大的单维改善**（8月窗外 8笔 +$28 vs 窗内 35笔 -$250）
4. **退出纪律是亏损的止血阀**（MFE_STALL 29笔 0% WR -$1,229 全历史）
5. **波动率是标的适配的唯一硬标尺**（ATR 2.5-6% 赢家区 vs MU 9.7% 失败池）
6. **LLM 降级为假设提出者不损失 alpha**（LLM 的 regime 识别/事件解读保留在定性层）

## 四、标的池筛选设计（双层漏斗）

### 4.1 第一层: 硬性市场适配 (每标的静态)

| 规则 | 阈值 | 依据 |
|---|---|---|
| ATR% 尾部剔除 | **>8% 强制降权** (仅此一条, 无正向选区) | 8月 >8% 区 3标的 -$112; 2.5-6% 区 38笔 -$123 同为负 (Qoder §12.2 修正: 无赢家区) |
| 流动性 | 日均成交额 > $500M | 紧SL 下 0.1% 滑点占 13% (Qoder §14.2) |
| 价格 | > $20 (低價股滑点占比高) | ALAB/RSSS 类仙股波动吞噬收益 |
| 波动变化 | ATR 周环比 < 2× (防财报/事件跳变) | 财报日 gap 打穿 SL |

### 4.2 第二层: 动态质量 (滚动 2 周)

- **净期望为正** 才保留在活跃池 (每标的 2 周滑动净 PnL / 笔数)
- 连续 2 周负期望 → 降级观察池; ⚠️ **n<15 不触发降级** (Qoder §12.5: 2周样本仅3-8笔
  = 噪声分类器, 45% WR 硬币连出 2 周负期望概率不低) — 降级仅用于"DA 省成本", 不得阻断执行
- 观察池标的仍可被 UE 扫描发现, 但 DA 不主动分析 (省 LLM 成本)

### 4.3 双向供给 (LONG 池 / SHORT 池分离)

- **LONG 池**: 趋势确认 + 回调日过滤 (chg -5%~0)
- **SHORT 池**: 仅 risk_off 环境开放 (SPY < MA20 或 VIX 抬升); risk_on 禁 SHORT 供给
  (8/5 三连亏 MU/MSFT/PLTR 全是 risk_on 轧空)
- 池子来源: watchlist_us.json 静态池 + UE 扫描动态池 + DA 候选池 三源合并去重

### 4.4 池子更新频率

- 静态层: 周度 (周末盘后)
- 动态层: 每日盘后 (滚动 2 周窗口)
- 事件触发: 财报前 2 日临时降权 (gap 风险)

## 十、辩论点（供对抗性攻击）

1. **ATR 门槛会过滤掉大赢家吗**: NVDA 3.65% 在窗口 ✓, 但 MU 类高波动标的在趋势日
   (8/3 后) 是否有被错杀的 alpha? ATR>8% 一刀切降权是否过粗?
2. **流动性 $500M 阈值**的依据: 滑点估计是模型假设, 有无实测支撑? 紧SL 下滑点占比
   13% 是 Qoder 的估算, 低流动性标的的实际滑点分布?
3. **"连续 2 周负期望降权"是否小样本过拟合** (协议反模式: n=5 天数据剔除标的)?
   TSM 5笔3胜仍净亏 — 是 9点档+死扛的产物 (已修) 而非标的质量问题? 剔除是否过早?
4. **risk_on 禁 SHORT 是否过度**: 8/5 三连亏是特例还是规律? 7 月 SHORT +$25.8K (旧管线)
   是 risk_off 环境? 若 8 月后半月转弱, 禁 SHORT 会错过系统性做空机会?
5. **score 重构依赖挑战者数据**: 挑战者强制表态 2 周后若 score 仍无区分度 (7.0 仍普遍),
   门禁接入 score 是否无意义? 备选方案 (score 不作为门禁, 只作为仓位乘数)?
6. **LLM 降级为"假设提出者"是否损失 alpha**: LLM 的 regime 识别 (DEB-20260714 哲学:
   DA alpha 在 regime 识别+退出) 是否被"量化规则"完全替代? 定性层与量化层的边界?
7. **标的池静态层周度更新 vs 事件驱动**: 财报前 2 日降权的实现成本? 是否漏掉
   "财报后跳空"的 alpha (业绩超预期的跳空高开是否该追)?

## 十四、策略级深度复查 (Qoder, 2026-08-09, 策略专家视角)

声明: 本节不复核数字 (§1-§12 已收敛), 审查的是**策略架构本身**——
当前这套系统在赌什么、结构性约束在哪、什么该停。

### 14.1 策略画像与中心结构事实

事件驱动 LLM 选股 + 日内动量 + 紧退出, ~$5.5K/笔 × 6-12 笔/日 on $97K。
**费用拖累 ≈ $34/日 ≈ 年化 8.4%** — 策略必须先跑赢这个门槛才谈得上收益。
这是全系统的第一结构事实, 一切 alpha 讨论都要先过它。

### 14.2 五个架构级问题 (按严重度)

**① alpha 本体未被证明 (最致命)**
ADF 周检 (8/9): 毛利均值 t=−0.10, 统计上等于零。这意味着过去一个月所有的
退出工程优化, 都是在打磨一个**费前零期望的内核**。供给端有没有 edge 这个问题
不回答, 一切参数调整都是在泰坦尼克上排椅子。
→ 建议: 8/10 起两周, 唯一重要的度量是 **源头×方向×regime 的毛利记分卡**
(rolling 20 日, 周度 go/no-go)。任何单元格到 8 月底毛利仍不显著为正 →
诚实结论是该层供给无 edge, 应停供而非继续调参。

**② 实验饥饿 (方法论约束)**
6-8 笔/日 × 同时在跑 ≥5 个实验 (VWAP A/B / 再入场 / 死信号 OOS / β OOS / 24 影子),
每臂 n≥30 需一周+, 而系统每周都在改 — **改变速度超过测量速度**, 必然导致
归因混乱 (本周"同一天三套配置"已是实例)。我自己的再入场也在加剧这个饥饿,
如实声明。
→ 建议: 立**变更预算** — 每两周最多一个 A/B 变量, 其余一律 shadow;
新机制排期表公开, 插队的必须先说清挤掉了谁的样本。

**③ 退出机制过度拥挤**
现役 7 个退出机制 (SL/保本/trailing/死信号/MFE停滞/TIME_EXIT/PRE_CLOSE) +
profit_override。先触发者独占交易, 后触发者永远攒不到数据 — 机制间互相
"饿测"。且每加一个退出, 其余机制的历史归因都漂移一次。
→ 建议: OOS 两周后按**触发率×净贡献**做一次退出机制审计, 合并/退役冗余者
(候选: MFE_STALL 并入死信号, TIME_EXIT 评估是否已被 PRE_CLOSE 覆盖)。

**④ 组合层风险缺位**
禁触窗把成交压缩到 10:00-10:05 一批 + DA 98% 做多 → 全部仓位是**同一时刻的
同向 beta 暴露**。10:05 的一次市场跳水打全部。现有防护只有日名义上限,
无同时持仓方向集中度控制。
→ 建议: 同时同向持仓 ≤3 或 10:00 批次分两批进场 (10:00/10:15 各半) —
后者顺带缓解 §六 10:00-10:15 最差桶 (−12.51/笔, 我的复算) 的暴露。

**⑤ 方向供给的 regime 盲 (唯一跨月稳健模式未被制度化)**
7 月 SHORT 大赚 / 8 月 SHORT 全亏 — 全部方向性证据里最稳健的模式就是
regime 依赖, 而生产环境没有方向×regime 门。§4.3 提了 (risk_on 禁 SHORT 供给)
但未落地。
→ 建议: 先用 VIX 水平 + SPY/MA20 做一个**供给侧 regime 标签**落影子
(不改行为), 2 周后若方向×regime 交互显著再硬门。这比任何微观过滤器
的期望值都高。

### 14.3 什么不该再动

- 入场侧 13 门 + 禁触窗 + admission: **冻结**。连续四个盘中优化思路
  (Step1/E2/β过紧/开盘证据分) 都被证明无边际, 入场侧已到局部最优, 再加闸
  是过拟合噪声
- score/confidence 重构: 已双证无区分度, 别再投入 (等挑战者 2 周数据)
- 新增 shadow: 24 个数据流已超测量能力, 新增影子前先退役一个旧的

### 14.4 一句话总结

**这个系统现在最缺的不是更多规则, 而是更少的同时变化 + 一次对"供给端有没有
真 edge"的诚实审判。** 退出工程已经做到测量能力的极限, 接下来两周的价值
全部在测量纪律, 不在新机制。

## 十五、Prompt ↔ 指令 ↔ 复盘 联动闭环设计 (2026-08-09, Hermes 追加)

### 14.1 现状联动图 (已存在的环节)

```
复盘层 ──→ ① strategy_memory ──→ trade_experience 文本 ──→ prompt 注入 (LLM 自行解读)
复盘层 ──→ ② condition_expectancy.json ──→ 条件黑名单文本 ──→ prompt 注入 (软约束) ✓ 已结构化
复盘层 ──→ ③ claim IC ──→ 论据有效性反馈 ──→ 已停用 (7/18, 跨 regime 污染)
复盘层 ──→ ④ feedback_learner ──→ 用户反馈建议 ──→ 未自动回注 (人工决策)
生成层 ──→ 19 字段 JSON ──→ signal_snapshots ──→ bridge ──→ playbook_instructions (只消费部分字段)
```

### 14.2 断裂点诊断

| # | 断裂 | 后果 |
|---|---|---|
| 🔴 1 | trade_experience 是自由文本 (LLM 自行解读) | 复盘结论强度不可控 — 过度回应 (个股全亏→SKIP) 或忽略 (上下文过长) |
| 🔴 2 | **score rubric 无回注** — 复盘发现 "7.0分 WR29%" 无法写回 prompt 评分定义 | score 永远是"分析师信心", 复盘的区分度发现无法闭环修正生成层 |
| 🟠 3 | claim_type IC 停用 (7/18 跨 regime) — 但 8 月已是纯 DA 时代 | 论据类型预测力无反馈 |
| 🟠 4 | 输出 19 字段 vs 消费端对不齐 — 复盘只归因 exit_reason/时段/方向 | 复盘看不到 "哪个 score 档/哪类论据赚钱" — 归因与生成维度脱节 |
| 🟡 5 | feedback_learner 建议不自动回注 | 用户反馈停留在人工环节 |

### 14.3 优化后的闭环 (4 条结构化回注通道)

```
┌─ 生成层: prompt + rubric(score定义) + 分析师/挑战者
│    ↓ score/direction/claim_type/execution_plan
├─ 指令层: signal_snapshots → bridge → playbook_instructions
│    ↓ 触发/执行
├─ 执行层: 入场(时段×方向×动量) → 退出(SL/死信号/trailing)
│    ↓ trade_records (exit_reason/pnl_net/mfe/mae)
├─ 复盘层: post_market_audit → 归因 (score档×WR / claim_type×alpha / 退出×期望)
│    ↓ 结构化反馈 (4 通道)
└─ 反馈层 → 回生成层 (下一轮)
```

**通道① score rubric 校准闭环 (P1)**
- prompt 加显式 rubric: `7.0=挑战者完全确认+催化剂+数据完整; 6.0=有保留(挑战者质疑); ≤6 证据缺陷`
- 复盘层每 2 周算 score 档 × WR/期望 → 自动收紧/放宽 rubric 文本
- score 从"信心"变"可校准的证据强度" — 复盘数据直接改写生成规则

**通道② claim_type IC 按 DA regime 重算 (P2)**
- 7/18 停用是跨 regime; DA 时代已 2 个月 (n≈200+), 按 DA 子集重算
- 输出: `product_catalyst α=+0.8% (n=45) 有效✅ / valuation_cheap α=-0.3% 无效⚠️`
- 复用 _load_claim_ic_for_prompt 函数体, 改 regime 过滤后启用

**通道③ 条件黑名单 (已启用 ✓ 保留)**
- condition_expectancy 每日更新注入, 软约束

**通道④ strategy_memory pattern 标签化 (P3)**
- 文本 hint → pattern 标签: `LONG+回调日(chg-2%~0)+ATR 3-4% → WIN (n=12, WR 67%)`
- prompt 按当前标的 setup 匹配注入 — 从"看文本自己判断"变"预设 pattern 先验"

**通道⑤ 输出精简 + 归因对齐 (P2)**
- 19 字段 → 消费端反推: 保留 score/direction/bull/bear/execution_plan/risks/data_quality_note
- rating/confidence/constraints/causal_chain/key_levels 标记弃用
- 复盘归因表增加 score 档列 + claim_type 列

### 14.4 优先级路线图

| 优先级 | 动作 | 依赖 | 预期 |
|---|---|---|---|
| P1 | prompt 加 score rubric + 复盘 2 周校准 | 挑战者强制表态数据 (采集中) | score 有区分度 + 可持续校准 |
| P2 | claim IC 按 DA regime 重算回注 | 8 月 DA n≈200 已够 | 论据权重可学习 |
| P2 | 输出精简 + 归因表加 score/claim 列 | 无 | 生成↔复盘维度对齐 |
| P3 | strategy_memory pattern 标签化 | P1/P2 后 | 经验注入结构化 |
| 持续 | condition_expectancy 黑名单 | 已启用 | 条件负期望规避 |

### 14.5 辩论点 (供对抗性攻击)

1. **score rubric 会否导致"评分通胀/通缩"**: LLM 为了满足 rubric 的"挑战者确认"条件而
   让挑战者"配合" (挑战者确认率上升但确认无信息量)? 校准闭环的反馈延迟 (2 周) 是否太长?
2. **复盘校准闭环是否过拟合风险**: 每 2 周调 rubric, 样本 30-50 笔, 噪声波动可能
   导致 rubric 反复横跳 (本周收紧下周放宽)? 需要最小样本阈值 (n≥30) + 双窗口确认?
3. **claim IC 按 DA regime 重算**: 8 月 n≈200 够吗? 论据类型粒度 (10 类) × regime 是否
   过度切分? 与小样本的平衡?
4. **输出精简**: 删 rating/confidence/constraints 等字段, 是否丢失未来可用的信息
   (如 constraints 用于下游风险检查)? 精简 vs 完整性的边界?
5. **pattern 标签化 (通道④)**: pattern 标签是否变成"新的 score" (同样无区分度)?
   WIN pattern 的 n=12 样本是否又是噪声分类器?
6. **闭环的循环依赖**: 复盘校准 rubric → rubric 改变生成 → 生成改变交易 → 交易改变
   复盘 — 系统是否可能振荡 (每次校准过度反应)? 需要阻尼机制?
7. **人工 vs 自动**: 校准闭环全自动 (每 2 周自动改 prompt) 还是半自动 (出建议人工审批)?
   基线纪律 (post-blackout) 对 prompt 改动是否同样适用?

## 十六、Qoder 分析 §十五 + Prompt 优化建议 (2026-08-09)

### 16.1 设计评价: 断裂点诊断准确, 但两个通道有问题

**断裂点诊断 (§15 表) 全盘成立** — trade_experience 自由文本注入不可控、
score rubric 无回注、归因维度与生成维度脱节, 都是真问题。以下按通道给意见:

| 通道 | 判定 | 理由 |
|---|---|---|
| ① score rubric 校准闭环 | ⚠️ **只许一次性澄清, 不许自动校准** | 见 16.2 |
| ② claim IC 按 DA 重算 | ⚠️ **前提有误 + 概念混淆** | 见 16.3 |
| ③ 条件黑名单 | ✅ 保留 | 已在运行 |
| ④ pattern 标签化 | ⚠️ n≥30 + 分半一致性才可注入, 否则就是"新 score" (辩论点5 自中) | |
| ⑤ 输出精简+归因对齐 | ✅ 先做 | 零风险, 对齐生成↔复盘维度 |

### 16.2 🔴 通道①与本 DEB 自己的架构原则冲突

§十三 已采纳 "LLM 降级 + 制度优先"。通道①却让 score 通过 rubric 校准**重新变成量化门** —
方向打架。且数据现状: 7.0 分 WR29% vs 6.0 分 WR60% = 3/5 vs 6/21, Fisher p≈0.3,
**score 当前无任何区分度证据**。用 2 周 n=30-50 的数据自动改写 rubric = 拿噪声校准文本,
振荡风险 (辩论点6) 不是可能而是必然。

**正确姿势**: rubric 一次性写清定义 (7.0=挑战者完全确认+催化剂+数据完整) 没问题 —
但此后 **score 只观测不进门**, 直到挑战者数据 n≥100 且分档 WR 单调再议。
校准闭环的预注册判据先写好, 不见数据不启动。这也回答辩论点7: **半自动** (出建议,
人工批), 且 prompt 改动适用与代码同级的基线纪律。

### 16.3 🔴 通道② 两处事实修正

1. **"复用 `_load_claim_ic_for_prompt` 函数体" — 该函数已不在活体代码**
   (grep app/ 无定义, 仅 scripts/archive 引用)。7/18 停用时已移除, 实际是重写而非复用,
   工作量估计要相应上调。
2. **"按 DA regime 重算"混淆了两个 regime**: 7/18 停用的根因是**市场 regime 混杂污染**
   (7月弱市 vs 8月反弹), 而 DA 时代内部同样跨市场 regime — 按"DA 时代"过滤解决不了
   原始病因。正确切分是 **市场 regime 标签** (VIX/SPY MA20) × claim_type, 不是生成管线时代。
   这又回到 §14.2⑤ 的 regime 标签影子 — 它是通道②的真正前置。

### 16.4 现在就该做的 prompt 调整 (证据充分, 低成本)

与闭环机制无关, 直接改生成端文本 (DA/UE prompt, 标记 prompt_version 递增):

1. **结构性约束前置** (省 token + 省下游拦截): 明确写入 "SL 距入场 2-5% (>6% 下游硬拦);
   不接日跌>5% 的飞刀 LONG; 入场区间贴近支撑/VWAP 而非追延伸"。这些在生成时刻可知,
   每条被 admission 拦下的指令都是对供给的浪费 — 让 LLM 别产注定被拦的单。
2. **LONG 回调日优先写入 UE prompt**: 8月 LONG×chg<−2% +$103 + 我的 post-blackout 复算
   (≥10:00 逆势 LONG +3.21/笔 vs 顺势 −12.22) 双证据。UE v2.3 已有板块级联, 在其后加
   一条 "回调企稳标的优先于新高追涨标的" 即可。
3. **prompt_version 递增纪律**: 任何 prompt 改动 bump version (config 已有该机制),
   按版本号分桶归因 — 这是 prompt 的 A/B, 零新基建。

### 16.5 明确不做

- ❌ 自动 rubric 校准闭环 (16.2)
- ❌ 每 2 周自动改 prompt (振荡器; 半自动+预注册判据)
- ❌ pattern 标签 n<30 注入 (噪声分类器)
- ❌ claim IC 按"管线时代"重算 (16.3 概念混淆)

### 16.6 一句话

§十五 的闭环图是对的, 但四个回注通道里只有"输出对齐"现在就该做;
其余要么等数据 (①④), 要么先修正前提 (②)。**prompt 优化的主战场不在校准机制,
在把已验证的结构性约束写进生成端** — 16.4 三条今天就能做。
