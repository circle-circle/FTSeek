## 一、历史逻辑 (为什么有这道题 — 通俗版)

topup 是"补量工": 主信号 (DA/UE) 每天只产 6-10 笔, 攒不够退出侧学习所需的样本,
于是在固定池 (24 只) 上用纯技术指标 (动量+回调) 做确定性补量。它的投票人
TechnicalFallbackAdapter **故意不用 LLM** — 便宜、稳定、可复现。

代价是:**这个投票人是个"只看 K 线的盲人"**。它看见 RSI 32 会说"深度回调, 该买",
但它看不见这只票今早刚发 8-K 暴雷 — RSI 32 可能不是回调, 是坠崖的第一段。
07-28 根因分析时作者就标注了此盲区 (F2); 07-29 F1 修复死路径后, 供给即将恢复,
盲区从"无产出的理论问题"变成"有产出后的质量风险"。

**修法不是给它配眼镜直接上岗, 而是先让它"试戴"**: veto 判断照常做、照常记录,
但**不拦截** (record-only shadow) — 攒若干周后对比"会被 veto 的笔" vs "正常笔"的结局,
数据说了算再决定是否实弹化。这是验证期"一切新退出/信号规则先走 shadow"纪律的同构应用。

## 三、方案

**F2a (前提, 修尺子)**: 
1. `news_sentiment` 退化归因 — 是没接线还是上游恒 0; 若修不好, veto 改用标题级规则/LLM 分类 (llm_cache 已有缓存设施, 成本可控);
2. 明确 veto 可用的新闻新鲜度边界: 盘前批次标题对盘前 vote 窗有效; 盘中窗是否接受 N 小时陈旧标题, 须作为显式口径写入 shadow 记录 (新旧分桶, 防口径拼接)。

**F2b (主体, record-only shadow)**:
在 topup vote 通过 (将生成指令) 时, 追加 veto 检查并落 `data/topup_veto_shadow.jsonl`:
- **方向敏感 veto**: LONG 遇近 24h 负面催化 (负面标题分类/当日 8-K 负面/财报当日) → would_veto=True; SHORT 遇近 24h 正面催化 → would_veto=True (负面新闻对 SHORT 是确认不是 veto — 方向语义必须显式);
- **不拦截**: 指令照常生成成交, shadow 只记录 "若实弹会被拦" 及证据 (标题/时间/分类);
- **结局回填**: 复用 decision_id 串联 (路径湖设施), 事后回填该笔 pnl/捕获率/路径特征;
- **分流台账**: vote 未通过的笔也记录 veto 检查结果 (对照组 — "veto 会拦的"与"技术本就不放行"是否同群)。

**明确不做**: 不实弹拦截 (shadow 先行); 不改 vote 打分; 不新建盘中新闻流 (若 F2a 证明盘中时效是硬伤, 则 veto 只覆盖盘前窗, 盘中窗如实标注 "veto 数据不可得" 而非硬凑)。

## 四、与既有原则的关系

- **供给诚实原则** (07-29 讨论): veto 实弹化会减少供给 — 但减的是"技术形态与新闻打架"的笔,
  属质量过滤非凑量, 方向与 W2 原则一致 (宁可少, 不可烂); 但正因为减供给, 必须 shadow 数据证明
  "被拦的笔确实更差" 才能实弹 — 否则就是又一次拍脑袋砍信号。
- **一次一变量**: F1 刚上线 3 日验收期内, F2b shadow 是 record-only 不改信号分布, 可并行;
  F2b 实弹化 (若未来裁决通过) 须等 F1 验收关闭后单独排队。

## 七、诚实边界 (作者自陈)

1. **样本量风险真实**: topup F1 后供给速率未知, veto 事件是其子集 — n≥30 可能需 4-8 周, 大概率赶不上 08-07 裁决点, 只服务终裁后时代; 若用户认为赶不上终裁就不值得做, 现在叫停是合法选项。
2. **标题≠催化**: 新闻标题分类是钝器, 错分率会稀释 veto 效果; shadow 数据若显示被拦队列与对照无差异, 应果断关闭而非继续调参 (防"为存在找理由")。
3. **F2a 可能翻出旧账**: sentiment 退化若牵出上游采集问题, 范围以"定性+修或弃"为限, 不顺手重构新闻管线。
