## 一、问题界定

全系统唯一稳定正引擎是 `SL_TRAIL_LOCK`（锁利退出），但该优势目前只作用于**初始仓位**——
锁利武装态出现后，系统没有任何"放大已验证赢家"的机制。本 DEB 提问：
**仓位进入 trail-lock 武装态后，追加 40% 金字塔仓能否在扣费后增厚净收益？**

本 DEB 只立影子设计与预注册判据，**不实现、不上 sim、不改任何行为**。

## 四、影子设计（裁决后落地，record-only）

1. **触发**：持仓 `effective_sl` 首次锁上净保本线（trail-lock 武装态，即 9/17 语义）。
2. **虚拟加仓**：qty = 母仓 qty × **40%**（预注册单值，禁网格购物）；成交价 = arm 时刻价
   ×（1 ± 0.10% 滑点垫，方向感知）；费用按 0.15% 往返线计。
3. **虚拟腿退出**：独立 trail（同 0.8/1.0 参数，从加仓价起算）；EOD 兜底平仓。
   母仓先出时虚拟腿**继续独立持有**至自身 trail/EOD。
4. **台账**：`data/shadow/trail_lock_pyramid.jsonl`（每武装事件一行，含母仓/虚拟腿双侧
   净额、MFE、回吐、config_version）；nightly 结算产物 latest.json。
5. **分层强制**：一切读数按 config_version（9/17 前/后）分层报告；跨层合计只作背景，
   不得进判据。

## 九、作者复查追加（2026-09-28，详见 DEB-20260928 §十五；判据原文未动）

- **数字 CONFIRMED**：58 笔 +$3,420.77、日内 48/+$2,592.67、隔夜 10/+$828.10、pre-9/17 40 笔 +$2,738.27/$68.46、post 18 笔 +$682.50/$37.92 —— 逐位吻合。
- **攒样可行性 CONFIRMED**：post-9/17 出场口径 18 笔/8 天 = **2.25/日** ⇒ 判据 n≥40 需 **18 天**（≈2.5 周），死线 12/31 内宽裕可达。这是三份新案中唯一攒样速率无风险的。
- **🟡 §15.6 可执行性缺口（建议落地前补）**：五周窗名义额均 **$5,474.84**，当前净值 $98,777.71、`max_position_pct=6.0%` ⇒ 单名上限 **$5,926.66**，均名义已占 **5.54%（帽内余量仅 0.46pp）**；**+40% ⇒ 7.76% 破帽，实测 196/207 = 95% 的笔加仓后直接撞单名帽**。R2 只写"backstop 触发面变大（中风险）"未量化此条 ⇒ 影子若按 40% 全额成交结算，测的是**真实系统加不进去的方案**。建议增加强制列 `帽内可加比例 = min(40%, (帽额−现有名义)/现有名义)`，判据只用帽内可行部分结算。
- **🟡 口径标注**：底牌2 的均净 +1.32%/+0.76% 实为 **`pnl_pct` 列（毛口径）**；同表 +$68.46/+$37.92 是**净额**。净/名义口径实为 pre **+1.229%** / post **+0.679%**（差 0.092pp = 费用）。两口径都对，建议标注避免毛净混排误读（本文未改原文，留 Codex 定）。
- **治理**：本 DEB 为 shadow ⇒ 不占变更预算（权威条款=DEB-20260808 每两周 1 个 A/B 变量）；但若裁过转 sim = 占额度，且需回答"插队挤掉谁的样本"（现役 27 个影子产物、5 个 KEEP_SAMPLING）。
