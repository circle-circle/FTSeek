## 零、立案人自我修正 (口径事故, 先于一切结论)

立案人 8/16 首轮分析向用户报告"未触发 BUY 反事实 +4.40%, IS +1.83 / OOS +5.72"。
**该数字是 anchor 基准 (fwd_return_t1, 以计划限价 entry_price 为起点), 是纸面 edge, 禁止引用。**

证据: `app/playbook/ic_tracker.py` L223 注释 (系统自己的警告):

> "未执行指令 limit 价不可成交, entry 基准会制造'纸面 edge'幻觉 (n=100 实测 +1.65%→open 基准 +0.04%)。"

未触发单的 entry_price 是**从未成交的限价**, 实测比信号时价平均低 2.44% (n=78 可比对)——
以它为起点等于假设"能在一个市场不给的价格成交"。+4.40% 里约 3.7pp 是这个不可成交折价, 不是 edge。

**正确口径 = open 基准孪生列 `fwd_return_t1_open`** (ic_tracker 2026-08-01 落库, 以当日开盘价为起点,
= "若开盘市价进场"的可成交反事实)。本案全部裁决数字以 open 基准为准, anchor 基准仅留档作诊断。

## 三、辩论点 (反方必须攻击的 6 处)

1. **日级相关 vs 观测级显著 (头号攻击面)**: Welch t=2.72 显著, 但日级配对 t=0.47 不显著。
   反方要求: 用 SPY 当日收益做市场调整 (open 基准收益 − SPY 同日收益) 重算差值;
   若调整后 gap < +0.3pp 或日级配对 t < 1.0 → P1 的 alpha 主张证伪, 效应是市场 beta, 结案。
2. **选择偏差的结构性解释**: BUY 未触发 = 当日没突破高点 = 当日没大涨。open 进场次日 +0.71%
   可能只是低波动票的隔夜均值回归/漂移, 与 LLM 方向判断无关。反方要求: 按前一日涨跌幅分桶
   (跌日/平日/涨日) 控制后看 gap 是否仍在——若 gap 只在"前日上涨"桶存在, 是动量漂移不是信号。
3. **方向不对称 (SHORT 镜像反着来)**: no_trigger SHORT open 基准 −0.68% vs executed SHORT +0.55%。
   若触发门对 BUY 是负过滤、对 SHORT 是正过滤, "统一触发门整体是坏的"就不成立——
   反方必须解释这个不对称 (候选: SHORT 触发=跌破当日低点, 跌穿才触发本身是动量确认, 而 BUY 突破高点是追高)。
4. **未触发集子集定位**: §2.5 遥测显示 5+ 类门拦截混在同一 skip_reason 终态里。
   反方要求: 把 +0.71% 按遥测 reason 拆开——若只来自 after_cutoff (10:15 禁触窗后), 与 8/12 禁触窗案交叉;
   若来自 low_atr_block, 与 8/6 候选预过滤案交叉。定位不到单一子集 = 机制叙事不成立。
5. **与 DEB-20260812 动态锚案的竞争**: 不改门、改锚 (pullback_to_support 替代 breakout 锚)
   也能提高触发率吃到错失集。两案是竞争方案, 反方须论证: 若锚案落地, 本案的 +0.79pp 还剩多少残存?
   (post-锚案基线纪律: 新规则评估必须叠加既有/在途规则基线, 禁止在无锚案基线上报全量)
6. **费用与容量**: open 进场意味着未触发集全量成交 (+175 笔/窗口), 费用敞口翻倍,
   且开盘市价单滑点未建模 (0.18% 费用拖累不含滑点)。反方要求: 扣滑点后的残存 edge 是否仍 ≥ 费用?

## 九、优化总纲 (Hermes, 回答用户 8/16 双问)

> 用户问: "如何优化调整, 确保不被历史信息拦截机会, 也能基于历史真正教训规避重复的坑。"

**核心框架: 历史信息有两种消费方式——硬拦 (gate) 与软知 (prompt)。过审计的教训保留硬拦, 不过的降级为软知: 教训不消失, 只换载体。**

### 9.1 不被历史拦机会: 历史门必须持续过反事实审计 (R3 记分牌, 已落地)

- **三档处置** (档位变更须预注册判据 n≥30 + 扣费 gap≥+1.0pp + 双窗口, 验证期内不动门):
  - 档 1 避坑 ✓ (vwap/vol/禁触窗): **保留硬拦**——这是"真教训"的物理形态
  - 档 2 杀机会 ✗ (streak_ban/extreme_gap/runaway_up): **候选降级为软知**——不物理拒绝, 把拦截理由变成 LLM 可见的教训字段 (§9.2), 由 LLM 权衡。等样本达标再裁
  - 档 3 样本不足: 观察
- **每周重跑** 两份记分牌 (no_trigger 回放 + gate_block_counterfactual), 追踪档位漂移
- conf 轴 (R2) 是同一框架的实例: conf 无区分度却参与 gate/仓位 = 历史分数在拦机会, 需裁决降级

### 9.2 用真教训避坑: 教训载体从"聚合标签"升级为"最近结局三元组" (R1 正确形态)

现状缺陷: trade_experience 注入 7/30 日**聚合 WR**, signal_gate 按聚合 WR ±15 分——静态标签的两个失败模式已实证:
1. **自增强循环**: WR≥60% 恒 +15 → 赢家越推越多 (MRK 12 天 10 成交, 8/4 实证)
2. **regime 切换后误判**: 聚合 WR 不随市况失效, 历史好=现在推

正确形态 (R1 落地内容, record-only): 注入 **"该股最近同方向 N 笔的结局三元组"**: `方向 + exit_reason + 当时 regime`, 例:
> "本股最近 BUY 2 连亏: MFE_STALL_EXIT@risk_on, SL_INITIAL@risk_on"

- LLM 看到的是**具体失败模式与场景**, 不是抽象标签——这才是"真教训": 场景条件化、近期优先、失败模式显式
- signal_gate ±15 与 streak_ban 将来消费同一信息源 (门级), 但须先过 §9.1 审计
- 与已落地的 score conviction 语义变更同包攒数据, 不单独占验证窗口

### 9.3 与用户交易哲学的对齐

- "不预测, 识别" → 教训注入只给事实 (最近结局), 不给结论 (LLM 自己识别)
