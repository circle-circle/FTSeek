## 背景

用户提问：每支标的盘前都会生成入场区间，8月成交数据里入场区间设置是否合理？是在高位还是低位入场？要提升盈利，合适的入场价格也是重要的。要求基于全链路分析入场价有没有更好的设计方案。

全链路（已审计）：
1. **区间生成**：`app/playbook/entry_band.py`（单一真源）。方向性不对称带：
   - LONG: `[anchor×(1-3%), anchor×(1+5%)]`（knife 3% 防接飞刀 / chase 5% 追涨上限）
   - SHORT: `[anchor×(1-5%), anchor×(1+3%)]`
   - RFC-065 vol_widen 变体（按 ATR 只放宽）生产开关关闭，影子常开攒样。
2. **触发判定**：`pipeline.py:_check_intraday_trigger`（L4667+）。两路径：
   - `pullback`（价格回到有利一侧）→ 直接触发；
   - `chase`（价格越过计划位）→ 需盘中量能门（`intraday_vol_ratio ≥ chase_vol_ratio_threshold=0.8`，开盘 15min 豁免）。
3. **时间门**：开盘禁触窗 ET≥09:35（8/15 从 10:15 缩短）、触发截止 ET≥14:00。
4. **成交**：触发后市价执行，成交价=触发时点实时价（中位偏离计划价 +0.007%，方向调整后）。

## 目标

1. 判定：8月入场主要发生在区间的"高位还是低位"，与盈亏的关系。
2. 判定：入场价位置是否是盈亏主因（还是时段/动量质量才是）。
3. 输出：入场价/区间/执行的更好设计方案（≥2 个候选方案辩论裁决）。

## 可选方案

### 方案 A：时段准入收紧（10:00-11:30 窗口加门）

- 提出者：Hermes（基于 E5 数据）
- 核心思路：亏损集中在 10:00-11:30 时段（-$683，两路径同崩），对该窗施加更严准入：量能阈值从 0.8 提到 1.2+，或该窗只放行 pullback 禁 chase。
- 优点：直攻最大出血口；有 8/15 禁触窗缩短成功的先例（同时段逻辑，效果 +$600 量级翻转）。
- 缺点：样本 61 笔（该窗），8月单月数据，可能混入特定行情日；需要先按日聚类验证不是单日事件。
- 适用条件：按日聚类后该窗亏损分布≥3个交易日。

### 方案 B：区间收窄 + anchor 重校准

- 提出者：（待辩论填入）
- 核心思路：中段成交（区间 0.33-0.67 分位）是亏损集中区，说明区间太宽让"不上不下"的弱突破也能进场。收窄区间（如 ±3% 对称）或把 anchor 从盘前计划价改为开盘后实测基准（VWAP/开盘 30min 中值），只让"真正到达有利位"的单子触发。
- 优点：直接回应用户"高位还是低位"的直觉；减少无确认入场。
- 缺点：与既有证据矛盾——不利区成交（深度回调侧）胜率最高，说明"等更低"未必比"已回调"更好；收窄可能拒掉回调赢家（RFC-065 已证"收窄拒掉的 10 条中 6 条是赢家"）。
- 适用条件：能证明中段成交的亏损是"区间宽"而非"时段差"造成（需与方案A做归因切分）。

### 方案 C：执行方式改造（限价单 + 有利边缘挂单）

- 提出者：（待辩论填入）
- 核心思路：触发后市价执行，chase 触发时中位已偏离计划价 +1.78%。改为触发后用限价单挂在区间有利边缘，接受部分成交/延迟成交，换取更好入场价。
- 优点：直接改善成交价；用户提到"实盘挂止损止盈单适配"方向一致。
- 缺点：SIM 市价成交滑点≈0（成交价中位偏离仅 0.007%），该方案在 SIM 期收益不可见；限价不成交会漏掉动量单；与"追涨需立即成交"的动量语义冲突。
- 适用条件：切实盘前验证；且只在 pullback 路径使用限价（动量单市价）。

### 方案 D：不动区间，只加影子（现状已够）

- 提出者：（待辩论填入）
- 核心思路：现有门禁（量能/禁触窗/低ATR/连败）已在持续改善入场质量（8/15 后开盘段翻正即证据）；追价偏离与盈亏无单调关系说明"入场价位置"不是可操作的主因。继续攒 entry_timing_shadow 样本，等 vol_widen 影子毕业再动。
- 优点：零风险零行为变更；符合"数据量优先"纪律。
- 缺点：对 10:00-11:30 出血口不作为；用户明确要"更好的设计方案"，纯攒样不回应诉求。

## 关键分歧

1. **分歧点 1：入场亏损的主因是"价格位置"还是"时段×动量质量"？**
   - 方案 B 观点：区间宽导致弱突破进场，位置是主因。
   - 方案 A 观点：E6 证明偏离度无单调关系，E5 证明时段是分界线，位置不是主因。
   - 可验证方式：中段成交样本按 10:00-11:30 时段切片——若中段亏损大部分落在该时段，则方案 A 归因成立。

2. **分歧点 2：10:00-11:30 加门的样本够不够？**
   - 61 笔是否够决策？单日事件还是结构性？
   - 可验证方式：按日聚类（用户纪律：先按日聚类再裁决），查该窗亏损的日期分布 + 单日最大占比。

3. **分歧点 3：SIM 期该不该动执行方式（方案C）？**
   - SIM 市价滑点≈0，限价单收益在 SIM 不可见；但用户哲学要求"实盘挂单适配"提前布局。
   - 可验证方式：限价单影子模拟（触发价+0.5% 限价假设成交率）反事实评估。

4. **分歧点 4：贴线追（0-1%）最差桶怎么解释？**
   - 可能是"突破刚发生、量能门 0.8 阈值放行太松"（阈值已从 1.5 降到 0.8）。
   - 可验证方式：贴线追样本的量能比值分布 + 盈亏对比（entry_timing_shadow 已有 vol 数据）。

## 决策

- **选择方案：D（维持现状基线 + 影子观察）—— 双模型 R2 收敛，置信度均 0.85**

#### T2. DA 链（主力）：落库区间 = LLM 自定义值，无固定公式

- 写库链路：deep-stock-analysis skill → `app/plan/deep_analysis_engine.py:436-446` 解析 `entry_zone {low/high}` → 直写 `playbook_instructions.entry_low/entry_high`（`app/playbook/db.py:477-478`）。

- **实测**：8月 147 笔 DA 成交指令，仅 17 笔碰巧符合 3%/5% 扁平公式；`entry_price` 不一定是区间中点（实测偏离样本：+1.15% / +0.89% / -2.16% / +3.54%）。

#### T3. UE 链：代码固定公式（单一真源 `app/playbook/entry_band.py`）

```
LONG : [anchor × 0.97, anchor × 1.05]   # -3% 防接飞刀 / +5% 追涨上限
SHORT: [anchor × 0.95, anchor × 1.03]   # -5% 追空下限 / +3% 反弹上限
```
- 依据（代码注释原文）：3% = 略宽于典型 2-2.5% SL；5% = 顺势加速方向最大追入幅度。
- 写库链路：`scripts/llm_universe_scan.py:1571 _compute_numbers(px, direction)` → `compute_entry_band()`；SL/TP 从区间边界外扩（`_compute_numbers` 内：LONG SL=low×0.97, TP=high×1.06），避免与 3% knife 重合。
- **anchor 来源**（`llm_universe_scan.py:1549`）：盘前可成交价（`_effective_quote_price`：BUY=ask / SHORT=bid），**防昨收滞后**——8/11 曾实锤 JD 锚错 3.8%（昨收 33.47 vs 真实盘前 32.21）后修复。

#### T4. ⚠️ 关键双轨事实：盘前落库区间 ≠ 盘中触发带

- 执行端 `app/playbook/pipeline.py::_check_intraday_trigger`（L4959-5078）**不读数据库的 entry_low/entry_high**，而是取指令的 `entry_price` 按 `entry_band.py` 的 3%/5% **现算触发几何**：
  - `pullback`（价格回到 anchor 有利一侧）→ 直接触发；
  - `chase`（越过 anchor）→ 需盘中量能门（`chase_vol_ratio_threshold=0.8`）。
- **后果**：DA 链存在两套数值并行——落库的"技术分析区间"（展示/归因/推送用）+ 执行端现算的"3%/5% 触发带"（真正决定何时成交）。
- 这解释了 E2 的"成交均匀散布落库区间全段（中位 0.51 分位）"：**成交价服从的是触发带几何，不是落库区间**——落库区间中点≠触发带中点时（DA 链常态），两者分位数本就不该对齐。
- **对第 1-2 轮结论的影响**：方案 D（维持现状）结论不变，但归因表述需修正——"区间中段成交亏损集中"反映的是触发带几何与时段的交互，不能直接归因于"LLM 区间设得宽"。
