## 二、Qoder 总判断

**病灶基本属实。根因不是措辞不够强，而是 Prompt 与规则层职责倒置。**

建议采用以下边界：

> 模型只输出有来源的判断、反证、证据缺口和必要的语义失效条件；凡是能够由输入确定、由代码计算、由 Schema 校验或由规则执行的事项，全部移出 Prompt。

优先级：

- **P0**：删除虚假的下游规则、重复门禁、无消费字段和相互冲突的契约。

- **P2**：UE 保留发现职责，但候选统一进入 DA 主链，不再作为平行裁决体系。

## 四、DA 分析师 Prompt 逐项建议

### 4.1 KO 具体股票示例

**结论**：删除真实 KO 内容，保留完整结构示例。

具体股票、具体数字和固定论据类型会形成内容锚点，诱导模型寻找类似的目标价、内部人交易和公司事件。示例对 Schema 依从有效，不等于具体案例内容对分析质量有效。

建议：

1. 使用明确标注为合成数据的完整 JSON 示例。
2. 示例只展示字段关系、空值规则和引用方式。
3. 增加一条“证据不足时允许空数组并 SKIP”的完整示例。
4. 不在示例中固定某一组高质量论据类型。

### 4.2 “每条必须有具体数字”

**结论**：会制造数字幻觉，应改成来源约束。

建议改写：

> 每条论据必须引用输入中的 `evidence_ref`；不得添加来源中不存在的数字。没有可追溯依据的论据不得输出。

同时删除“输入没有时可标注未验证或估算”的例外；允许交易论据携带未验证数字，与反虚构硬规冲突。

### 4.3 多空各至少两条

**结论**：与证伪官旧版“固定凑四条风险”属于同族病。

建议改写：

> `bull_case` 与 `bear_case` 各最多 3 条，允许为空。只输出会实质影响方向、准入或失效判断的论据；每条必须携带 `evidence_ref`，不得为满足数量补充通用风险。

若 BUY / SELL_SHORT 必须有正向依据，可规定“最终方向至少一条有效支持论据”，不应强制反方凑数。

### 4.4 “该股独有、不可移植”

**结论**：不可稳定判定，应改写成可验证引用规则。

建议改写：

> 个股论据必须引用属于该 symbol 的输入记录；宏观或板块论据必须给出从事件到该 symbol 的传导关系。

不再要求模型判断一句话是否能复制到其他股票。

### 4.5 C / D / E / F 混合强度清单

**结论**：自然语言中的“必须项 + 加分项”容易被统一理解为全部必填，应拆成条件式 Schema 或代码规则。

- 有有效情绪数据且超过阈值，代码生成拥挤标记。
- PE 与行业中位数都有效时，才要求相对估值。
- 风险日期落入交易期限时，代码添加风险门。
- 分批执行若为真实消费要求，改成结构化 `entries[]`，不要只写在 `entry_strategy` 散文里。

### 4.6 数据充分性路由

**结论**：“≥6 维缺失优先 SKIP”与“不得滥用数据不足”存在冲突；“优先”本身不可执行。

建议改成具名原因：

```text
现价缺失                 -> SKIP(DATA_PRICE_MISSING)
方向所需核心证据源均缺失 -> SKIP(DATA_CORE_MISSING)
数据存在但无方向性证据   -> SKIP(EVIDENCE_WEAK)
```

不按缺失维度总数裁决，因为各维度重要性并不相等。

### 4.7 冗余与诱导字段

建议继续裁定以下项目：

1. `rating`、`confidence`、`direction` 三重表达冗余，原则上只保留 `direction`。
2. `score_band` 若完全由三项条件决定，应由代码计算。
3. `stop_loss` / `stop_loss_price`、`take_profit` / `take_profit_price` 重复，应保留单一事实源。
4. “因果链至少三层”会诱导虚构中间环节，建议改为 1–3 个带来源的因果边。
5. `tripwires` 若仍无消费方，应从生产 Prompt 删除；影子研究使用独立 Prompt，不污染生产契约。
6. 实时表现、负 IC 论据类型和短期盈亏统计会诱导近期结果追逐，原则上应由规则层处理，不作为模型心理锚。

## 五、校准段与档位塌缩

### 5.1 是否把历史表现写进 Prompt

**不建议写总体命中率、费用后净期望或总体盈亏比。** 这些数值会形成全局锚点，却不能告诉模型当前样本的具体证据哪里不可靠。

推荐分工：

1. 模型输出事实、来源、证据缺口和方向。
2. 代码计算证据等级、历史校准和最终权重。
3. 模型通过 `evidence_gaps[]` 与结构化 `SKIP reason` 表达不确定性，而不是输出主观 confidence。

### 5.2 HIGH 档规则

当前 HIGH 必须包含 `product_catalyst` 或 `earnings_beat`，会结构性压低技术突破、监管事件、内部人变化等其他证据类型。

建议：模型不直接输出 HIGH / MEDIUM / LOW；代码依据以下事实派生：

- 引证是否存在并通过核验。
- 关键论据是否相互独立。
- 是否存在未解决的决定性矛盾。
- 信息是否已经被价格与量能反映。
- 数据是否满足具名完整性条件。

“信息是否已被价格反映”若使用明确阈值，也应由代码计算，不应让模型重复执行布尔判断。

## 六、Challenger 重构建议

### 6.1 当前内在冲突

1. 在同一请求里先展示候选方向，再要求“独立先行”，无法真正消除锚定。
2. 强制 BUY / SELL_SHORT 二选一会把证据不足变成强制猜测。
3. “至少两条反证”把数量误当成严重度：一条决定性反证可能足够，两条弱风险也可能毫无意义。
4. “每发现一处未知数字 my_score -1”会诱导模型少报问题以保分。

### 6.2 推荐两阶段调用

1. **盲评阶段**：只给原始数据，不给分析师方向与论据；允许 BUY / SELL_SHORT / SKIP。
2. **核验阶段**：再给分析师论据，逐条进行来源、可证伪性和影响等级审计。

### 6.3 推荐输出契约

```json
{
  "independent_direction": "BUY|SELL_SHORT|SKIP",
  "claim_checks": [
    {
      "claim_id": "...",
      "source_status": "VERIFIED|UNSUPPORTED|CONTRADICTED",
      "falsifiability": "TESTABLE|NOT_TESTABLE",
      "impact": "DECISIVE|MATERIAL|MINOR",
      "evidence_ref": "..."
    }
  ],
  "strongest_failure_case": {
    "observable": "...",
    "condition": "...",
    "deadline": "...",
    "evidence_ref": "..."
  },
  "flip_condition": "...",
  "verdict": "UPHOLD|DOWNGRADE|REJECT"
}
```

约束：

- 一条 `DECISIVE` 反证即可 REJECT，不要求凑两条。
- 原始数据不支持精确价位时，不得强制生成价位；只输出可观测条件和时间窗。
- 删除 `my_score -1`，来源不明数字由代码独立计数。
- `UPHOLD` 只有关键论据完成核验后才产生正向信息；单纯“没找到反证”不自动增加信心。

## 七、UE 定位与字段裁剪

### 7.1 推荐职责边界

> UE 负责扩大候选召回，DA 负责统一裁决。

不建议合并两份 Prompt；建议把 UE 候选合并进 DA 候选池，经过同一证据核验、准入和执行规则。

### 7.2 建议删除或代码派生的字段

| 字段 | 建议 |
|---|---|
| `self_tier` | 由 evidence 类型和核验结果在代码中计算。 |
| `evidence_checklist` | 可由输入计算的 bool 交给代码；不可计算且无消费者的项删除。 |
| `expected_move_pct` | 无消费方且制造伪精度，删除。 |
| `horizon_hours` | 只有接入候选 TTL / 过期机制时保留。 |
| `is_universe_external` | 由代码按候选池成员关系计算。 |
| `winner_loser` | 与 direction 重复，删除。 |
| `corroborated_by_market` | 与 evidence tier / checklist 重复，删除或代码派生。 |
| `borrow_feasible` | 没有真实融券数据时模型无法可靠判断，应由券商数据提供。 |
| `squeeze_risk` | 有结构化流通盘、做空与量能数据时由代码计算，否则删除。 |

### 7.3 UE 非盈亏发现价值口径

1. 榜外独有候选率。
2. `evidence_ref` 核验通过率。
3. 进入 DA 后的有效候选转化率。
4. 相比常规榜单的提前发现时间。
5. 重复候选率与冷却拦截率。

不建议把 LONG / SHORT 比例本身作为质量目标，避免再次诱导配额式生成。

### 7.4 失效条件格式

建议统一到较轻契约：一条 narrative invalidation，加可空的结构化 triggers。若 triggers 尚无生产消费者，则从生产 Prompt 删除，在独立影子契约中采集。

## 八、与既有蒸馏 DEB 的冲突

`DEB-20260901-da-prompt-distillation-shadow.md` 的核心前提是“只精简表达，不改变任何行为规则”，并把以下内容视为必须 100% 保留：

- 三层因果链。

本次复核认为其中至少一项是**事实错误**，其余多项可能是行为病灶。故两案不是简单并行关系：

> 如果本档判断成立，则“37/37 行为规则完整保留”不再代表蒸馏正确，而可能代表把旧病灶无损复制到了新版。

**Qoder 建议**：在多 Agent 裁决完成前，不把“语义等价蒸馏版”转正；现有影子数据可以继续只读采集，但不得据此宣称 Prompt 结构已经解决。

## 九、建议的离线验收口径

不依赖交易盈亏，使用固定分层输入集：

- 每个角色至少 **60 条**。
- 覆盖：多头证据、空头证据、证据不足、现价缺失、硬事件、纯技术信号六类。
- 固定输入、固定模型参数；新旧 Prompt 配对运行。

| 验收项 | 建议阈值 |
|---|---|
| JSON / Schema 合法率 | 100% |
| 输出中无来源数字 | 0 条 |
| 非空论据 `evidence_ref` 覆盖率 | 100% |
| 非适用字段正确为空或缺省 | 100% |
| Challenger 对分析师关键论据逐条核验覆盖率 | 100% |
| 因最小数量要求产生的重复或通用凑数论据 | 0 条 |
| 具名数据缺失场景的 SKIP reason 准确率 | 100% |
| 代码可派生字段与代码重算结果不一致 | 0 条 |

说明：30 条只适合发现明显结构错误；若 60 条中零违约，按“三倍法则”才可粗略认为真实违约率低于约 5%。这仍是契约验收，不是收益有效性证明。

## 十、Qoder 推荐裁决顺序

1. **事实核验**：确认 UE confidence、DA score、tripwires、self_tier 等字段当前真实消费者及开关状态。
2. **P0 纠错**：删除虚假止损规则，不等待收益样本。
3. **字段减法**：删除确认无消费者的字段和重复表达。
4. **规则下沉**：把可计算阈值、方向硬门和档位映射移到代码。
5. **Challenger 两阶段影子**：先盲评，后逐论据核验。
6. **UE 汇流影子**：保留发现器，候选统一走 DA 裁决。
7. 一次只转正一类变更，按 Prompt hash 分割基线。

## 十一、提请多 Agent 独立回答的问题

为避免同源互相盖章，建议首轮 Agent **只读原始 brief，不先读本档 Qoder 结论**；首轮完成后再把意见写入下列区域进行交叉质询。

2. 哪些字段在真实代码中有消费者，哪些只是写入或影子字段？
3. 删除 confidence 后，是否会造成 SKIP 滥用；应通过何种结构化字段提供不确定性出口？

5. Challenger 必须两次调用才能实现盲评吗？有没有单调用但仍能产生信息量的更低成本方案？
6. UE 汇入 DA 候选池会不会损失事件发现多样性或增加 DA 供给拥塞？
7. 本档与 `DEB-20260901-da-prompt-distillation-shadow.md` 应当暂停、并案还是保留并行？
8. 请给出可以在 30–60 条固定样本内裁决、无需等待 PnL 的验收指标。

### 交叉质询答案（四方意见收敛后，2026-09-07）
