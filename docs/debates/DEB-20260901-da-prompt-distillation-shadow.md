## 一、问题定义

**DA 系统提示词是战伤累累的活文档——每条注释都是一次事故的疤，但疤痕本身开始消耗模型的注意力。**

1. 现状测量：SYSTEM_PROMPT 2867 字符 / ~1880 tok / 73 行，6 个段落；10+ 行携带显式变更史标记（DEB 编号/日期/修订缘由/原规则引文），段落标题本身带日期戳（如"【校准原则】(2026-08-25 接入生效; 此段此前只写在函数docstring里…)"）。
2. 最佳实践对照（Anthropic/OpenAI PE 指南）：
   - 行为指令与历史叙述分离——模型不需要知道规则"为什么变成现在这样"，只需要知道规则本身；
   - 关键规则置首置尾（注意力首尾效应）——当前最硬的下游废单规则（止损 2-5%/不接飞刀）排在第 4 段，校准原则排最末；
   - 结构化分段与一致格式——当前段落间优先级不分层。
3. 反向证据（必须如实列出）：本提示词历经 DEB-20260808/0814/0823/0825 多轮实证修订，每次修订都对应一个真实病灶（KO 深度死循环 83% 观望 / LIF 盘前锚定昨收 / 信息 edge 年龄误判）。**提示词不是冗余，是压缩包**——蒸馏的风险是解压丢数据。

## 二、蒸馏设计（阶段一：离线，无影子无生产触碰）

**原则：只动表述与结构，不动任何行为规则的语义。**

1. **行为规则清单化**: 先从现行 SYSTEM_PROMPT 逐条抽出全部行为规则（硬规/加分项/禁令/判定测试），形成机器可核对的 checklist（预计 20-30 条）。
2. **蒸馏版 v2 制作**:
   - 删除：变更史注释、日期戳、"原规则如何/为何修订"叙述、文档性括号；
   - 重排：结构性硬规（废单级）置首 → 核心原则 → 校准纪律 → KO 深度（加分级）→ 示例；
   - 保留：KO 示例（示例对质量的锚定是实证有效的，DEB-20260814 证据）、全部判定测试原文语义。
3. **行为等价审计**: checklist 逐条比对 v2——任一行为规则缺失/语义漂移 = 阶段一不通过，回炉。**这是蒸馏的生死线，先于一切效果评估。**
4. **预期收益（诚实预估）**: token 降幅 15-30%（元注释占比实测约 15-25%）；主要收益假设是注意力重分配而非省钱（省下的输入成本 ~$0.03/日，可忽略）。
