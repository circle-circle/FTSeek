## 可选方案

### 方案 A：三次采样并行化（立即档）

- 内容：`_run_challenger` 内 2 次补采（llm_synth.py:742-743）与主挑战者调用并行发出（ThreadPoolExecutor，I/O 密集，GIL 无碍）；返回值收集顺序固定（第 1 个仍作 live，保持现有语义）。
- 收益：消除今日 +28 min 增量，回到 67 min 基线；若 shadow 转多数票，并行化红利继续存在。
- 质量影响：**零**——同 prompt、同模型、同温度，i.i.d. 采样正是测量设计本身；并发不改变分布。
- 风险：DashScope 并发/RPM 未知（攻击面 1）；429 重试/降级行为需写死（补采失败→跳过该样本，不影响 live 第 1 采）。
- 改动面：llm_synth.py 单文件 ~15 行。

### 方案 B：shadow 裁决日写死 + 登记（立即档）

- 内容：主 DEB 执行项加"三次采样 shadow 裁决 ≤2026-07-30：翻转率低→回退单次（挑战者成本立省 2/3）；翻转率高→切多数票（单独批准）"。逾期未裁决→自动回退单次（默认删除，防墓地）。
- 收益：成本轴最大杠杆（挑战者调用量 ×3 是今天全部增量的来源）；防实证 3 的墓地重演。
- 质量影响：零（shadow 本就 record-only）。

### 方案 C：分析师结果日级缓存（低优先顺手档）

- 内容：以 `(symbol, trade_date)` 为键缓存 analyst+challenger 结果（`data/llm_cache/` 已有目录与先例）；同日重跑/崩溃续跑直接命中。
- 收益：异常场景（手动调试、中途崩溃）全量重付 → 免费；正常日零变化。
- 风险（攻击面 2）：同日盘中重跑若行情已变，缓存给出**陈旧分析**——须定义为"默认不读缓存，仅 `--use-cache` 显式开启"，或键内含数据摘要哈希。

### 方案 D：候选级并行 ×4（缓行档，本文倾向拒绝）

- 内容：4 worker 并行处理候选，结果收集后统一写 bridge/DB。
- 收益：97→~25 min（或基线 67→~20 min）。
- 反对理由（作者自攻）：实证 5 无下游死线，收益是体验不是运营；交易资金链路引入并发=限流/日志交错/异常隔离三类新故障面；**改动收益比远低于方案 A**。建议：仅当未来候选数翻倍（如 30+）或出现真实死线时再议。

### 方案 E：score<5 跳过挑战者（休眠档）

- 前提实证 4 成立；但今日节省为零（score 恒定 6~7）。**不实施**，仅在 score 轴修复（主 DEB 数据开门档）后自动生效。写入本文仅为防未来重复提出。

### 方案 F（新增，辩论中提出）：token usage 落库

- 内容：`_call_llm` 返回时把 API `usage` 字段写入 debate/bridge 元数据（只读字段，零行为变更）。
- 收益：补齐实证 6 的度量地基；方案 B 裁决时拿真实 token 成本而非估计。
- 改动面：~3 行。

## 核心论点（作者立场，待辩论）

**论点 E1**：在零质量损失硬约束下，值得立即做的只有 A+B（+F 顺手）；C 可顺手但须防陈旧语义；D 应**拒绝**（无死线 + 资金链路复杂度）；E 休眠。

**论点 E2**：成本轴的真正杠杆不是任何代码优化，而是**方案 B 的纪律**——三次采样是临时测量，裁决日一到就回退或转化，让 +50% 调用量自然消亡。优化代码去适应一个本应消失的临时成本，是本末倒置。

**自我声明的不确定性（主动交出的攻击面）**：

1. **DashScope 并发限制未验证**：3 路并发若触发 RPM 限流，方案 A 的"零影响"不成立（补采 429→样本缺失→翻转率测量样本偏少）。辩论方可查 DashScope 文档或用现有日志反推峰值 RPM。
2. **缓存陈旧语义**：方案 C 若默认开启，同日重跑会用早盘数据覆盖盘后分析（方向性错误）。作者已把"显式开启"写进方案，但是否足够、是否该干脆拒绝 C，交由辩论。
3. **max_tokens 截断未查**：分析师 3000 / 挑战者 2000 上限是否截断过输出（影响质量的既有问题，非本文引入）？若有截断，方案 A 省下的时间应优先花在"查 usage 是否顶格"上——这与方案 F 联动。
4. **67 min 基线的构成未拆解**：数据采集（data_collector.collect_all, 网络 IO）vs LLM 各占多少？本文假设 LLM 主导（由 +28min/30 次反推单次 ~55s），但未直接计时。若数据采集占比高，方案 D 的收益结构会变（采集也可并行，但也更可缓）。
