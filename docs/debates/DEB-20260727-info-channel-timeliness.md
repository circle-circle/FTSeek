## 二、概念拆解 (三个词三种药, 不可混开)

1. **时效性**: 系统内最大时延不在"信息→决策"(分钟级) 而在"决策→执行"(15h, E7)。信息侧再快, 执行侧隔夜全浪费。
2. **独家性**: 个人系统无真独家 (合规+成本双不可行)。可得平替 = ①公开信息的更快一手化 (EDGAR 8-K 直连比 RSS 转述快一跳且权威, 天然 HARD_EVENT) ②别人不看的角落 (借券利率/期权异动)。
3. **反馈响应**: P3 负反馈 (7日结果表注入) 已上线; 缺**来源级判分闭环** (E6) — 不知道哪个渠道有 alpha, 就无法定向加深或砍掉。

## 三、方案分级

### 修尺子·可先行 (零机制变更, 建议本周)
- **S1 来源级判分接线**: UE 落库信号带 news source(已有字段) → scorecard 加"来源×fwd"切片。产出: 2 周后知道每个渠道的信号命中率。~30 行, 纯可观测性。
- **S2 RSSHub 消单点**: instances 加 2 个备用公共实例 (rsshub.app 等, 按 priority 降级) 或自建 docker (成本≈0, 稳定性自控)。配置级改动。
- **S3 SEC EDGAR 8-K 直连**: EDGAR full-text/RSS 官方免费接口, 8-K (重大事件) 分钟级入库 → \_gather_hard_events 第一手源。复用 sec_form4_provider 的 EDGAR 访问框架。
- **S4 周末补扫**: 周一盘前首轮采集前补一次"回看 48h"的深度拉取 (feed 分页/archive 端点), 堵 E4 缺口。采集侧小改。

### 需 DEB 裁决 (机制变更)
- **M1 事件驱动触发**: 8-K/盘中异动 → 即时唤起单标的 UE 扫描 (替代等 21:10 批扫)。这是"快速响应"的真形态, 但侵入盘中主循环 + LLM 调用增量 → **等 S1 来源判分证明信号值得抢时间再裁** (判据见 Q2)。
- **M2 付费数据源** (Benzinga/Tiingo news API/期权流): **后置** — 等 S1 数据证明免费源 alpha 上限确实被卡 (判据见 Q3)。UE 29% 命中现状下先花钱 = 给漏水的桶加水。
- **M3 决策→执行提速** (E7): 已归 A4/入场分散化议题, 本案只挂账不重复立案 — 但排序上 **M3 > M1 > M2** (最大时延在这)。

## 四、预注册判据

- **Q1 (S1 生效)**: 2 周后来源切片 n≥30/源, 若某源命中 ≥55% 且另一源 ≤40%, 则信息饮食权重调整立案。
- **Q2 (M1 门槛)**: 仅当 S1 显示 HARD_EVENT 通道命中 ≥55% (n≥20) 且 L2 复跑仍现半衰期, 事件驱动才值得裁; 否则否决 (快≠准)。
- **Q3 (M2 门槛)**: 免费源全部命中 <50% (n≥30/源) 且 S3 EDGAR 直连仍不改善 HARD_EVENT 占比 → 才考虑付费源试用。
- **Q4 (S4 验证)**: 周一 UE 输入中"周末发生事件"覆盖条数, 补扫前后对比 ≥+3 条/周为有效。

## 五、诚实弱点

1. S3 EDGAR 8-K 量大噪多 (日均数百份), 需 form-type 白名单 (8-K item 2.02/7.01/8.01 等) + 标的池过滤, 否则信息饮食变信息中毒。
2. S1 判分受混杂因素 (同一标的常多源同报) — 切片按"首报源"归因, 需在落库时记 first_seen_source。
3. M1 若上线, 盘中 LLM 调用不可控增长风险 — 须带日配额熔断 (复用 llm_budget 框架)。
4. 本案全部收益兑现的前提仍是信号质量本身 (08-07 P5/A2 判分) — 渠道是放大器不是发动机。
