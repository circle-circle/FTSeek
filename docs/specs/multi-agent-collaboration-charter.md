# FTSeek-US 多模型协作宪章（v1，2026-07-24）

> **适用对象**：所有参与本项目的模型/Agent **以及用户本人**。任何角色（含用户）违反本宪章的动作，执行方有义务指出并要求显式确认后才继续。
> **地位**：与 `AGENT.md`（运维/架构规矩）、`handoff.md`（进度状态）并列的三大入口之一。新 Agent 接手顺序：AGENT.md → handoff.md → 本宪章 → 相关 DEB。
> **每条规则都来自真实事故**，括号内为出处，不是理论洁癖。

## 一、角色协议（多模型辩论如何组织）

1. **三角色制**：作者（起案+证据链）→ 辩论方（证伪式攻击，禁止只做"确认式复核"）→ 独立复核方（第三模型，只读复现）。同一议题的不同轮次尽量换模型担任。
2. **辩论方的合格标准**：必须独立重跑数据（不引用作者数字）、必须找出至少一个攻击点或明确声明"无法证伪"；只写"同意"的复核无效。
3. **轮内自我修正光荣**：发现自己上一轮错了，在同一 DEB 追加修正节（如"第 5 轮补注"），**禁止静默改写历史轮次**（诚实归档规范）。
4. **裁决权**：数据判，不投票。两模型分歧时用原始数据复核裁决；数据不足则标注"证据不足待积累"，不强行收敛。用户是最终裁决人，但用户裁决若与预注册判据冲突，须在文档记录"知情破例"。

## 三、落档强制（不落档 = 没发生）

1. **一事一 DEB**（`docs/debates/DEB-YYYYMMDD-主题.md`）：状态栏勾选、每轮追加讨论记录、结论附**可复现命令/代码锚点**。
2. **复核结论强制写回原 DEB**（新轮次），不允许只在会话里说——下一个模型看不到会话。
3. **handoff.md 是唯一进度队列**：每次改动更新"变更日志"（最新在上）+"下一步"（按时间排序）；`最后更新` 日期同步。
4. 涉及配置/环境的结论 → 记忆（project_environment_configuration）；涉及教训 → DEB 方法教训节。

> ⚠️ **验证期已届满**（2026-08-31 补记，2026-11-14 时效校正详见文末变更记录）：本节条文保留为历史与方法论出处，**现行红线以判据字典（`docs/ADJUDICATED-CRITERIA.md` C 类）与 `docs/OKR-2026-11.md` guardrails（§1 继承裁决）为准**；§四.1 白名单不再约束 9 月后的动作。

1. **三类动作白名单**：修尺子（度量/校准修复）、攒样本（shadow/透传/记分牌）、做减法（三步：证零消费→配置停→观察一周后代码退役）。**新机制默认排队 9 月**——任何人（含用户）坚持插队，须在对应 DEB 记录"知情破例 + 归因影响评估"。
2. **一次一变量**：同一交易日不叠加两个会改变信号分布或退出行为的变更（拒切 glm、推迟 prompt 回灌均因此）。
3. **一切 live 改动带独立开关**，一行配置回滚；prompt 属信号源改动，必须 scan-eval 离线 A/B 先行（v2.0 相变教训）。
4. **验证窗口冻结**：首夜/裁决日前 8 小时管线冻结，零收益纯风险的改动（墓碑清理类）不占验证名额。
5. **动手前查寄宿**：停用任何循环/模块前先查其寄宿任务（scan_loop 巡检/复盘寄宿教训）；改名单前先查派生消费者（防御股并集教训）。
