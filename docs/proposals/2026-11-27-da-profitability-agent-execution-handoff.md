## 三、已经发现的问题：先独立验证，不直接套补丁

### 问题 1：费用未知时，评分器可能把毛利当净利

历史代码位置：

```text
scripts/okr_2026_11_scoring.py
window_stats()
```

已复现输入：

```python
{
    "trade_date": "2026-11-02",
    "entry_price": 100,
    "quantity": 10,
    "realized_pnl": 10,
    "fees_est": None,
    "pnl_net": None,
}
```

原结果将其计算为：

```text
费用 = 0
净利 = 10
净收益 = 100bps
```

问题：

> 费用未知不等于零费用，净额未知也不能直接回退为毛利。

另外，同类归零逻辑可能出现在：

- 辅助净额汇总；
- KR2 分组净收益；
- 退出原因净贡献。

不能只修主汇总，留下相互矛盾的报表。

### 问题 2：置信区间文案可能虚报“下界大于零”

历史函数：

```text
scripts/okr_2026_11_scoring.py
kr1_verdict()
```

当前统计对象存在差异：

- 点估计：名义额加权净收益比率；
- CI／MDE：每日净 bps 的日等权均值。

这两个统计对象可能出现相反符号。

已复现：

```text
n = 120
名义额加权净收益 = +9.0188bps
日等权均值 = -89bps
日等权 CI80 = [-103.0976, -74.9024]bps
```

原文案仍可能写：

```text
CI 下界 >0
```

这是错误说明。

**修复文案不等于允许修改官方统计公式或 KR 判据。**

### 问题 3：启动已加载当日 bridge，随后同日更新可能无法刷新

历史位置：

```text
app/core/scheduler_core.py
启动 bridge 加载

app/playbook/pipeline.py
_try_load_bridge()
_reload_bridge_if_landed()
```

已复现路径：

1. 服务启动时加载当日 bridge。
2. 没有建立对应的刷新版本基线。
3. DA 同日重新生成候选文件。
4. 刷新助手遇到空基线直接返回。
5. 内存继续使用旧候选。

重要补充：

- loader 还会追加写入 `daily_active_pool.json`，不是纯读取函数。
- 刷新可能改变候选集合及方向消费，属于**行为相邻的正确性恢复**。
- adapter 刷新不等于指令库同步。
- 现有生成完成标记可能继续阻止重生成。
- 当前供给 complete 判定主要核同 symbol 的 DA 真指令存在，不等于同 decision／内容版本一致。

**首批不能顺带修改生成完成判据、强制重建全部指令或覆盖已认领行。**

- 修改 complete 判定；
- 将所有 DB 指令同步成最新 bridge；
- 重写已认领、已成交方向／SL／TP；
- 清 UNKNOWN 或释放订单锁。

### 必须覆盖的测试

- 启动加载 A，磁盘变 B，下一轮能加载 B。

若需要独立热回滚，使用经过批准的新开关；现有跨日 stale reload 开关不能被误当作同日刷新回滚。

回滚不会自动撤销已经注入动态池、写入 DB 或成交的变化。不得自动删池、回改认领行或清锁。

### 准入条件

正式输入改变前，重新核对当前：

- R2验证窗口；
- 现行 OKR；
- 实验名额；
- 新影子限制；
- 预算和付费调用权限。

此前方案 B仅顺延特定 Kill／Pivot时点，不代表所有结算与实验约束都可顺延。接手时必须依据当前裁决，不沿用过期日期。

### 三层验证，不得替代

1. **搬运层**：数据正确渲染。
2. **机制层**：对照臂是否产生超出模型随机性的判断变化。
3. **经济层**：真实可成交、完整成本、独立日簇上的增量。

不能用第1、2层成功代替第3层。

预注册必须事先规定：

```text
唯一假设
对照与候选母池
主终点及单位
模型随机性控制
样本与独立日数
MDE与计算方法
成本预算
决策日期
停止条件
失败或不可分辨后的动作
```

资料、功效或名额无法满足，标 `BLOCKED_PRE_REGISTRATION`，不得强行上线。
