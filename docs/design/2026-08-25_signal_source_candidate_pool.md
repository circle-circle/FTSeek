## 候选详解 (按证据路径优先级排序)

### ① 盘前微观结构 — 头号候选 (可回测, 不用攒样)

- **数据**: `request_history_kline(session='ALL')` 返回盘前 04:00–09:30 全量 1min bar,
  回拉深度 ≥2026-04-28 (实测 4/28–30 三天每天 570 根盘前 bar 完整)。
- **为什么是头号**: 现有 `premarket_invalidation.py` (8/9 起 record-only) 已证明盘前信息有
  方向性苗头 (规则 A 逆势追空亏损桶 −$172 / B 接飞刀 / C 追涨延伸日), 但它是 8/9 才开始攒样的
  前向影子——**本探针把同一个问题升级为全史回测裁决** (4/28 起 ~80 个交易日 × 全部成交笔可重放),
  符合 8/14 裁"历史存在→直接回测, 不默认攒样"。
- **可构造特征** (入场时刻全部事前可得): 盘前累计涨跌幅、盘前成交量相对历史盘前中位、
  盘前最后 30min 斜率、盘前波动率、盘前高/低点位置。
- **预注册判据**: 与死胎回放同口径 (eta²≥5% + |t|≥2 + 双窗口同向, 切点按交易日对半),
  结局标签 = MFE≥1% (存活)。费用门槛另算: 任何门禁候选须证明被拦票的净结局差 > 费用量级。
- **风险预警**: 盘前成交量稀薄, 量特征噪声大; 69% 死胎基率下特征分离的绝对空间本来就小,
  预期值要管理——这是"值得裁决"不是"预期有效"。

### ② 盘中资金流失衡 — 前向攒样候选

- **数据**: `get_capital_flow` 返回当日分钟级大/中/小/超大单净流入 (391 行/天实测),
  大单方向与散户方向背离是经典订单流信号。
- **限制**: 仅当日数据, 无历史 → 只能攒样。按 8/14 预注册攒样器纪律: 幂等采集器按
  (symbol, date, minute) 去重 + cron 挂载 + n≥30/组 + 双窗方向一致且差≥15pp 才列门禁候选。
- **成本**: 每日收盘后一次性拉取, 无订阅占用。

### ③ 订单流失衡 (TICKER) / 盘口失衡 (ORDER_BOOK) — 前向攒样候选 (重)

- **数据**: 两者订阅均接受, **订阅余量 998 槽** (当前仅用 2) → 可同时挂 40+ 票的攒样器。
- **限制**: 仅实时, 需建采集器持续落库才有历史; 数据量大 (逐笔), 存储与配额要预算。
- **定位**: ②③⑤ 同属"订单流族", 建议只选一个先攒 (最简=资金流, 最细=逐笔),
  避免三个同源信号同时攒样浪费样本期。

### ④ 期权 IV 结构 — 降级候选

- **数据**: 期权链完整 (22 个到期日, 单日 232 合约), IV/HV/溢价/分位接口活。
- **限制**: IV 历史序列实测仅 3 行周频快照, 无法构造连续 IV 时间序列回测;
  且富途期权权限档位未知 (probe 未测下单侧)。
- **定位**: 只做"入场时刻 IV 分位快照"式前向攒样, 优先级低于 ①②③。

### ⑦ 卖空数据 — 出局

- 美股 `get_market_snapshot` 的 short 字段全返回 NaN (卖空数据仅港股实体可用)。死源, 勿再探。

## 与既有组件的接线关系

- 候选①直接升级 `premarket_invalidation.py` 的三条规则 (A 逆势追空 / B 接飞刀 / C 追涨延伸日)
  从"8/9 起前向攒样"到"4/28 起全史回测裁决"——**同一个问题, 从攒样路径切换到回测路径,

- 候选②③⑤ 若启动攒样, 统一挂既有攒样器模板 (幂等+主键去重+cron), 判据写死在采集器里防漂移。
