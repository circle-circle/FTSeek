# 精简实盘驾驶舱 v1

> **实施状态**: Batch 1（入口、今日页信噪比、交易页布局、触控与响应式）已落地并验证；Batch 2 的 runtime capabilities、断线只读态、持仓保护状态与订单来源标记已落地并验证。重连对账状态机、改止损快捷入口仍未实现。

> **依赖边界**: 本设计只在现有 Jinja + 原生 CSS/JS 上落地，没有引入 React、Tailwind、BeUI/shadcn 运行时或任何前端构建链。BeUI/shadcn 仅作为层级、留白、状态表达和可访问性的参考。

## 1. 目标

只做四件事：

1. 一级入口 7 → 4，删掉重复 Tab。
2. 今日页只显示“当前状态 + 待办 + 风险仓位”，研究内容退出首屏。
3. 交易页围绕下单、保护、平仓、改止损、撤单和成交状态组织，不再当分析看板。
4. 断线/陈旧数据必须显式、只读、可对账，不能制造可交易的假象。

非目标：全站重写、设计系统工程、React/Tailwind 迁移、第二券商接入、真实实盘解锁、改任何交易策略或闸门。

## 2. 入口收敛

| 现状 | 目标 | 处理 |
|---|---|---|
| 指挥中心 `/` | 今日 `/` | 保留路由，重写首屏内容优先级 |
| 作战计划 `/plan` | 旧页兼容 | 不占一级入口；页顶标注停用并指向 Playbook；未做重定向/物理删除 |
| Playbook `/playbook` | 计划 `/playbook` | 当前唯一计划主入口，继续使用现有 Playbook API |
| 交易 `/trade` | 交易 `/trade` | 作为唯一交易入口 |
| 交易 HK `/trade/hk` | 并入交易入口 | 导航不再出现；由 `/trade` 内“美股/港股”切换进入，模板物理合并留后 |
| 股票池 `/watchlist` | 不占一级导航 | 从今日/交易/计划页进入；保留路由 |
| 系统 `/system` | 系统 `/system` | 保留；集中四锁、健康、审计和危险操作 |

落地原则：先减少入口和默认内容，不急着删后端路由。旧 URL 至少保留一个版本周期的兼容访问，避免书签失效。

## 3. 页面职责

### 今日

Batch 1 现状（只回答“现在需要我做什么”）：

1. 统一页头：今日 / 研究数据 / 股票池。
2. 状态条：今日盈亏、系统状态、持仓数、SPY/VIX、保证金、运行模式。
3. 决策摘要：市场状态、暂停开仓、今日与本周已实现盈亏。
4. 决策脑健康：只有异常/降级时占首屏；健康时随“研究数据”展开。
5. 待办区：有动作时显示；零待办显示“当前无需操作”。
6. 交易日报：已实现/浮盈、无盈利持仓、无亏损持仓。
7. 研究模块：决策链路、OKR、毕业门禁、因子性能、退出画像、新机制、记分牌、校准、完整分析默认隐藏；点击后才加载对应接口。

交易页已落地单行 runtime（券商/报价/持仓/订单/时段）；今日页尚未接入同一状态条，待办严格按风险取前 3 仍未实现。

今日页目标示意（非当前页面）：

```text
┌ 今日  ·  SIM  ·  券商已连接  ·  报价 2s  ·  美股 RTH  ┐
├ 今日净 PnL +$184.20 ｜ 风险占用 18.4% ｜ 待处理 2 ─────┤
├ 待办 1  补保护：TSLA 30/50 股       [处理] ──────────┤
├ 待办 2  挂单异常：NVDA #3812        [查看] ──────────┤
├ 持仓摘要  TSLA  +$420  保护缺口 20  止损 3.2%  [交易] ┤
└ 挂单摘要  2 笔；无成交异常                          ┘
```

### 交易

Batch 1 现状：

1. 页头：交易 / 美股 / 港股 / 股票池。
2. 账户摘要 + 手动下单闸门条：总资产、持仓盈亏、今日盈亏、购买力、保证金占用、全局阻断/手动单额度。
3. 下单票据：标的、类型、方向、操作、数量、风险预算、盘前盘后、自动止损止盈、报价与预览确认。
4. 运行状态条：账户摘要上方单行显示券商/报价/持仓/订单/市场时段；断线时红色只读、写按钮 disabled、摘要点显示“离线”。
5. 桌面双栏：左“下单票据”，右“持仓 + 交易记录/券商真值条”；移动端按“下单 → 持仓 → 交易记录”纵向排列。
6. 持仓表继续显示数量、成本、现价、今日盈亏、持仓盈亏、距止损/SL、保护状态（券商单/仅DB/无保护/未知）、占比；交易记录继续合并订单与操作审计。

现有标的智能卡/AI 建议条仍留在订单票据内，因为其上下文就是当前下单标的；本批未删除。深度研究、因子统计、退出画像和归因不进入交易首屏。

```text
┌ 交易  [美股] [港股]  ·  账户 $102,483  ·  购买力 $38,200 ┐
├ 标的 NVDA  145.22 +1.8%  买 145.20 / 卖 145.24  09:41:03 ┤
├ 订单票据：方向｜数量｜市价/限价｜TIF｜RTH ｜风险预览       ┤
├ 闸门：额度 ✓  回撤 ✓  资本水位 WARN        [预览下单]     ┤
├ 持仓交易组：NVDA LONG 40 / 保护 40 / 止损 -3.8% [管理]   ┤
└ 挂单 1 · 今日成交 2 · 台账（折叠）                       ┘
```

### 计划

`/playbook` 是唯一计划主入口：

- 一行 pipeline 摘要：候选 → 投票 → 指令。
- 今日指令列表：方向、标的、触发条件、失效条件、状态和下一步。
- 执行、跳过、修改沿用现有 API 与确认弹窗。
- 旧 `/plan` 只保留兼容访问，页顶明确标注停用；不参与默认计划路径。

### 系统

Batch 1 保留现有职责并补统一页头；自动交易开关、风险档位（保守/标准/激进）提升到 40px 触控高度。四锁、OpenD/WS/DB/push、审计、重启/模式切换的现有行为未改。

## 4. 断线不是新页面，是全局状态

> **已落地最小版**。`/api/trade/snapshot.runtime`、前端 capabilities guard、红色只读横幅、最后数据时间/校验时间、摘要“离线”点、持仓保护状态和订单来源标记均已实现。未实现独立的重连对账状态机；重连后 runtime 只按下一轮券商证据重新计算。

不新增“容灾 Dashboard”。把只读态作为所有交易页面的同一种运行状态：

| 状态 | 页面 | 可用动作 |
|---|---|---|
| 正常 | 实时数据，绿色/中性状态条 | 现有全部动作 |
| WebSocket 断 | 轮询模式，不阻断 | 数据仍新鲜时可交易（runtime 不依赖 WS） |
| 报价降级 | 横幅/持仓 SL 列标注降级 | 禁新开仓；减仓仍可用 |
| 持仓 DB fallback | 横幅标注“持仓为本地兜底” | 禁开仓/减仓/改保护；撤单仍看订单来源 |
| 订单审计 DB fallback | 交易记录标注“订单为本地审计” | 禁撤单；开仓/减仓仍看各自数据证据 |
| 券商断线/未确认 | 顶部红色只读条 + 最后同步 + 本地台账 | 禁下单/平仓/撤单/改保护 |
| 重连 | 下一轮 snapshot 重新计算 | 未实现独立“对账完成”门槛；不得宣称已对账 |

关键规则：缓存价格永远不能显示成实时价；未确认的订单只能显示“状态未知”，不能显示“成功”；断线时摘要点必须与横幅同源显示“离线”。

## 5. 信噪比规则

> 已应用：研究默认收起、无待办空状态、同页不重复台账、颜色配文字、交易页双栏、runtime 状态文字与 as-of、断线只读、持仓保护状态。尚未完全达成：每个交易数字的统一 as-of/来源、首屏严格最多 3 个动作、所有异常订单自动展开、重连对账。

1. 首屏最多 3 个动作；超过 3 个只按风险取前 3，其余进队列。
2. 每个数字必须带单位、as-of、来源/新鲜度；不满足就不进入决策区。
3. 同一个指标只允许一个主展示位置，其他位置只做链接或下钻。
4. 颜色只做辅助，风险/涨跌/连接状态必须有文字、图标或符号。
5. 无待办时明确显示“无需操作”，不显示空卡片。
6. 研究、回测、因子和小样本结论默认不进入今日页和交易首屏。
7. 用户当前动作的上下文永远优先于全局说明；不要在平仓弹窗旁放无关市场故事。

## 6. 最小数据契约

> **已落地（最小版）**。`/api/trade/snapshot` 已返回下列字段；前端只消费服务端 capabilities/reasons。未改订单 validator、闸门阈值或执行器裁决。

只在现有快照上加最小运行状态，不重做数据层：

```json
{
  "runtime": {
    "broker": "connected",
    "account": "real",
    "quotes": "live",
    "positions": "live",
    "orders": "live",
    "market": "regular",
    "as_of": "2026-10-25T09:41:03-04:00",
    "runtime_as_of": "2026-10-25T09:41:05-04:00",
    "capabilities": {
      "place": true,
      "reduce": true,
      "cancel": true,
      "modify_stop": true
    },
    "reasons": []
  }
}
```

服务端负责给出 capabilities 和 reasons；前端只据此禁用按钮、显示原因。fail-safe 规则见 RFC-165 §4：断线全关；持仓 DB fallback 关闭开仓/减仓/改保护；订单审计 fallback 关闭撤单；报价降级只禁止新开仓；现有 `blocks_now` 只关闭开仓。`market` 只用于展示，不新增阻断；盘前/盘后/休市约束仍由现有订单流程处理。`broker_attached` 仅表示本地记录有券商 STOP 单 ID，尚未向券商逐单核验。

## 10. 明确不做

- 不做新的图标库、主题系统或第二套 CSS。
- 不做大而全的组件文档站。
- 不为“未来可能的多券商”预先抽象 UI。
- 不把复盘内容搬到交易页。
- 不为了减少 Tab 而提前物理删除仍有调用的后端接口。
- 不引入 React/Tailwind/BeUI/shadcn 运行时、图标包或第二套组件系统；不增加前端构建链。
