# RFC-101: 延长时段入场链跨轮扫描状态缓存（L2）+ 影子注册（L3）

- **日期**：2026-09-23 | **状态**：**已回滚**（同日, 原因与证伪源见 §8）| **预注册**：见 DEB-20260923-eth-scan-efficiency §10–§11
- **触发**：用户「盘前盘后每一轮扫描都过相同不达要求的标的，都需要连接，比较低效，是否可以增量检查」→「落地」

## 1. 成本模型（先测后改；实测见 DEB §1/§10）

| 面 | 实测 | 能否被增量缓存减掉 |
| --- | --- | --- |
| 每轮候选生成 | `_scan_movers`（榜）1 次 + 仅"不在榜上的日历票"批量快照（个位数） | ✗（榜必须每轮拉才能发现新票） |
| 每轮固定开销 | `OpenQuoteContext` ×2（dry + live 臂）+ 榜 + 日历/Finnhub ≈ **4–6 次调用/轮** | ✗（**与候选数无关**，只有常驻载体能减 ⇒ L4） |
| 逐票昂贵调用 | `_liquidity_quote`(快照) / `_pretrade_gate`(价差深度) / `_entry_structure_gate`(K线)，位置 L2474/2499/2515，只在过完前门后触发 | ✓ **这是 L2 的目标** |
| 逐票廉价部分 | 价格闸/带/量/事件/判据（榜行字段或进程内日历字典） | 勉强（重算本身免费，缓存只会增加 I/O） |

**结论（与 §10 的初版方案相比的修正）**：连接成本由**每轮固定开销**主导，不在"每票重复评估"上；L2 今日实测节省 ≈ 0 次连接（42 只候选全部死在前门 ⇒ 昂贵调用 0 次），它的价值是**当链路真正产出时**（RFC-100 放宽早段后 5–6 只/轮会走到昂贵门 ⇒ 5×2 calls/轮 × 113 轮 ≈ 1,100 次/日）不再重复取数。故 L2 的目标类别收窄为"昂贵 + fail-close"，不做廉价门的缓存。

## 2. 授权开关（两个词回滚）

| 开关 | 默认 | 作用 |
| --- | --- | --- |
| `EXT_SCAN_STATE_CACHE` | **false** | 打开后：昂贵门的结论按类别 TTL 跨轮复用 |
| `EXT_SCAN_STATE_SHADOW` | false | 只记账（"若打开会命中/失效多少"），不改变判定 |

未配置 ⇒ 本模块**完全不被调用**，行为字节级不变（同 RFC-100 的 fail-safe 约定）。

## 3. 缓存类别与有效期（按"输入可变性"定，非拍脑袋）

| 类别 | 覆盖的拒绝原因 | 有效期 | 依据 |
| --- | --- | --- | --- |
| `fail_close` | `surprise_stale` / `src_err` / `actual_missing` | **10 分钟** | 数据迟到是"暂时态"，长 TTL 会把迟到钉成永久拒绝（硬约束 C3） |
| `quote_quality` | 价差/深度/费用/漂移/流动性评级不合格 | **15 分钟** | 价差深度分钟级会变，短 TTL 只省"5 分钟内重复问同一件事" |
| `structure` | 结构门（VWAP/区间）不合格 | **30 分钟** | 结构由当日累计量价决定，变化慢 |
| `event_absent` | 当日无同相位财报事件 | **30 分钟** | 日历会补标相位（实测空相位 11.8%），不能整段钉死 |

**失效优先于命中**（硬约束 C2）：每轮用榜单行新鲜读数比对，出现以下任一即视为失效并重评 ——
① 价格变动 >10%；② 成交量变动 >50%；③ 涨跌幅变动 >1.5 个百分点；④ 记录时间戳晚于 `next_check_at`。命中必须**同时**满足"类别有效 + 未失效"。

## 4. 故障语义（硬约束 C5：宁多算，不少算）

- 状态文件不存在/损坏/结构不符 ⇒ `load()` 返回空态（不抛、不阻断）；
- 写盘失败 ⇒ 记一行 warning 后继续（本轮照常判定）；
- 关闭开关 ⇒ 零调用；
- **任何路径都不得因缓存而少评估**：命中时被跳过的调用必须记入观测计数器，可与"关闭时的调用数"对账。

## 5. 观测契约（C6）

- 新增**独立打印行**（不动闸计数主行）：`[ext_entry] 扫描状态[session] 命中=K 省调用≈M 失效=E 到期=T 写入=W`；
- 命中的拒绝仍进既有 reject 台账，行内加 `"cached": true` 供对账区分；
- L3：ETH 链 6 个既有台账 + 本次读数注册进 `app/playbook/shadow_registry.py`（`min_n`/`graduation_criteria`/`eval_script`），停摆守卫交框架 `check_mounting()`。

## 6. 判据（开/留/回滚）

**允许打开**（全过）：
1. 同轮 A/B：`ordered` 相同；除新增键外，闸计数**逐键相等**；命中的票其"关闭时最终处置"与"命中复用的处置"**逐条一致**；
2. 故障注入（状态损坏/只读）后：评估与调用数**不得下降**（fail-open 生效）；
3. 11 个 ETH 套件 + 棘轮用例全绿（本批不得增加 `except:pass/continue` 计数）。

**回滚触发**（任一）：① 出现"因缓存而漏掉一笔本该成交的票"（漏票反事实 > 0）；② 观测行缺行连续 1 日；③ 状态文件损坏导致 rc≠0；④ 命中率 >95% 且失效计数为 0（说明失效判据失灵）。
**回滚动作**：`EXT_SCAN_STATE_CACHE=false`（下一 tick 生效）+ 删 `data/loops/ext_entry_scan/`（无残留副作用）。
**复核日**：2026-10-08（与 RFC-100 同期读数）。

## 7. 不在本 RFC 范围（明说）

| 项 | 为什么不做/单列 |
| --- | --- |
| L1 qualified-first（只评事件池） | **实测收益 ≈ 0 次连接**（昂贵调用不在非事件票上发生），却会改变拒绝归因（非事件票从 `pretrade` 类键挪到事件键）⇒ 收益小、代价是真金白银的归因漂移。**不落地**，留作"若放宽事件门"时的前置件 |
| L4 常驻载体（省 113 次/日连接） | 唯一能减掉每轮固定开销的办法，但改的是进程模型 ⇒ 单独立项（DEB §11.4） |
| 死区降频（`*/10`） | 与 RFC-100 方向相反，等 10/08 读数 |

## 8. 回滚记录（2026-09-23 同日；用户令「逻辑感觉搞复杂了，从第一性原理和核心目标进行复查」→「执行」）

**结论：本 RFC 的 L2 方案整体撤回**（模块/用例/接线/开关/注册项全部删除，保留本文档作决策留痕）。

### 8.1 证伪源（三条，均为实读/实测，不是判断）

1. **成本模型（本 RFC §1 自己算出的）**：每轮固定开销 ≈ 4–6 次调用（`OpenQuoteContext` ×2 + 榜 + 日历/Finnhub），
   **与候选数无关**；逐票昂贵调用只在过完前面所有门后触发，**今日 42–43 只候选全部死在前门 ⇒ 昂贵调用 0 次**
   ⇒ 缓存的可缓存项 = **0 条**、收益 = **0**。
2. **代码实读**：逐票判据 `_earnings_surprise()` 的第一件事就是 `_earnings_calendar_event()`，
   而后者读的是**每轮进程内缓存的日历字典** ⇒ 「每轮重复评估同一批标的」的重复成本只是**字典查找**，
   没有任何取数可省。我此前把它写成"~90% 评估在重算已知答案"，真值是"重算的成本≈0"。
3. **替代方案 α 同样不成立（本打算落地、现场被证伪）**：把"资格"提成每轮一次的集合、非事件票直接短路 ——
   看似更优雅，但无事件票的拒绝原因取值域含**多个值**（`calendar_missing` / `calendar_phase_unknown` /
   `surprise_stale` / `actual_missing` …）⇒ 用集合替换必然**改变 reject 台账的逐字节形态**（归因漂移），
   而省下的仍只是字典查找。**省不了钱、却要动归因 ⇒ 不做**（属"读码后自我撤回"，标注证伪源）。

### 8.2 第一性原理复核（为什么该撤）

- 循环**存在的理由**是出单；实测 `ordered=0` 连续多日，链路是**零产出循环** ⇒ 给零产出配缓存 = 优化零。
- 门链的**必要条件**是"当日同相位财报事件"，异动榜 38/43 只是**结构上不可能出单**的人群 ——
  但**逐票判据已经是"先判事件、再判其余"**，人群问题在代码里已用最便宜的方式处理完了。
- 真正被浪费的不是调用，而是**方向**：本批次该服务的目标是"出单/盈利/降亏"，不是"省那 600 次调用"。

### 8.3 保留与后续

- **保留价值**：本文 §1 的成本模型（固定 vs 逐票两栏）**仍可引用** —— 它解释了为什么"增量检查"类提案
  在**本链当前形态**下必然近似零收益；§3 的失效判据/类别表若将来链路真正出单（昂贵调用每天上千次）才值得重启。
- **重启前置条件（写死）**：出现"每轮有 ≥1 只票走到价差/深度/结构门"的连续读数（观测行/台账可查），
  且**已先做完人群侧简化**（本 §8.2）。
- **真瓶颈已转向**：准入/供给（事件池 5–6 只/日 × 量闸/价差/数据迟到三态），见 DEB-20260923 §11.3 与技能
  「产出归属」一节。
