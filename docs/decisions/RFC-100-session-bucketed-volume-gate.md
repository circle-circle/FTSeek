# RFC-100 · 量闸按时段分档（session/hour buckets）

- **状态**：已落地（生产 `.env.us` 开）；复核日 **2026-10-08**
- **用户裁决（2026-09-23）**：「**我需要先跑通，选择中**」= 选我给的**方案②（中）**并先把它跑起来
- **落地提交**：`scripts/extended_hours_entry_executor.py` + `tests/test_ext_entry_volume_buckets.py`
- **一句话**：把「成交量 ≥ 20 万股」这一个绝对数字，换成**按 ET 小时分档**的门槛；早段用它原来等价的分位，而不是用收盘段的绝对量。

## 1. 动机（实测，不是推测）

口径：`data/extended_hours_price_gate_rejects.jsonl`（执行窗内每轮候选，4 个交易日 / 402 轮），同一 (session, ET 日, 标的, ET 小时) 取最大量 = 该时点累计量。

| 盘前 ET | 中位量 | ≥20 万占比 | 生长倍数 | | 盘后 ET | 中位量 | ≥20 万占比 |
|---|---|---|---|---|---|---|---|
| 04:xx | 398 | **12%** | 1.0x | | 16:xx | 1,015 | **14%** |
| 05:xx | 878 | 18% | 2.2x | | 17:xx | 11,663 | 25% |
| 06:xx | 1,777 | 20% | 4.5x | | 18:xx | 9,646 | 27% |
| 07:xx | 2,640 | 26% | 6.6x | | 19:xx | 11,116 | 29% |
| 08:xx | 25,182 | 34% | **63x** | | | | |
| 09:xx | 148,163 | **47%** | 372x | | | | |

外部同向证据（Cboe/SIP）：盘前 04:00–07:00 ≈ 3,300 万股/日、07:00–08:00 ≈ 4,400 万、**08:00–09:30 ≈ 1.86 亿**（≈早段 4 倍）。

**结论**：20 万股在 09:xx 只是人群的 ~47 分位（近一半能过），在 04:xx 却是 ~p88（只有 12% 能过）⇒ 现役闸的实际语义 ≈「**盘前 04:00–08:00 基本不下单**」，而 **bmo 财报（常 07:00–08:30 发）的盘前跳空正落在这里**。这不是"行情不好"，是闸与时段不匹配。

## 2. 规则（落地形态）

```ini
# .env.us
EXT_ENTRY_MIN_VOLUME_BUCKETS=4-7:20000            # live: 盘前 04:00-07:59 ET → 2 万股
EXT_ENTRY_MIN_VOLUME_BUCKETS_SHADOW=16-16:20000   # 影子(只记账): 盘后 16:xx 若 2 万会放行几只
```

- 格式 `"起-止:阈值"`（ET 小时**闭区间**，逗号分隔多项）；命中区间的用该阈值，未命中回落 `MIN_VOLUME`（20 万）。
- **未配置（默认空）= 行为 byte 级不变**；解析失败的片段**忽略**、`阈值 ≤ 0` **拒收** ⇒ 手误不会把量闸降为 0（fail-safe）。
- 只放量闸，**不动**价格/市值/换手/深度/费用/价差闸。**执行质量由既有 `EXT_ENTRY_MAX_SPREAD_PCT=1.0` 兜底** —— 早段价差大时它会把票拦下（实证：CBRL 盘前价差 **12.4%**，探针挂 bid 都不成交；CTAS **0.49%** 一次成交）。
- 两个决策 pass（dry 观测臂 + live 下单臂）**共用** `_min_volume_now(session)`，防"干跑漏斗 ≠ 实跑漏斗"。观测侧两处**有意**保留旧门槛（`prefilter` 影子的 `passes_current_gate`、near-miss 台账）：它们只记账不判定。

## 3. 反事实观测（"先可见再打磨"的落地）

每轮独立一行（**不进**闸计数主行的「空格分隔 k=int」契约）：

```
[ext_entry] 量闸分档[session] live门槛=20000 旧门槛=200000 分档放行=N 影子分档会放行=M 标的=...
```

- `分档放行` = 因分档而**过了量闸**、旧 20 万会拦掉的票次（= 本次改动到底放进了什么）。
- `影子分档会放行` = 盘后 16:xx 等**只配了影子档**的时段，若设 2 万会多放行的票次（下轮裁决的实数，零副作用）。

## 4. 预注册判据（写死在先，改判据要留痕）

**保留条件（复核日 2026-10-08，约 10 个交易日）——四条全过才继续开**：
1. 分档放行的票产生**真实早段入场 ≥ 3 笔**（在跑 ≠ 有单）；
2. 这些笔的**净额/笔 ≥ 0**（含往返费，费闸实值口径）；
3. **价差闸拒绝率未劣化**（早段薄盘的执行质量没被换掉）；
4. 无"薄盘事故"：未成交撕单率与滑点相对 08:00 后样本**不显著上升**。

**回滚触发（任一命中，不辩论）**：
1. 早段入场笔的平均往返价差 **> 1.0%**（说明价差闸没兜住）；
2. 早段入场 ≥ 3 笔且**净额/笔 < −$25**；
3. 未成交撕单率 **> 50%**；
4. `量闸分档` 观测行连续 **2 个交易日**缺失（可见性契约破坏 = 盲跑）。

**回滚动作**：删 `.env.us` 的 `EXT_ENTRY_MIN_VOLUME_BUCKETS` 行 → 下一 tick 生效（本链 cron 每轮新进程，**无需重启**）。

## 5. 明确禁项

1. **禁**顺手放开 08:00 之后（该段量已在 63x 起跳，20 万是合理门槛）；
2. **禁**把 afterhours 也一起放开 —— 先只用影子档攒证据，够数再裁；
3. **禁**用分档去替换财报事件门 / 方向判据（分档只解决"早段能不能过闸"，与"该不该交易这只票"无关）；
4. **禁**在早段放宽价差闸（价差闸是这条改动的安全绳，不是待优化项）。

## 6. 局限（随结论携带）

- 量分布口径来自**我们自己的候选池**（异动榜为主，微盘占比高）⇒ 绝对量偏小、不能外推到大中盘；大中盘财报票量更高（实证：KBH 盘后 29.2 万）。
- 4 个交易日的样本（402 轮）够定"结构性"，不够定"每档阈值最优"；阈值的进一步标定等观测数据。
- Cboe 分档是**全市场**口径，我们的是**候选池**口径，两者同向但不可逐字互证。
