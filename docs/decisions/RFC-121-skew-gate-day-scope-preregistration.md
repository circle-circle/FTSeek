     尚无任何已入库指令 → day-scope prior 必然 =(0,0)。日志实锤: 9/30 偏斜门 WARNING
     @21:05:55 CST = 13:05:55 UTC, 与主生成 created_at 12:35 UTC 同属一次 ~30min 生成
     (scheduler_core.py:1152 注: 单次生成 09:01→09:31 未完成), 非独立第二批。
  3. ⇒ **day-scope 逐字退化成 batch-scope, 方案 A 对 9/1–9/30 全历史是纯 no-op,
     救回 0 条**, 对触发本提案的 9/30 AMD/HPE 实例完全无效。
  4. **原核查报告 §3「批次局部≠组合全局」归因不成立**, 但 conf 倒置是**真的**, 真机制
     更深: 9/30 偏斜门日志报 **86% (=6B/1S)**, 而最终 DB 是 **9B/4S=69%** — guardrail
     当时看到的子集 ≠ 最终入库全体。AMD/HPE(conf=70, 被砍) 与 COIN/SNDK(conf=35, 存活)
     created_at 同为 12:35:31 却结局相反, 说明**存在多条写库路径 (DA bridge 直写 vs
     scanner 投票), 不同路径的指令进了不同 guardrail 视野** — conf 倒置根因是**路径
     覆盖不一致**, 不是"批次 vs 组合", 也不是"砍最低conf"设计本身 (设计没错, 是喂给
     它的数据不全)。**此为真正待查的 P2-5, 需独立立项, 不在本撤回 RFC 内仓促修。**

  (批次→组合/局部→全局) **必须先验证"更全局的作用域里是否真有被遗漏的单元"** —
  若生产侧本就是全量单次跑, "改口径"是伪命题。回放证据 (net/t 显著) 只证明
  "被砍人群事后表现好", 不证明"改这个门能救回他们"; 救援可行性是独立的时序问题。

## 附: 原始提案内容 (保留供审计, 结论已被上方撤回)

- **类型**: L2 行为变更 (guardrail 作用域修正) — **未实施**
- **预注册纪律**: 判据先于实施固化; 禁拿裁决后数据反推阈值
- **前置**: RFC-120 (chase_cap 倒挂) 已落地; 本提案独立, 不依赖

## 1. 病灶 (30 秒版)

偏斜门 `_trim_majority_direction` 按**单批次**算方向占比 (>80% 砍最低 conf 多数方),
但组合风险是**当日全局**的。批次局部偏多 ≠ 组合偏多 → 高 conf 单因"恰好在偏多的
那一批"被杀, 而更早批次的低 conf 单照常成交 = 结构性反向选择。

## 2. 历史回放裁决 (2026-09-01 ~ 09-30, replay_bars_daily 日K, entry→当日收盘同口径)

被砍人群 (skip_reason LIKE '方向偏斜%'): **n=45, 全部 conf=70, 全部 BUY**。

| 组 | n | net (毛,未含费) | avg | WR | t |
|---|---|---|---|---|---|
| **被偏斜门砍** | 45 | **+3,721** | +82.70 | 60% | **2.99** |
| 同日成交 conf≥65 BUY (对照, 同口径) | 26 | −475 | −18.26 | 46% | −0.88 |
| 全部成交单 (对照, 同口径) | 176 | −2,371 | −13.5 | 45% | — |

- **日匹配对照封死"强势日效应"辩解**: 对照与被砍在同 11 个交易日, 同口径下对照为负、
  被砍为显著正 → 不是"偏斜门只在上涨日触发所以被砍单都赚", 而是同一天里被砍的
  比成交的高 conf 单**更好**。
- **零重叠**: 45 条中同日同标的已有成交单 = 0 → 全是边际新增供给, 不是重复计数。
- conf 倒置实证: 被砍 45 条 **100% 是 conf=70**; 同期成交单含大量 conf 35-50。
- 诚实边界: ① 毛口径, 未含费/未含退出策略 (对照组同口径, 相对比较公平; 绝对值
  会缩水 — 成交人群同口径 −2,371 经真实退出后为 −238, 退出策略贡献 ~+12/单);
  ② n=45 单月样本, t=2.99 过显著线但非多周期验证; ③ 反事实无滑点/无成交概率折减。

## 3. 方案对比 (按建议排序)

| 案 | 内容 | 回放救回 | 毛收益 | 性质 |
|---|---|---|---|---|
| **A (推荐)** | 偏斜判定分母改**当日组合口径**: 本批 valid + DB 当日已有活跃指令 (非终态 skip 不计) 合并算占比; 仍 >80% 才砍 (照旧砍最低 conf 多数方) | 21/45 | +1,695 | 修尺子: 门保留, 只修作用域; 当日全局真 >80% 的日子照砍 (9/15,17,18,21,22,23 六天仍砍 24 条 — 保护意图不丢) |
| B | conf≥65 豁免偏斜门 | 45/45 | +3,721 | 放松风控: 高 conf 单不再有方向集中度保护, 行为变更面大 → 若选 B 须先 record-only 影子 30 天 |
| C | 维持现状 + record-only 影子攒样 | 0 | 0 | 不推荐: 8/14 裁决原则 — 历史可回放时直接回放裁决, 攒样只留给历史输入不存在的新组件; 本案回放已完成 |

**推荐 A 的理由**: 病灶定义就是"批次局部 ≠ 组合全局", A 是对病灶的最小修复 (做减法:
不加新门、不加豁免分支, 只把分母算对); 风险敞口增量受既有**单日 notional 帽 + 购买力帽**
双重约束 (救回 21 条不改变总仓位上限); B 的豁免逻辑与"不预测, 识别"哲学冲突 —
conf 是 DA 自评分, 用它豁免组合级风控 = 让被风控对象给自己发通行证。

## 4. 预注册判据 (裁决通过后才实施; 实施前不得改动)

1. **打标**: skip_reason 区分 `方向偏斜超限(day-scope B/S=x/y)` (新口径仍砍) 与
   放行不再打标; 砍单日志同时输出 batch-scope 与 day-scope 两个占比 (可审计)。
2. **转正判据** (30 天窗口, 2026-10-01 ~ 10-30):
   - 救回人群 (旧口径会砍、新口径放行且实际成交) 净 PnL (成交口径, 含费) ≥ 0;
   - 且救回人群执行率 ≥ 50% (对照 RFC-120 后合规组 ~70%, 低于一半说明放行也触发不了, 白改);
   - 且当日组合方向占比 >90% 的天数 ≤ 现状 +2 天 (防"实际变成单边市")。
3. **回滚判据** (任一触发即回滚, 回滚 = 恢复批次口径单行改动):
   - 救回人群净 PnL < −$500 (毛口径回放 +1,695 的 ~30% 容差外);
   - 或单日 notional 帽触顶频率翻倍 (说明救回单挤占了其他供给)。
4. **禁则**: 实施后 30 天内不得调整 80% 阈值本身 (阈值购物禁令); 救回人群与成交对照
   的周检并入既有周六 09:05 周检, 不新增 cron。
