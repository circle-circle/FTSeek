## ① 腿守卫缺口可见化 (推送升级)

### 问题

`102afe42d` 给 `release_unsettled()` 加的腿守卫**方向是对的** (意图 BOOKED 后无人
看护活跃 `pbe_*` 单 = 孤儿; `orphan_ext_order_watch` 只认 `ext_exit_` 前缀扫不到),
但它把"人工先撤腿"变成**隐性前提**:

仓已不在券商侧 + 我方腿仍非终态 ⇒ 释放被拒 ⇒ 该 symbol 继续进 `blocked_exits`
⇒ **SL 评估仍被跳过** —— 即 2026-10-01 US.ACN 病灶的变体 (当日 SL=223.16 越线
2.0pp 无保护 6 小时, 多暴露 42%: −244 可控 vs −347 最坏)。

而拒释放只落 `logger.warning` ⇒ 缺口躺在日志里, 值班人看不见。

### 修法

| 文件 | 改动 |
|---|---|
| `app/execution/exit_lifecycle.py` | `release_unsettled()` 增可选 `on_blocked` 回调; 事务内**只收集** `blocked_events`, 回调在**事务外**触发 |
| `app/core/position_sync.py` | 新增 `_push_release_blocked()` (走 `push_text_safe` 统一出口 + 15min 节流); helper 传 `on_blocked=` |
| `tests/test_exit_intent_external_release.py` | +16 例 (50 passed) |

### 两个设计约束 (都是踩过才写进去的)

1. **回调必须在事务外**: `transaction()` 用 `BEGIN IMMEDIATE` 持写锁, 推送的网络
   I/O 若在锁内会拖长持锁时间, 与 fast loop (10s 节奏) 抢锁。初版我把回调写在
   `with self.transaction()` 内, 已改。测试 `test_callback_fires_outside_transaction`
   在回调内尝试另开写事务来钉住这一点。
2. **推送文案里的命令必须真能跑通**: 初版写
   `release_stuck_exit_intent.py --symbol <SYM>`, 而脚本只有 `--intent-id` (required)
   ⇒ 值班人在 P1 现场照抄会撞 argparse 报错。**给错命令比不给更糟**。
   测试 `test_push_command_matches_script_cli` 双向钉住 (文案含 `--intent-id` 且
   不含 `--symbol`; 脚本 argparse 同步)。

### 为什么不自动撤腿 (明确不做)

撤单请求发出的瞬间该腿可能刚好成交 (**成交竞态**)。这是拿一个
**0 先例**的罕见形态 (生产 `exit_legs` 183/183 全 `TERMINAL`; 腿非终态而意图
BOOKED 的先例 0 条; 真幽灵仓分支历史触发 0 次) 换一个钱链上的新竞态面。

罕见 + 高危 + 可见 ⇒ 正确处置是"看得见 + 人工", 不是自动化。

### 节流

`_BLOCKED_PUSH_TS` (TTL 900s)。需要节流的理由: 真幽灵仓分支只
`DELETE open_positions`, **不调 `position_store.remove`** (external_close 分支才调)
⇒ 内存仓可留存 ⇒ 该分支可重入。实测该分支 0 次触发 ⇒ 节流是兜底不是主防线。

## ② ADR-044 UE 风险参数: 登记转正前置 (不改参数)

`241fba3c3` 给 UE 直写通道加了风险分层 (`risk_layering_enabled: true` 直接启用,
未走 shadow 预注册): 弱证据/PRICE_IN 标的 `stop 3.0% → 2.0%`、`tp 6.0% → 4.0%`,
ATR 只做上限 (`atr_stop_multiplier: 1.25`)。

**现在不构成风险**, 两条实测理由:

| 事实 | 数据 |
|---|---|
| UE 直写通道**零实弹流量** | 近 7 日 `UE-` 前缀指令 **281 条 / 执行 0 条**; 成交全归 DA (32) + un (3) + EXT (1) |
| 方向是**收紧** | `min(base, conservative)` 降档 + ATR 只做上限, 不放大风险 |

**登记的前置**: UE 直写通道转正 (开始真成交) **之前必须复核这组数值**。理由: 2% SL
落在 skill 已载的「<2% 是噪声扫损区」附近 (7/9 分桶实证 WR47% 亏 $1352), 且与
③ 的 MAE 分布对照 — 现行时代中位 MAE 仅 0.33%, 2% 档绑定率会显著高于 5% 档,
不是同一个"死参数"性质。零样本时无法攒 shadow ⇒ 只能登记前置, 不能现在裁。

## ③ 「振幅自适应 SL + 等风险仓位」轴: **否决, 不建影子**

用户 2026-10-01 提出"财报日波动大, 是否留足空间和时间"。我上一轮建议建
record-only 影子回放裁决。**跑完 skill 核心流程第 0 步 (绑定预检) 后撤回该建议** —
该轴是死参数, 建影子 = 给一把量不到东西的尺子攒样。

### 死参数三重检验 (全部命中否决)

样本: `trade_records` 932 笔有 `mae_pct`; 现行参数时代 (entry ≥ 2026-08-20, be_0.4
+ 方案A 稳定期) **283 笔**。单位纪律: `mae_pct`/`mfe_pct` 是**百分数** (5.0 = 5%)。

| 检验 | 结果 |
|---|---|
| ① MAE 分布 | 中位 **0.33%**, p75 1.28%, p90 2.85%, max 6.71%。**5% SL 触及率 2.5%** (7/283); 全史 1.0% (9/932) |
| ①b 分方向 | LONG 7/226; **SHORT 0/57** (空单侧 SL 完全不绑定) |
| ② 谁在决定出场 | `SL_BREAKEVEN` 46.6% (n=132, +921) + `SL_TRAIL_LOCK` 29.0% (n=82, **+4682**) = **75.6% 由 be/trailing 决定**; `SL_INITIAL` 仅 7.1% |
| ③ **参数在分布外** | MAE ≥ 7.68% (ACN 10/1 振幅档, 也是"放宽目标值") ⇒ **全史 932 笔 0 笔** |

③ 是决定性的: 把 SL 放宽到 7.68%, **历史上零笔会改变结局** — 没有任何一笔的 MAE
到过那个深度。放宽的不是"约束", 是一个从未被触碰的边界。

### 反证: "扛着会好"零证据

| 事实 | 数据 |
|---|---|
| `SL_INITIAL` 桶**无一笔盈利** | n=20, 净 **−2880.27**, 均 −144.01, **盈利笔 0/20** |
| "噪音杀" (SL 出场但该笔结局为正) | 现行时代 **0 笔**, 全史 **0 笔** |
| 病灶在入场不在 SL 宽度 | `SL_INITIAL` 出血笔 **19/20 MFE < 0.3%** (均 MFE **0.04%**) ⇒ 入场即错, 从未有过浮盈 |

⇒ 放宽 SL 对这些笔的作用只是**让它亏更久**, 不是"给波动留空间"。

### ACN 10/1 那笔为什么不构成依据

- **n=1 且方向恰好对** (留空间后从 −244 变 +5) ⇒ 选样谬误, skill 明令禁止据此改参数;
- 它的 MAE 7.10% 是**全史 932 笔中的 0/932 档** ⇒ 属分布外单点, 不是可推广形态;
- 且它的真实病灶是**意图卡死导致 SL 零保护** (已由 RFC-128 + `0f563afdc` 修),
  不是 SL 宽度不够 — SL=223.16 (距离 4.99%) 本身是有效的, 只是**没被执行**。

### 判据轴也错了 (与 ③ 独立)

Finnhub 证实 ACN 在 2026-08-01→10-05 窗口**只有 10/1 一个财报日**, 而 8/19 振幅
**7.8% > 财报日 7.68%** ⇒ "财报日"不是判别轴, 按它放宽会漏掉同量级的非事件日。
正确的轴是振幅/ATR — 但 ③ 已证明该轴上的 SL 参数本身不绑定。

### 真正的出血口 (杠杆点转移)

现行时代净亏排序:

| exit_reason | n | 净 | 均 MFE | 日内 SL 宽度能防吗 |
|---|---|---|---|---|
| `SL_INITIAL` | 20 | **−2880** | 0.04% | ❌ 病灶在入场 (19/20 MFE<0.3%) |
| `OVERNIGHT_GAP_STOP` | 7 | **−2176** | 0.12% | ❌ 隔夜跳空, 物理上防不了 |
| `tighten` | 3 | −452 | 0.02% | ❌ 同上, 入场即错 |
| `breakeven_lock` | 2 | −297 | 1.61% | — |

两大出血口 **−5056 全部与 SL 宽度无关**: 一个是入场质量, 一个是隔夜跳空。
⇒ 与 skill 既有结论一致 (MFE<0.3% 墓地净亏 ≈ 全部亏损 ⇒ 漏在入场, 退出线微调救不了)。

### 撤回声明 (横跳禁令要求注明证伪源)

我上一轮的建议"建 record-only 影子攒样"被本轮**绑定预检**证伪:
证伪源 = `trade_records.mae_pct` 分布 (n=932 / 283) + `exit_reason` 分布 +
`SL_INITIAL` 桶 0/20 盈利。撤回原因: 未跑 skill 核心流程第 0 步就提了影子方案。

**该轴状态 = 已否决 (不是"未裁决")**。复活条件 (需新证据, 不是新想法):
若未来出现 MAE ≥ 5% 的笔**且结局为正** (噪音杀) 累积 ≥3 笔, 或 SHORT 侧
出现 SL 绑定案例, 才重开。
