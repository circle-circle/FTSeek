## 摘要

一次多模型辩论（三个跨厂商 agent 独立攻击主会话诊断）击穿了 9 条推理链，并暴露两个系统性缺陷：
**(a) MFE 字段存在三套口径**（落库全程峰值 / 在线闸门 tick 峰 / 决策时刻 peak），语义不同却被混用，
消费面全是判据，**且决定 OKR KR2 的达标与否**；
**(b) W_WEEK 水下豁免把「当日完全没走方向」的仓也放行隔夜**，随后在隔夜跳空里各亏 5~6%。

本 RFC 实施三项**零交易行为变更**的改动：① 把 MFE 三口径分列落库 + 提供并列披露消费方；
② 判据字典新增 **A11** 把 KR2 死单率口径钉死为落库口径；③ 为 (b) 立**纯观测**影子（无毕业门），
并预注册"两轴命中集完全重合 ⇒ 本议题关闭"的自动结案条件。

## 问题陈述

### (a) MFE 三口径分裂

落库 `trade_records.mfe_pct` = `max(tick峰, bar峰, 已落袋)`，**出场时刻重算** ⇒ 含隔夜尖峰。
在线闸门（`app/playbook/exit_engine.py`）读的是 **tick 峰**；死信号/豁免判定读的是**评估时刻的 peak**。

实测（GLM-5.3 / Kimi-K3.1-Pro 独立复算 + 主会话日志对齐）：
- Kimi：DA 133 笔中 **84 笔（63%）** 落库 ≠ tick；
- 主会话：112 条死信号豁免事件逐笔对齐 DB ⇒ **91/111（82%）** 落库 `mfe_pct` > 日志里的决策时刻 peak
  （例：AVGO 日志 peak 0.00% / 落库 0.6029；MPC 0.00% / 1.3274；NBIS 0.02% / 0.7445）。

**消费面全是判据**：`symbol_streak_ban`（在线门，`intraday_indicators.py:264`）·
`close_flow.py:851` 的 `e60_ok`（≥0.3）· DEB 探针"墓地 MFE<0.3%"分档与 `eod_mfe_pct<0.5` ·
`app/review/bundle_builder.py:75` · `scripts/factor_ic_backfill.py:319` · `edge_weekly_report.py:215`。

**且它决定 OKR 自身达标判定**：KR2 死单率 **db 口径 17.29%（轻松过 23.0%）vs tick 口径 22.56%（贴线）**
⇒ **KR2 过不过取决于用哪个口径**，判据字典此前未写死。

佐证：仓内既有不变量 **I4_mfe_recalc**（重算 MFE 与落库值比，容差 0.05）当前 **19 行报警**
（例 `id=1737 AVGO mfe=0.4604 recalc=0.098`）—— 0.4604 是 bar 峰、0.098 是 tick 峰，
**这些告警一直存在却从未被归因**；本批新增两列后才可能被指向正确口径（改 I4 比较列 = 改监控判据面，须另落档，本批未动）。

### (b) W_WEEK 豁免把「从没对过」的仓放行隔夜

主会话日志实锤（`logs/ftseek_us.log-2026*.gz`；轮转语义：文件按 CST 日期收，ET 盘跨两个文件）：

```
2026-10-09 22:42 CST  US.SNDK LONG held=60min peak=0.03%<0.2% → [规则3.3-死信号·W_WEEK豁免]
2026-10-09 23:31 CST  US.AMD  LONG held=60min peak=0.07%<0.2% → [规则3.3-死信号·W_WEEK豁免]
2026-10-27 22:51 CST  US.CRM  LONG held=60min peak=0.08%<0.2% → [规则3.3-死信号·W_WEEK豁免]
```

三笔的**入场后 60 分钟 peak 仅 0.03~0.08%** ⇒ 它们活下来**不是因为 peak 过了 0.2%**，
而是被 `w_week_loser_exempt`（`app/playbook/overnight_decision.py:58`）放行 ⇒ 随后隔夜跳空各亏 5~6%。
豁免的裁决基础（2026-08-15 用户裁，n=15 多日回放修复率 73% vs 纯等 SL 53%）假设
「**水下 = 方向对但回吐了**」⇒ peak≈0 的单是「**从没对过**」，两类仓被混为一谈。

**由此撤回的原建议**：死信号阈值 `dead_signal_exit_mfe_pct` 0.2→0.3（曾估 ≈+$1,000）——
对这三笔**完全无效**（peak 0.03~0.08% 本来就 <0.2%，分支照样进入、照样豁免）；
Kimi 口径下真实可寻址上限 ≈$396。

## 变更内容

### 变更 1 · MFE 口径分列（零交易行为变更）

| 项 | 内容 |
|---|---|
| 加列 | `trade_records.mfe_tick_pct REAL`（tick 通道**全程**峰值）、`mfe_t15_pct REAL`（**入场后 15 分钟检查点**读到的 peak，覆盖速死族）、`mfe_gate_pct REAL`（**入场后 60 分钟检查点**读到的 peak，覆盖"整日没走"族）；单位均为**百分比**（3.72 = 3.72%） |
| 不改 | `mfe_pct` **语义保持不变**（全程峰值 = max(tick, bar, 已落袋)） |
| 写入 | `app/playbook/pipeline_parts/close_flow.py` 平仓 UPDATE 增三列 |
| 捕获 | `app/playbook/exit_engine.py` 峰值追踪后**无条件**捕获两个检查点（各取"首次达到该持有时长时"的 peak）；**不挂在 `dead_signal_exit_enabled` 开关下**（否则关掉该规则会连带停止采集 ⇒ 度量链断档） |
| 缺列容错 | 旧库/最小夹具 DB 无新列 ⇒ UPDATE 在 PREPARE 阶段失败（**无任何行被写**）⇒ 安全回退旧语句；**只吞 "no such column"**，其它异常照旧抛出 |
| 消费方 | `scripts/mfe_caliber_report.py`（三口径并列 + distinct 基数自检 + 填充率告警）—— **新列的唯一消费方**，防 write-only 字段（军规 P7） |

**不变式（AST 契约钉住，`tests/test_mfe_caliber_contract.py` 14 例）**：
① `mfe_pct` 仍取 max(tick, bar) + 已落袋兜底；② `mfe_tick_pct` **不加**已落袋兜底（镜像闸门读数）；
③ `mfe_t15_pct` / `mfe_gate_pct` 缺失留 **NULL** 不猜；④ **三个新列从不进入任何 Compare** ⇒ 只写不读判定；
⑤ 死信号条件 `peak_profit_pct < _ds_mfe_pct` 逐字未改；
⑥ **检查点捕获必须无条件**（不在 `dead_signal_exit_enabled` 分支内）—— 否则关掉该规则会连带停止采集、度量链静默断档（与 W2/W10 同族失效）。

**⚠️ 任何门禁改读新列 = 行为变更**（`symbol_streak_ban` / `e60_ok` / I4 / DEB 探针），
**须独立立项 + 影子先行**，本批刻意未动。

### 变更 2 · 判据字典 A11（KR2 死单率口径钉死）

**KR2 死单率 = 落库 `mfe_pct` < 0.3%**（A9/A10 口径）。
理由：① **与既有基线同轴** —— C12 的「入场即错」基率 **26.0%（mfe<0.3%）** 就是这个口径，
换口径会切断与历史基线的可比性；② KR2 的对象是"入场即错"这一**交易属性**，全程峰值最贴近该语义；
③ 换口径 = 改判据（判据字典 §使用规则 4）= 重新裁决。
**替代口径（tick / 闸门 / 决策时刻）仅作并列披露**，由变更 1 提供可算性。
**并记一条**：tick 口径下 DA 死单率 22.56%（贴 23.0% 线）⇒ 若将来改口径，达标判定会翻转。

### 变更 3 · W_WEEK peak 轴纯观测影子（**已降级**，无毕业门）

**原提案**（给豁免加 peak 下限 + 毕业判据）撞 **C11/C14/C15/C16/C17 五条终裁红线 +
B19 `eod_depth_gate` 已终裁 GATE_NOT_WORTH + B15 已存在隔夜臂判罪线** ⇒ 降级为纯观测：
人群 = `metadata_json.overnight_arm.source='w_week'`；只按 peak 分档记账；
**不改任何豁免行为、不设毕业门、不进任何 live 路径**。
**预注册关闭条件**：若 peak 轴命中集**完全含于** depth 轴（B19 同轴）命中集 ⇒ 本议题关闭
（同族换判据轴不产生新信息，不得再以同族理由重开）。
**为何仍值得观测**：peak 是**过程变量、时点早**（入场+60 分钟），depth 是**结果变量、时点晚**（EOD）
⇒ peak 轴可能触及 depth 轴触及不到的笔；该差异由影子实测回答，不靠推理。

## 副作用与已知边界

1. **本批零实盘、零 live 门、零四锁改动、零出场参数改动**（C1/C7：修尺子为主轴）。
2. **两侧口径并列 ≠ 已选边**：A11 钉的是**判据口径**，另两个口径只是把"换口径会怎样"变成可算的。
3. **② 影子不产生新信息即关闭**：这是预注册的自毁条款，不是"等攒够再说"。
4. **未做**：台账行（`docs/CONTROL-LOOP-LEDGER.md` 有另一 agent 在途 WIP，按军规不顺带上线）；
   I4 比较列改指新列（改监控判据面，须另落档）；任何门禁改读新列。
5. **本次多模型辩论的元结论**：多 agent 的价值在**审计/证伪**（本次抓出主会话自己一条错的头号建议 +
   两个口径分裂率 + KR2 达标与否取决于口径），**不在提高胜率**（DA 论据级 IC 仍 −0.0061）；
   ⇒ **不为交易收益建多 agent 决策层**，只建离线复核层。
