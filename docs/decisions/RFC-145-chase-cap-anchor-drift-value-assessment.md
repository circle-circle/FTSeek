# RFC-145: 锚漂移类的价值评估与处置路线

## 0. 本文件回答的问题

RFC-144 把"帽终态杀死"分成三类，主因是**锚漂移**（cap 锚在生成价、entry 被 reprice 逐轮上调后落到锚错误一侧，28/39 = 72%，10/1 起 8/8）。
当时给出的候选处置是 **P2「放宽闸」= 计划锚失效后以市价重锚一次 cap**（RFC-144 §2.3 我建议"先按预注册口径算干净再谈"，实测算不了）。
**本文不是再提一次那个机制，而是先做价值检查：这条过程值不值得做。结论：不值。**（§2）

## 1. 缺陷规模与暴露（实测，口径: `playbook_instructions` + `trade_records`，since 2026-09-01）

| 项 | 值 | 来源 |
|---|---|---|
| 帽终态杀死 | **39 条 / 33 交易日 = 1.18/日**（其中锚漂移 28 条 = **0.85/日**） | `skip_reason LIKE 'chase_cap_enforced%'` ∧ executed=0 |
| 同期实际成交 | 268 笔 / 33 交易日 = **8.12 笔/日** | `trade_records` (exit_time NOT NULL) |
| ⇒ 被帽吃掉的入场机会占比 | 约 **0.85 / (8.12+0.85) ≈ 9.5%** | 上两行 |
| 空转足迹 | `chase_cap_violation` **2167 轮 / 89 个 (指令,日) 对**；中位 10 轮、最大 71 轮、≥20 轮 40 对 | `data/shadow/pullback_limit_shadow.jsonl` |

## 2. 价值检查（决定性：救活这些入场值多少钱）

**单笔经济（since 9/1，n=268，全部已平）**

| 指标 | 值 |
|---|---|
| 均净 / 均毛 / 均费 | **−$2.38** / +$4.94 / $7.32 |
| 总费 / 总毛 | $1,926.37 / $1,300.12 = **费 1.48× 毛利** |
| 胜率 | 78%（204 赢 / 59 亏） |
| 均赢 / 均亏 | +$27.86 / **−$106.96** ⇒ **盈亏比 0.26 : 1**（4 笔大亏吃掉 15 笔小赢） |
| 净合计 | **−$626.25 / 33 交易日** |

**把缺陷类代入三种口径（28 条锚漂移若被放行）**

| 口径 | 假设 | 金额 |
|---|---|---|
| 乐观上界 | 按**全史**均净 +$12.26/笔（n=1010，**含 7/1 前旧时代，A10 口径本应剔除**，故此数只作上界不作预期） | **+$343 / 7 周 ≈ +$49/周** |
| 现实 | 按**同期(A10)**均净 −$2.38/笔 | **−$67 / 7 周**（救活反而更亏） |
| 唯一获许可的同轴读数 | D 案配对面 n=167（chase_cap/确认位等待轴） | 配对差中位 **−$10.61/笔**，日聚类 **t=0.75 / MDE ±$10.86** ⇒ **与 0 不可分辨**；误杀率 89/152=58.6%，但成交换手率 0.333 < 0.50、`wire_routing=false`（ADR-035 四条只过 2 条） |

**过程成本侧**

- 该轴既有机制足迹：**104 个文件**提及 `chase_cap`、**144 处**代码引用、专名脚本/模块多头（`entry_band.normalize_chase_cap` / `entry_routing.chase_cap_violated` / `auto_execute_flow` 归一+enforce+轮次 / 3 个测试文件 / replay 与 shadow 面）。
- P2 要新增的成本：重锚分支（代码+测试+审计字段）× 4 个待裁参数 × **再一次 prompt 指纹断基线** × **预注册判据所需的 40 配对样本/腿（数周）** × **前置的尺子修复**（fidelity reason_match 0.688 → ≥0.8，其失败桶如 `SL_TRAIL_LOCK(n=47, 复刻 0.298)` 属观测模型问题，是独立工程）。

**⇒ 判定：收益上界（$49/周，且需先证明这批入场优于平均）< 噪声与过程成本；现实口径为负；同轴获许可读数为 0；而放宽闸的代价正好落在尾部（均亏 −$107 那一侧，更差的入场价把 SL 距离拉开）。不建。**

## 3. 顺带翻出来的真问题（重新定义问题）

**瓶颈在费用线，不在入场门。** 费 = 1.48× 毛利、均净为负、盈亏比 0.26:1 —— 在这个尺度上，"0.85 条/日被帽吃掉（≈9.5% 入场机会）"是舍入误差：
- 每多救一笔**平均质量**的入场，期望是 **−$2.38**（必须先有 edge > 费用线，救量才有意义）；
- 该期真正的亏损来源是**少数大亏**（59 笔均亏 −$107），而不是"入场笔数不够"。

这与此前 8/22 的结论同向（"机制救毛利≈0，救不回费用；edge 必须 > 费用线"）。

## 4. 处置路线（按性价比排序，均不等尺子）

| # | 动作 | 行为影响 | 成本 | 理由 |
|---|---|---|---|---|
| **B1 推荐** | 新增 **record-only 机检** `chase_cap_anchor_headroom`：cap 对生成锚的余量 < 追价带宽（5%）时记一行"过紧帽"（含余量%、archtype、方向） | **零** | 极低（同 RFC-144 机检形态） | 给"帽太紧"这一假设攒**自己的**攒样面（成交率/被拦率/终态率），不碰 prompt、不碰执行 |
| **B2 待裁** | prompt 第二条：明确"cap 是计划锚附近的容忍上界；执行层可能 reprice 跟价，帽太紧会把计划自己锁死；拿不准就 **null**" | 改：**会改变生成出来的 cap 值域** | 低（但 = 第二次改 prompt；**今天正处于换指纹的空窗，搭同一窗口最省**） | 直击"帽 98% 被填、仅 36% 有文本依据（≈2/3 自造）"。**须先用 B1 的面看现状分布再改**，否则又是一次无对照的改测量系统 |
| **B3 推荐** | 把"同指令 ≥20 轮空转 且当日 executed=0"作为 **DA 生成质量指标**（不新增机制：数据已存在 `pullback_limit_shadow.jsonl` / 遥测） | 零 | 极低 | 2167 轮 / 89 对的空转是**真实**噪音成本，而它可被"别产出会被自己帽锁死的计划"这条生成侧修法改善（RFC-144 已治自相矛盾子类 8 条） |
| ❌ P2 重锚机制 | 计划锚失效后以市价重锚 cap 一次 | 放宽闸 | 高 | §2 判定不值；且"cap 追价 = 门恒放行 = 静默废闸"（`auto_execute_flow.py:840-843` 原话） |
| ❌ 任何"为救 28 笔"的执行侧改动 | — | — | — | 同一数据前提（无获许可的尺子） |

**尺子修复（fidelity reason_match ≥0.8）单独排期，不与本文绑定** —— 它服务的是 ADR-035「限价 vs 市价入场」这条更大的决定（现 2/4 过、接线关闭），不该被一个 $49/周 的问题拖着做，也不该因为它没修好就让本文结论悬空（本文结论用的是同期实测经济与获许可的 L1a 读数，不依赖尺子修复）。

## 5. 重开条件（写死，防以后凭感觉复活）

同时满足才允许重提 P2：
1. A10 期均净转正且**费/毛 < 1.0**（当前 1.48）；
2. D 案尺子获许可（`reason_match ≥ 0.8`）且配对 n≥40/腿、同尺配对差双侧可分辨；
3. 该人群（锚漂移型）在**新**预注册面上显示优于系统平均质量（而非"T+1 开盘基准 +3.31%"这类含追涨选样偏差的读数）。

## 6. 回滚
B1/B3 为纯观测（新增字段/指标），回滚 = 删机检/指标；B2 未落地前无回滚项。
