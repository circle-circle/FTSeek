# RFC-141: 入场延迟确认门 SIM 实弹前瞻 (D2' forward)

- 日期: 2026-10-10
- 状态: **已批准执行** (用户裁「同意执行」, 2026-10-10 会话)
- 类型: L3 新特性 (行为变更: SIM 期入场时序)
- 载体: `app/playbook/entry_confirm_gate.py` + `auto_execute_flow.py` 两点接线 + `_playbook_exit_fast_loop` sweep
- 配置: `playbook.execution_parameters.entry_confirm_{enabled,delay_sec,holdout_pct,ttl_sec}` (扁平键, 与 entry_open_blackout_* 同节) (热重载穿不透, 改动须 restart)
- 关联: DEB-20260909 §5.2 (D2' 原判据) / DEB-20261009 §27 缺陷1-B、§28、§31 (载体节奏+前瞻裁决) / RFC-081 (原预注册) / RFC-123 (双锚, 阶段1 裁决中) / DEB-20261008 (confirm_gate 反向先验披露)

## 1. 一句话

触发后让子弹飞 120 秒: 价格仍站**执行锚**同侧 → 放行照常进场; 反转 → 记 `ABANDONED` 放弃 (落 guardrail SKIP `entry_confirm_reversed`)。**全量走门** (`holdout_pct=0`), 结果看富途 app 上的 SIM 真实盈亏, 不靠影子攒样。

## 2. 为什么是 SIM 实弹而非 record-only (形态裁决留痕)

DEB-20261009 §32.2-3 原裁「保持前瞻影子」。本 RFC 是对该条的**形态升级**, 不是绕过:

1. 影子与实弹的载体代码同源 (pending 状态机/sweep/锚冻结/遥测), 差别仅一行执行分支;
2. 门的方向 fail-safe: 只拦入场不碰持仓, 最坏情况 = 少开仓; SIM 期无真实资金;
3. **信息量严格更大**: 门后的成交是真实 SIM 成交 (富途 app 可见的盈亏), 影子回放给不了 (bar 反事实出场原因一致率仅 60–63%, §28.8);
4. **用户 2026-10-10 点名口径** (原话): 「富途 app 上目前的链路交易, 盈利和亏损是可见的, 我的本意是直接走 sim 交易链路, 不用影子攒样看 sim 交易结果」⇒ 裁决源 = SIM 真实盈亏。
   ⚠️ 同日我一度把「可见」误解成 dashboard 展示面, 已按用户纠正撤销 (dashboard 是 live 实盘交易面, 不承载 SIM 观测); 真可见面 = 富途 app + 结算器读数。

**风险对价与处置**: 实弹门改变 SIM 交易行为, 而 ALL 人群历史回放是平的 (t=−0.16) ⇒ 直接裸开等于掷一枚历史证据约等于平的硬币。故:
- 判据全部门前预注册 (§4), 达标前**不得转正 REAL**;
- 原设计的 20% holdout 对照臂 **已按用户裁归零** (留对照臂会稀释 SIM 结果, 与「看 sim 交易结果」冲突)。代价 = 无同期对照臂、受市况混淆, 处置见 §5.4 (以判据 1∧3 机制量为强证据);
- 若要更硬的因果证据, 唯一低成本做法是把 holdout 改回 5–10 (机制 inert 保留), **需用户再裁, 不自动开**。

2. **开盘窗净均改善**: 开门后 09:35–09:45 每笔净均 > −$2.2632 (v2 BASE_OPEN_WIN, 比 v1 的

   ⚠️ **t 门槛单独钉住 v1 严值**: v2 基线 t = −0.3849 比 v1 的 −0.3218 更负, 若跟基线走

3. **机制量达标**(不随市况漂, 来自 jsonl 留痕): 避免率 (ABANDONED/ok) ≥30% ∧

   判据: 开门后非 SL_INITIAL 族每笔净均 ≥ +$9.7353 的 80% (即 **≥ +$7.79**), 防门把好单也拦掉。
   **两端同尺 (见 §5.6)**: 上述基准含 2 笔 fee_bps>100 的费用异常单 (CTNT 915.1 / GIPR 203.6,

   = **+$10.9854/笔** ⇒ 剔费地板 = **+$8.79**。**裁决以剔费口径为准** (剔费样本 vs 剔费地板),
   全量口径只并陈; 若用「干净样本 vs 含异常单的低地板」比, 判据④ 偏松 ⇒ 门可能白过。
   地板精度取 2 位 (与本文本逐字一致): 全量 +$7.79 / 剔费 +$8.79。
   **v2 使判据④ 门槛抬高 2.8 倍**(+$2.79→+$7.79): v1 窗口的 BASE_REST 是 +$3.4852(t=+0.21
   不显著), v2 是 +$9.7353(t=+2.47 显著正)⇒ v1 地板严重低估了「不伤赢家」的真实要求,
   门只要做到 +$2.79 就算过 = 允许把赢家表现打掉 71%。

**分层只印不判** (防只挑有利层报数): R1-forward SHORT×开盘窗 (session_min 0–15)、
LONG×开盘窗 —— 只印读数, 不作独立裁决依据。

**裁决三态**:
1. 判读 1∧2∧3∧4 全过 → 呈用户裁: SIM 常态化 / 是否谈 REAL (REAL 另须本 RFC 修订+签字, 不自动);
2. 判读 1 过但 2 或 4 不过 → 不行动, 数据留档, 轴维持 OBSERVING (病灶对了但总量没转好);
3. 判读 1 明确不过 (n 达标而 SL_INITIAL 族强度未收敛) → 轴 KILLED, enabled=false, 产物留档。

**速率预估**: 近窗 ~7.5 触发/日 ⇒ n≥60 约 2 周; 但 SL_INITIAL 族基线仅 29 笔/3.5 月
(≈0.4 笔/日) ⇒ **判读 1 需要更长窗口才能看出族收敛**, 这是本设计的真实限速环节, 不得
用「样本不够」当通过理由, 也不得提前改用其它判据替代。

## 5. 强制披露 (沿 D2' 影子注册条目原文)

1. **反向先验**: confirm_gate (UE 域盘前注入趋势) 历史成本 +0.50%/笔 t=5.67 —— 域不同 (盘前注入 vs 开盘窗微结构), 方向相反, 裁决时必须并陈;
2. **ALL 人群回放是平的**: 580 行 t=−0.16 不可区分, 误杀 58%; 达标证据全在 SL_INITIAL 事后族 (65.5%/误杀0/t=4.92), live 门无法事前只对它开 ⇒ 前瞻 ALL 读数可能同样平, 这是本实验的真实风险, 不是缺陷;
3. E3 PULLBACK_LIMIT TTL 互斥: 当前路由 disabled 无冲突 (C8), 启用前须裁。
4. **无同期对照臂 ⇒ 市况混淆** (2026-10-10 用户裁 holdout_pct=0 的对价): 裁决变成
   「开门后 vs 开门前」, 若开门那几周大盘转好, SIM 改善可能不是门的功劳。缓解 =
   判据 1 (病灶族收敛) 与判据 3 (避免率/机会成本) 是**门自身机制量**, 不随市况漂;
   判据 2/4 才受混淆 ⇒ 裁决时以 1∧3 为强证据、2/4 为弱证据, 且必须并陈当期市况。
   若要更硬的证据, 唯一低成本做法是把 `entry_confirm_holdout_pct` 改回 5–10
   (机制 inert 保留), 代价是稀释 SIM 结果 — 需用户再裁, 不自动开。
5. **判据 1 是限速环节**: SL_INITIAL 族基线仅 29 笔/3.5 月 (≈0.4 笔/日), 而样本门
   n≥60 约 2 周即到 ⇒ 会出现「总量样本够但病灶族样本不够」的相位。此时**不得**用
   「样本不够」当通过理由, 也不得改用其它判据替代; 结算器会如实输出 INSUFFICIENT/
   OBSERVE, 裁决须等族样本到位。
6. **判据④ 必须两端同尺 (费用异常单)**: `scripts/deb20261009_fee_anomaly_sensitivity.py`
   (只读) 实测基线窗 [2026-06-24, 2026-10-10) n=632:
   - 判据①② **稳健**: SL_INITIAL 族 (n=29) 与开盘窗 (n=324) 内 fee_bps>100 的笔数
     **均为 0** (SL 族 fee_bps 最大仅 19.9) ⇒ 这两条基线不被费用单决定;
   - 判据④ **不稳健**: 非 SL_INITIAL 族 (n=603) 内有 3 笔 (CTNT 915.1bps / GIPR 203.6 /
     NVDA 198.6), 全量净均 +$3.4852 → 剔后 +$4.3340 ⇒ 全量地板 +$2.79 被低估
     +$0.68/笔 (24.4%)。
   **规则**: 结算器对判据④ 同时算两套 — `c4` (剔费样本 vs 剔费地板 +$3.47, **裁决用**)
   与 `c4_full_caliber_also_printed` (全量样本 vs 全量地板 +$2.79, 只并陈)。禁止
   「干净样本 vs 含异常单地板」的混合比较 (那是判据偏松, 门会白过)。
   `fee_bps = fees_est / (entry_price × quantity) × 10000` 是**事前可算**量 (不同于
   MFE 门要事后才知道), 阈值 100bps 沿用 §27 缺陷3 与已实装的 `W8_fee_bps_anomaly`
   同口径, 不另造阈值 (防阈值购物)。
   **附带更正 §27 缺陷3 的适用域**: 其「净符号由 2 笔仙股决定、剔除后翻转」在本基线窗
   **不复现** (全量 −$3.9205 → 剔后 −$3.1461, 仍为负; 翻转发生在其自身 n=172 窗口)
   ⇒ 该结论是窗口特异, 不得推广。费用/毛利 = 3.1847× (毛利 +$1,134.12 / 费用 $3,611.86),
   与用户 8/22 已证伪的「执行纪律可保底」同向: edge 必须 > 费用线, 退出参数微调救不回费用。
