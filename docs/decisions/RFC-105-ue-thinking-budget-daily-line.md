## 2. 改动（最小面）

1. `scripts/daily_llm_token_report.py` 新增 `UE_BUDGET_ANCHOR` / `UE_FEATURE` /
   `UE_BUDGET_BASELINE` 常量与 `_query_ue_budget(conn)`，并在 `_build_message` 末段输出常驻一行：
   ```
   ── UE 思考预算 (glm-5.3 强制思考, 修复锚 9/18 起累计) ──
   主调用 10 次 | 触顶 0 (0%) | 最大 out=9662 | 中位延迟 63s | 失败 0 | 兜底 0 次 | 降档重试 0 次 → 判定: 改善 (改前基线 6/9=67%)
   ```
2. 档 `data/llm_token_daily_<day>.json` 增 `ue_budget` 键（供事后复算，不参与任何判定）。

**口径三条**（都写进 docstring，防下一份文档读错）：
- `downshift_retry` 行 = 同一轮的降档重试臂 ⇒ **不入分母**（否则一次触顶记两次；实测 5 行↔3 事件）；
- 兜底行（非 glm 模型）**单独计数** —— 主模型失败由 fallback 作答，对下游不可见，必须可见；
- 延迟取**主调用中位数**（含触顶行会拖高；触顶行本就最慢）。

## 6. 裁决留痕：换档 A/B 结果 + 用户裁定（2026-09-24）

用户令「先跑一轮同材料 A/B（3 轮×2 模型）再定」→ 已跑 → 用户裁 **「保持不动」**（当日）。
留痕目的：防同一提案被后来的 agent 重新提起（否决结论必须带证伪源）。

| 维度 | glm-5.3（现役） | glm-5.3-prime | 读法 |
|---|---|---|---|
| TPS（Σout/Σwall，n=5/臂） | 90.5 tok/s | 107.5 tok/s | +19%（官方宣称 1.5–2× 的下沿） |
| 延迟 p50 / mean / max | 84.6 / 79.7 / 89.7s | 60.3 / 68.8 / **105.6s** | 中位更快，但**尾部无界**：prime 最慢那轮 (=它吐 11299 tok) 比 glm-5.3 最慢还慢 |
| 触顶 / schema / 契约违约 | 0 / 3-3 / 0 | 0 / 3-3 / 0 | 无差异（截断问题与加速档无关，已由 §1 的 reasoning_effort 修好） |
| `invalidation_triggers` 填充 | 50%（20 items） | 67%（15 items） | n=3 ⇒ 在噪声内，**不构成证据** |
| 成本 | ¥0.246/轮（¥8/¥28） | ¥0.44–0.50/轮（¥16/¥56） | 1.8–2.0×（UE 3 轮/日 ⇒ ~¥16→~¥29/月） |

裁决理由：① 换档原始理由（截断）已被证伪；② Prime 是**同模型加速档**，非能力升级，质量面无差异；
③ UE 延迟 p50 63s 不在关键路径上，买到的 25s 不改变任何窗口时序；④ 尾部（9/22 那次 433s）本次 A/B
两臂均未复现，Prime 不承诺约束尾部。

**重提条件（写死，满足才可再问）**：UE 生产延迟出现**连续 ≥3 次 > 300s** 的量级恶化（而非单次离群），
或 UE 被移入盘中关键路径（当前是盘前供料）。届时先做「同臂对照 + workspace 域名对照臂」
（本次无法从外部证实是否真进了 Prime 加速档，见 §7 局限），再谈换档。

## 7. 局限（诚实披露）

- A/B n=3（质量面）+ n=5（速度面，含 2 轮探针），单材料（1 份 brief）、单时段 ⇒ 质量维度无统计力，
  速度差虽方向一致（5 轮中 4 轮 prime 更快）但**未能区分**「Prime 服务档」与「服务端瞬时波动」；
- 文档要求 Prime 走 workspace 专属域名，本账号用共享 endpoint 亦可调用 ⇒ **无法外部证实**调用真的落在
  加速档；若将来换档，须补一组 workspace 域名对照臂；
- prime 侧同样强制思考（`enable_thinking=false` → HTTP 400 `restricted to True`），现有 `extra_body` 原样适用
  （这一条是换档可行性的关键前提，已实测）。
