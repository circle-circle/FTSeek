# 实时价权威入口审计（2026-09-21）

**起因**：2026-09-20 数据面审计 P0-2 —— "实时价两条路径并存，没有'单一实时价函数'加断言"。
本文用一把可重跑的尺子把这句话变成实测数字，并**实测证伪了其中一个我原本准备报为严重缺陷的假设**。

工具：`scripts/realtime_price_authority_audit.py`（只读，`--json` 供机器消费）。
产物：本文 + 脚本内 `VERIFIED` 登记（逐条读码裁决，带理由）。

## 1. 实测分布（`app/` 全仓，价格字段读取点 180 处）

| 分类 | 处数 | 含义 |
| --- | --- | --- |
| `AUTHORITY` | 28 | 处于已认可的实时价获取链：`broker_adapter.get_current_price` / `market_data_router.get_quote` / `futu_lv3_provider` |
| `GUARDED` | 13 | 附近有显式降级/警示（"降级"/warning/fallback）—— 知情使用 |
| `T1_OK` | 28 | 有 T-1/盘前/上一交易日 口径声明 |
| `FILL` | 7 | 读的是成交回执/订单明细价（`deal.get('price')`）—— 非"实时价"语义 |
| `NORMALIZED` | 97 | 读的是本仓规范化 context/quote 的 `price` 字段 —— 非券商快照字段 |
| `VERIFIED` | 7 | 已逐条读码裁决（见 §3） |
| `SNAPSHOT_SUSPECT` | **0** | 读券商快照/K线字段且无口径说明 |

**结论（对 P0-2 的正面修正）**：下单期取价确实是**单一链路**——
`order_executor._get_current_price`：①适配器实时价 → ②`data_router.get_quote` 的 **bid/ask 中间价** →
③才降级 `price`/`last_price` **并打 WARNING**。没有"两套实时价互相冒充"的形态；
读券商快照的 7 处已全部有裁决，无未判定的无口径读取。

**另一处要修正原报告的地方（正面）**：入场资格门**已有报价新鲜度断言**——
`app/playbook/candidate_eligibility.py:107-112` 要求候选记录带 `quote_age_sec`：
缺失、为负 5s 以下、或 > `entry_max_quote_age_sec`(默认 90s) 一律拒绝（fail-closed）。
所以缺的不是"断言"，而是"单一取值函数 + 该断言的覆盖面"。

## 2. 实测证伪：`premarket_invalidation` 不是"T-1 假死门"

**假设**（读码时形成，准备报为严重缺陷）：`premarket_invalidation.py:117-128` 用
`futu.get_snapshot()` 的 `last_price - prev_close` 算涨跌幅；若盘前快照 `last_price` 是 T-1 收盘，
则 `chg_pct ≡ 0` ⇒ A/B/C 规则**永不触发**（假阴性死门）。

**实测**（`data/premarket_invalidation_shadow.jsonl`，396 条 / 27 个交易日）：

| 检验 | 结果 | 判定 |
| --- | --- | --- |
| `|chg_pct| == 0` 的记录 | **0 / 396（0.0%）** | 假设**不成立** |
| 中位 `|chg|` / p90 / max | 1.54% / 7.05% / 109.6% | 取到的是**真盘前价** |
| `would_invalidate=True` | 44 条 | 规则有触发，非死门 |

**撤回**：该假设证伪，不作为缺陷上报。教训与 2026-09-20 那条一致——口径假设必须先用产物分布验，
不能凭"字段名 + 上一次的纠正"外推（`get_market_snapshot` 的 T-1 现象不适用于
`futu_lv3_provider.get_snapshot` 这条链）。

## 3. 但实测带出一个真问题：相位与口径不一致（`premarket_invalidation`）

实测同一份产物的时间戳分布：**396 条全部落在 09:35–09:47 ET**（`08-11` 至 `09-18`，日均 ~1 次），
方向分布 BUY 323 / SELL_SHORT 73。

- 09:30 ET 已是**常规时段开盘**⇒ 这些记录用的 `last_price` 是**盘中价**，不是盘前价；
- 而该影子登记在案的问题是"**盘前口径增量**"（注册表 `premarket_invalidation` 条目；
  `B_long_knife` 执行时刻硬门已在线 RFC-068，其判据针对盘前口径增量）。

**影响（口径缺陷，不是数值错误）**：该影子积累的 396 条证据回答的是"**开盘后 5–17 分钟**的涨跌幅
能否预测该笔交易该被禁入"，而登记要回答的是"**盘前**失效口径"。二者不可互相冒充：
（a）若据此 396 条裁决 A/B/C，等于用盘中数据给"盘前门槛"背书；
（b）真正的盘前窗口（预定开盘前的决策时点，即 ETH 链）**从未被该影子采样**。

**处置建议**（未执行，待裁）：裁决前先定谳这条影子的**实际相位**，二选一——
① 承认它是"开盘后 N 分钟失效门"并**改判据文字 + 改登记名**（改判据 = 重新裁决，须留痕）；
② 保留"盘前"口径，则需在盘前时段另跑一次采样，现有 396 条**不得**计入该判据。

## 4. 次要项：`market_state` 的 SPY 读取缺就地口径注释

`app/analysis/market_state.py:95` `spy_price = snap.iloc[0].get("last_price", 0)` 用于
`regime`（SPY vs MA200）判定：**日线级**语义，盘前取到的是上一交易日收盘，逻辑成立，
但代码里没有像 `vix_source`（"盘中用实时报价 / 盘前盘前价 / 盘后与周末回上一交易日收盘"）那样
就地写明口径。建议照抄 `vix_source` 的写法补一行注释——**零行为变更**，只防后人误用。

## 5. 工具的长期用法（避免每次重新人工过一遍）

- 已裁决的站点写在脚本 `VERIFIED`（文件 → 理由）；**未判定面从此只报新增的无口径快照读取**，
  即"回归探测器"。
- 出列方式：读码 → 若确认无害，加进 `VERIFIED` 并写理由；若确有 T-1 风险，就地补口径注释
  （进 `T1_OK`）；若既无注释又确属决策路径且口径可疑，留在 `SNAPSHOT_SUSPECT` 并要求定谳。
- 首版教训（已写进脚本注释）：以"变量名含 snapshot/df"作判据会把本仓自造的规范化字典
  （`facts`/`analysis['snapshot']`）误报成 T-1 风险——首跑 111 条候选里 104 条是噪声。
  **静态启发式只能产出候选，结论必须逐条读码**（7 条已读，其余 173 处按类归档、未逐条读）。
