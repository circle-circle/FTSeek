## 二、策略流程冲突检查

### 2.1 跨市场套利策略流程

**时间线**:
- 09:00 - 盘前分析，生成信号
- 09:10 - 钉钉推送计划，用户审核
- 09:25 - LLM预分析，倒计时5分钟
- 09:30 - 开盘执行，自动执行未否决信号
- 10:00 - 退出清理，趋势策略接手

**主导权管理**: 通过 `TransitionManager` 实现平滑交接
- `ARB_DOMINANT` (09:30-09:50): 跨市场策略主导
- `TRANSITIONING` (09:50-10:00): 过渡期
- `TREND_DOMINANT` (10:00-16:00): 趋势策略主导

### 2.2 趋势策略流程

**时间线**:
- 全天运行 (09:30-16:00)
- 在ARB_DOMINANT阶段被延迟5分钟
- 10:00后完全接手

### 2.3 冲突避免机制

✅ **已实现以下机制确保无冲突**:

1. **时间窗口隔离**: 跨市场套利仅在09:30-10:00运行
2. **主导权管理**: TransitionManager判断当前主导策略
3. **信号协调**: SignalCoordinator解决多信号冲突
4. **缓存隔离**: LLM预分析使用独立的SCHEDULED缓存键
5. **共识引擎集成**: LLM结果作为置信度调节因子，不直接决策

**结论**: ✅ 跨市场套利与趋势策略流程**无冲突**

## 六、注意事项

### 6.1 推送限流

钉钉机器人限制每分钟最多20条消息。当前实现:
- 09:10 推送计划: 每个标的1条 (假设10个标的 = 10条)
- 09:25 推送汇总: 1条
- 09:25~09:29 推送详情: 每个标的1条 (假设有方向性的15个标的 = 15条)

**可能超限!** 建议:
- 减少详情推送数量（仅推送高置信度标的）
- 或者增加推送间隔（当前0.3秒）

### 6.2 消息长度

钉钉markdown消息限制4096字符。当前实现:
- 汇总推送已截断到4096字符
- 详情推送单条约1500-2000字符，安全

### 6.3 LLM预分析时间

09:10推送计划时，LLM预分析(09:25)尚未执行，因此:
- `send_cross_market_plan()` 的 `llm_assessment` 参数为 `None`
- 09:10计划卡片中**不会显示**LLM预分析板块
- 如需在09:10就显示LLM分析，需将LLM预分析提前到09:05

**当前设计**: 09:25的LLM预分析结果仅在汇总和详情推送中展示，不影响09:10的计划卡片。
