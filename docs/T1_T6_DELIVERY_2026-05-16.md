## 2. T5 详解 (信号质量, 核心)

### 2.1 问题 (修复前)
`signal_pipeline._build_signal_from_vote` 收到 IntradayScorer 输出 (含 trend=0.25, volume=0.18), 转为 SignalScore. 该 signal 进入 `ConsensusEngine.generate_consensus` → `SignalScorer.score()` 再算一次 trend_confirm=0.20 + volume_confirm=0.15.

**实际权重**: trend = 0.25 (一层) + 0.20×系数 (二层) ≈ 0.40 ; volume 同理 ≈ 0.32.

### 2.2 修复
两步:
1. **传递因子明细**: `_build_signal_from_vote` 把 `vote_result["_factor_detail"]` 注入 `signal.metadata["_factor_detail"]`.
2. **二层检测**: `SignalScorer.score` 启动时检查 `metadata._factor_detail` 是否含 `trend.conf>0` 或 `volume.conf>0`, 若有则将 `weights["trend_confirm"]=0` / `weights["volume_confirm"]=0`.

```python
# signal_scorer.py:66
upstream_factors = signal.metadata.get("_factor_detail", {})
if "trend" in upstream_factors and upstream_factors["trend"].get("conf", 0) > 0:
    weights["trend_confirm"] = 0.0
if "volume" in upstream_factors and upstream_factors["volume"].get("conf", 0) > 0:
    weights["volume_confirm"] = 0.0
logger.debug("[scorer·T5] upstream factors → 二层权重置 0")
```

**结果**: 6 个本层独有因子 (volatility_fit/market_align/history_performance/news_sentiment/regime_fit/risk_reward) 仍正常工作, 但 trend/volume 不再被 2× 加权.

### 2.3 风险
- 历史信号库 (5/15 前) 是基于双计权重训练的, 切换后单笔信号 strength 可能整体下移 ~10-15 分.
- 解决: 模拟盘验证 7 天数据, 必要时调整 `strategies.defaults.min_strength: 25→20` 补偿.

## 4. T4 详解 (multi-bucket 占用消除)

### 4.1 修复前 (5/15)
```
22:30 ScalpingEngine ARM SHORT → 写 scalping 桶 (无 lock check)
22:35 ScalpingEngine ARM SHORT 再次 → 重复占 scalping 桶
21:30 MAIN_PIPELINE ARM SHORT → 写 main 桶 (lock observe_only 不阻断)
→ 总敞口 = scalping 0.10 + main 0.20 = 0.30, 实际只有 1 个方向 thesis
```

### 4.2 修复后 (sandbox 启用时)
- `scheduler_core.py:670`: sandbox 启用时强制 `observe_only=False`, banner 显式提示.
- `order_executor.py:1872`: 主线在 arbitrate 后申请 `coord.lock.acquire(symbol, "main")`, 已被占用 → 拒下单.
- `scalping/engine.py:2387`: scalping 在 arbitrate 后申请 `coord.lock.acquire(symbol, "scalping")`, 主线持有则放弃.
- `scalping/engine.py:2752`: scalping 平仓释放 lock.
- 主线平仓走 `coord.on_position_closed()` 已含 `lock.release()`.

**结果**: 同标的同时刻 1 owner. 5/15 ARM 3 笔将变为 1 笔 (赢家未必是 706 的 +$1219, 但敞口可控).

### 4.3 风险
- ScalpingEngine 高频性可能让 main 持续被锁外, 失去主线机会.
- 缓解: scalping 平仓快 (30min 内), main 短时间内可恢复.
- 监控: `coordinator_status.py --all` 看 `OBSERVE_CONFLICT` 转 `DENIED` 比例.

## 5. T6 详解 (周期 reconcile)

### 5.1 触发
后台线程 `T6CapitalReconcile`, 每 `strategies.coordinator.reconcile_interval_sec` (默认 300s) 一次:
1. 从 `PositionStore.all()` 读真实持仓
2. 按 `owner_strategy` 分组累计 `market_value / equity`
3. 调 `coordinator.capital.reconcile_with_positions(by_strategy)` 校正账本

### 5.2 实际效果 (理论)
若中途某笔平仓未触发 `on_position_closed` (例如 broker 直接平仓 + 30s sync 后 PositionStore 移除), capital_allocator 桶占用会漂移. T6 周期校正这种"幽灵桶占用".
