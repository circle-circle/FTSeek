# FTSeek 每日动态作战池方案

## 核心问题诊断

**当前状态（2026-04-30）：**
- 监控股票：21只
- 实际持仓：11只（超出 max_positions=5 限制）
- 总市值：~10,946,645 HKD
- 初始资金：1,000,000 HKD
- **当前仓位：1094.7%** （严重超标）

**根本原因：**
1. 动态仓位模式将 max_positions 设置为股票池数量 (21只)
2. 缺乏每日聚焦机制，信号驱动盲目开仓
3. 无作战计划门禁，所有股票同等对待
4. 资金分配无层级差异

---

## 方案设计原则

### 1. 聚焦原则
- **作战股票 ≤ 3只**：每天只交易评分最高的 3 只股票
- **兜底股票 ≤ 3只**：当作战股票信号不足时启用
- **每日总活跃 ≤ 6只**：降低行情分析压力

### 2. 分层原则
| 层级 | 名称 | 数量 | 仓位比例 | 特征 |
|------|------|------|---------|------|
| Tier1 | 核心龙头 | 3只 | 8% | 恒指成分、高流动性、南向资金 |
| Tier2 | 高弹性成长 | 2只 | 6% | 行业龙头、成长性强、催化剂 |
| Tier3 | 事件驱动 | 1只 | 4% | 技术突破、高波动、短期机会 |

### 3. 资金分配
- **初始资金**：1,000,000 HKD
- **最大暴露**：75% (750,000 HKD)
- **现金储备**：25% (250,000 HKD)
- **单只上限**：8% (80,000 HKD)
- **最大持仓**：5只

**示例分配（3只作战）：**
```
作战#1 (Tier1): HK.00700 → 80,000 HKD (8%)
作战#2 (Tier1): HK.09988 → 80,000 HKD (8%)
作战#3 (Tier2): HK.01347 → 60,000 HKD (6%)
总暴露：220,000 HKD (22%)
现金储备：780,000 HKD (78%)
```

## 执行流程

### 盘前 (08:30)
1. **数据收集**：获取所有 21 只股票的 K 线、成交量、新闻
2. **多维评分**：
   - 技术面 40% (RSI/MACD/BB)
   - 动量 30% (3日涨幅/趋势强度)
   - 成交量 20% (量比)
   - 新闻情绪 10%
3. **层级加成**：Tier1 +5分，Tier2 +2分
4. **生成计划**：前3名为作战，接下来3名为兜底
5. **推送通知**：钉钉发送今日作战计划

### 盘中 (09:30-16:00)
1. **门禁检查**：
   - 是否在作战池中？→ 允许交易
   - 是否在兜底池中？→ 作战池信号不足时允许
   - 是否在计划外？→ **拒绝交易**
2. **仓位检查**：
   - 总暴露 < 75%？
   - 当前持仓 < 5只？
   - 单只仓位 < 8%？
3. **信号执行**：符合所有条件才执行

### 盘后 (16:30)
1. **复盘分析**：今日作战股票表现
2. **评分更新**：根据实际表现调整权重
3. **次日准备**：预生成明日候选池

## 代码实现

### 新模块
`app/strategy/daily_combat_pool.py`
- `ScoringEngine`: 多维评分引擎
- `DailyCombatPool`: 每日作战池管理器
- `generate_daily_plan()`: 盘前生成计划
- `is_in_combat_pool(code)`: 盘中检查门禁

### 配置更新
`config/unified_config.yaml`
```yaml
strategy:
  decision_buffer:
    daily_combat_pool:
      enabled: true
      max_combat_stocks: 3
      max_backup_stocks: 3
      min_score_to_enter: 60
      generation_time: '08:30'
      require_in_pool: false  # 先设为false，验证后改为true
```

### 集成点
1. **main.py**: 08:30 调用 `generate_daily_plan()`
2. **decision_buffer.py**: 在 `_check_position_status` 前增加作战池检查
3. **risk_pipeline.py**: 在 Pipeline 中增加 `CombatPoolCheck`

## 风险控制

### 硬性门禁
1. 不在作战/兜底池 → 拒绝
2. 总暴露 ≥ 75% → 拒绝
3. 持仓数 ≥ 5 → 拒绝
4. 单只仓位 ≥ 8% → 拒绝

### 软性控制
1. 兜底股票仓位减半
2. Tier3 股票仓位最低
3. 连续亏损 3 次 → 当日停止交易
4. 回撤 > 12% → 触发熔断
