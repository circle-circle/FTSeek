> **状态**: 🟡 规划中（持续迭代）

> **本文档是「总纲」**：给出根因叙事、四阶段总览、优先级矩阵、阶段间门禁、状态跟踪表。

## 1. 背景：一次系统级诊断的结论

基于对 779 个 Python 文件、44 个子系统的全量审计（四个并行深度代理 + 代码逐行验证 + `docs/PM_RISK_AUDIT_2026-06-17.md` 团队自查），得出三条核心结论：

### 结论 A：当前信号已失效，且无自动止血机制
| 指标 | 健康线 | 当前实测（PM 审计 2026-06-17）| 判定 |
|------|--------|------------------------------|------|
| 整体 IC | >0.05 | **-0.0356**（n=884）| 信号反向 |
| LONG 胜率 | >52% | **25%** | 方向选反 |
| HIGH_VOL 胜率 | >40% | **14.89%**（亏 -$154K，占总亏 71%）| VIX>25 全盘崩溃 |
| 高置信度信号 | IC 应更高 | IC=0.1685 **但仍亏钱** | 拟合/泄露嫌疑 |

### 结论 B：**所有学习闭环全部断裂（根因）**
这是贯穿全系统的结构性病灶。反馈机制都写好了，但**没有一个接回它本该影响的决策**：

| 闭环 | 代码已实现？ | 实际是否生效？ | 证据 |
|------|------------|--------------|------|
| 多模型权重随胜率自适应 | ✅ `VotingPerformanceTracker.get_model_weights_adjustment()` | ❌ **零消费方** | `app/agents/voting/performance_tracker.py:108` 全局无调用 |
| 辩论产生分歧观点 | ✅ `DebateEngine` 在 voting_coordinator 创建 | ❌ **从未调用** | `app/agents/voting/voting_coordinator.py:355-363` 后无 `run_debate` |
| 复盘教训 → 次日作战计划 | ✅ `LessonInjector.generate_battle_plan_injection()` | ❌ **plan/pipeline 零调用** | 教训只入 DB 不进次日 prompt |
| 进化自动转正 | ✅ `ShadowTracker._execute_promotion()` | ❌ 注释写"模拟"，**只改 DB 不写 YAML** | `app/evolution/shadow_tracker.py:426-443` |
| IC 监控 | ✅ `get_ic_summary()` + 物理门禁 | ⚠️ **只拦单不调权**，无统计显著性 | `app/pipeline/order_executor.py:3517-3542` |

**一句话根因**：这个系统具备「学习型交易系统」的全部零件，但闭环全部断开。它每天在亏钱、每天复盘、每天算 IC、每天跑影子进化，但这些产出**没有一个真正改变下一个决策**——所以它不会自己变好。

### 结论 C：横向集成不足（纵向防御很强）
系统纵向防御纵深极强（5 级水位 / 三级熔断 / 9 步 Pipeline / 标的日亏护栏 / order tracker 超时撤单 / SSOT 配置治理三层防御），但**横向存在三套并行风控、540 行面条式启动、20+ 处"降级运行"吞噬故障**。典型「组件丰富、集成不足」。

## 2. 四阶段总览

设计哲学：**止血 → 通电 → 架构收敛 → Alpha 提升**。前一阶段是后一阶段的**硬前提**（门禁见 §4）。

| 阶段 | 一句话目标 | 项数 | 预计周期 | 详写深度 |
|------|-----------|------|---------|---------|
| **Phase 1 止血** | 让系统不再出血、让模拟盘说真话 | 5 | 本周（3-5 天） | ✅ RFC 级（见 phase1 doc） |
| **Phase 2 通电** | 把 4 个断裂的闭环接回去，让系统能"自己变好" | 5 | 2 周 | 📋 提纲（见 phase2 doc） |
| **Phase 3 架构收敛** | 消除三套并行风控、面条启动、配置四源 | 5 | 2-3 周 | 📋 提纲（见 phase3 doc） |
| **Phase 4 Alpha 提升** | 因子学习 / 截面排名 / 自适应止损 / 微观结构 | 5 | 3-4 周（IC>0 后） | 📋 提纲（见 phase4 doc） |

## 4. 阶段间门禁（Gate Criteria）

不可跳级。每进入下一阶段前必须满足对应的 gate，**全部以数据为准、不靠感觉**。

### Gate 1 → 2（止血完成）
- [ ] P1.1~P1.5 全部 `✅` 且部署 ≥3 个交易日
- [ ] **模拟盘 IC 与实盘 IC 差值 <0.05**（证明模拟盘不再撒谎）
- [ ] HIGH_VOL（VIX>25）自动交易数下降（P1.3 生效证据）
- [ ] 连续 3 日无「幽灵仓 / kill switch 静默绕过 / 过期计划无降级」事件

### Gate 2 → 3（通电完成）
- [ ] P2.1~P2.5 全部 `✅`
- [ ] **投票权重在过去 7 天至少发生过 1 次自适应变化**（证明闭环通电）
- [ ] 至少 1 个策略被 IC 监控自动禁用或 1 条教训进入次日计划（证明反馈真的回流）

### Gate 3 → 4（架构收敛完成）
- [ ] P3.1~P3.5 全部 `✅`
- [ ] 风控只剩 1 条主路径，废弃路径代码已删除（非注释）
- [ ] `main.py` 启动阶段失败可见（critical 阶段退出而非静默降级）

### Gate 4（重新打开油门）
进入 Phase 4 前，系统应已满足 PM 审计「Pre-Relaunch Checklist」：
- [ ] 整体 IC 连续 7 天 ≥0.05
- [ ] LONG 胜率 ≥45%，SHORT ≥50%
- [ ] HIGH_VOL 胜率 ≥25%
- [ ] 无 circuit breaker 触发满 7 天
- [ ] **人工 review final sign-off**

## 5. 关于「暂停实盘」的精确建议

团队 PM 审计（2026-06-17）建议**立即暂停实盘**。从代码层面**支持**，但给出更精确的条件，避免一刀切：

**在以下两个前提未达成前，保持 conservative 模式**（日限 3 笔 / 仓位 -50% / 信号门槛 70，config 已配）：
1. **P1.1 模拟盘滑点修复**——否则你在用假数据评估策略
2. **P2.1 或 P2.3 至少一个闭环通电**——否则系统永远不会自己改善

**特别警示**：PM 审计原话"在 IC 为负时优化速度等于在崖边加油门"是准确的。Task 1（信号 5s 轮询加速）应**冻结到 P2.3 完成之后**——加速轮询会放大负 IC 的出血。

## 6. 与现有 RFC 的关系

| 现有 RFC | 关系 | 本程序如何处理 |
|---------|------|--------------|
| RFC-055 止损止盈数据驱动 | 已实施（Phase1-3，commit 454c9801/e275bad9）| 已识别的 edge（SHORT+Trailing Stop 63.9% WR）是**方向性优势**，本程序 P4.3 在其基础上做自适应止损 |
| RFC-056 HIGH_VOL regime filter | 已决策 | **P1.3 直接落地并扩展**（25-28 区间当前无强制，需补） |
| RFC-057 min_hold_minutes | 已决策 | 与 P1.1 模拟盘修复不冲突，继续生效 |
| RFC-058 LONG direction bias | 已决策 | P2.1 通电后由真实胜率驱动，而非硬编码 bias |
| RFC-059 sandbox mode | 已决策 | 为本程序提供安全的影子测试环境（P2.5 复用） |
