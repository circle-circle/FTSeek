## 📋 项目现状分析

```
FTSeek V4
├── 策略层 (V3/V3.5)

│   ├── 融合策略：FusionV2, ConfluenceV2
│   └── 市场状态：MarketRegimeDetector

│   ├── 日内交易：IntradayStrategy
│   └── 定时调度：TradingScheduler
├── 执行层
│   ├── 模拟交易：PaperTrading
│   ├── 订单执行：TradeExecutor
│   └── 持仓管理：PositionManager
├── 风控层
│   ├── RiskManager (五层检查)
│   └── RateLimiter (频率限制)
└── 报告层
    ├── 日报/周报生成
    └── 钉钉推送
```

## 🤔 澄清问题

### 问题 1: 升级范围优先级

您希望优先实施哪个方向？

**A. 因子库扩展** (1-2 周)
- 新增资金流因子 (北向/机构)
- 新增情绪因子 (新闻/社交)
- 新增 ESG 因子
- 预期：+15-25% 信号质量

**B. ML 模型集成** (2-3 周)
- XGBoost/LightGBM集成预测
- LSTM时序预测
- 预期：+20-30% 预测准确率

**C. 组合优化** (2 周)
- 风险平价配置
- Black-Litterman 模型
- 预期：-30% 组合波动率

**D. 全面升级** (6-8 周)
- 按顺序实施所有 5 个 Phase
- 系统性升级

**我的建议**: 选择 **A → B → C** 渐进式升级，每阶段独立验证，降低风险。

### 问题 2: 生产环境保护策略

升级期间如何保证现有功能不受影响？

**A. 特性开关 (Feature Flags)**
- 新功能默认关闭
- 通过环境变量控制启用
- 可随时回滚

**B. 并行运行**
- 新策略独立模块 (`app/factors/`, `app/ml/`)
- 不影响现有 `app/strategy/`
- 通过配置切换

**C. 分支开发**
- 创建 `feature/upgrade-2026` 分支
- 完整测试后合并

**我的建议**: **A + B 组合** - 特性开关 + 并行模块，最安全。

---

### 问题 3: 测试策略

如何确保升级质量？

**A. TDD (测试驱动开发)**
- 每个功能先写测试
- 测试覆盖率先 80%+
- 符合 Superpowers 规范

**B. 回归测试**
- 保留所有现有测试
- 新增集成测试
- 性能基准测试

**C. 灰度发布**
- 先在模拟盘运行 2 周
- 对比新旧策略表现
- 验证后实盘

**我的建议**: **A + B + C 全部** - 完整质量保障。

---

### 问题 4: 数据源依赖

新因子需要额外数据源，如何处理？

**A. 使用现有数据**
- 优先使用已缓存的 K 线数据
- 计算衍生指标

**B. 新增 API 集成**
- AKShare (A 股/港股数据)
- 新闻 API (情绪分析)
- 需要 API Key 配置

**C. 混合方案**
- 核心因子用现有数据
- 高级因子可选配置

**我的建议**: **C 混合方案** - 降低依赖门槛。
