## 三、FTSeek-US 应有逻辑

### 3.1 核心设计原则

**美股特点**:
1. **T+1 制度**: 当日买入，次日才能卖出 → 不适合日内 T+0
2. **无涨跌幅限制**: 单日可能波动 20%+ → 需要更宽止损
3. **财报波动大**: 财报日可能±30% → 需要避开或减仓
4. **盘前盘后交易**: 延长交易时段 → 需要特殊处理
5. **做空容易**: 融券方便 → 可以做多/做空双向

### 3.2 监控器逻辑 (当前实现)

```
┌─────────────────────────────────────┐
│   定期查询股价 (5-15 分钟)           │
│   - 富途 API (优先)                  │
│   - 备用数据源 (Fallback)            │
└──────────────┬──────────────────────┘
               ↓
┌─────────────────────────────────────┐
│   检查持仓的止损止盈条件            │
│   - 固定止损：-8% ~ -15%            │
│   - 固定止盈：+15% ~ +30%           │
│   - 追踪止盈：盈利后回撤触发        │
└──────────────┬──────────────────────┘
               ↓
┌─────────────────────────────────────┐
│   触发条件 → 自动平仓               │
│   - 调用富途 API 卖出                │
│   - 发送钉钉通知                    │
│   - 记录交易日志                    │
└─────────────────────────────────────┘
```

**适用场景**:
- ✅ 中长线持仓监控
- ✅ 自动止损止盈
- ✅ 跨时段监控 (夜间)
- ❌ 不适合日内高频交易

### 3.3 与 FTSeek 策略对比

| 策略维度 | FTSeek (港股) | FTSeek-US (美股) |
|---------|--------------|-----------------|
| **入场信号** | RSI 超卖/MA 交叉/突破 | 基本面/趋势突破/财报后 |
| **出场信号** | 日内反转/止盈 | 止损止盈/趋势破坏 |
| **持仓时间** | 分钟 ~ 小时 | 天 ~ 周 ~ 月 |
| **仓位管理** | 单笔 5-10% | 单笔 15-25% |
| **止损方式** | 固定 -3% | 固定 -10% 或 ATR×2 |
| **止盈方式** | 固定 +5% | 分批止盈 (+15%/+25%/+40%) |
| **交易频率** | 日均 20+ 笔 | 月均 5-10 笔 |

## 五、FTSeek-US 正确定位

### 5.1 核心功能

**FTSeek-US 应该是**:
1. ✅ **中长线持仓监控器**
   - 监控已有持仓的止损止盈
   - 自动执行平仓
   - 跨时段监控 (美东夜间)

2. ✅ **美股数据源**
   - 提供美股实时价格
   - 备用数据源 Fallback
   - 支持 16 只股票监控

3. ✅ **交易执行器**
   - 接收信号 → 执行交易
   - 富途 API 集成
   - 自动下单

**FTSeek-US 不应该是**:
- ❌ 日内高频交易系统 (不适合美股)
- ❌ 复杂多 Agent 决策 (过度设计)
- ❌ FTSeek 的简单复制 (市场不同)

### 5.2 简化架构

**建议架构**:
```
┌─────────────────────────────────────┐
│   持仓监控器 (核心)                 │
│   - 定期查询股价                    │
│   - 检查止损止盈                    │
│   - 自动平仓                        │
└─────────────────────────────────────┘
         ↑              ↓
┌────────┴────┐  ┌─────┴────────┐
│  富途 API   │  │  备用数据源  │
│  (交易)     │  │  (行情)      │
```

**移除部分**:
- ❌ 多 Agent 投票系统 (过度复杂)
